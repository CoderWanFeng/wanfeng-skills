# 日常碎片 Vlog：素材先行，AI 负责成片形式

本技能接受用户随手拍的视频、照片和一个目录。**口播视频、文稿、SRT、数字人都不是前提。** 用户负责记录，Agent 负责看懂素材、找到主线、选择表达形式、写旁白、设计动画、剪成视频。
需要「对镜头讲话的口播包装」「每句话弹卡」「数字人混剪」「固定底图封面」时，走姊妹技能 **晚枫自动剪视频-Pro（`mograph-pro`）**，本技能不复制它那套版式与问答关卡。

## 1. 输入与范围

- 听到「日常 vlog」「随手拍」「零碎视频」「把这个目录剪成一条」时，先检查素材，走本流程。给了文稿也可以使用，但不能倒过来要求用户补稿。
- 有用户已确认的事件、身份、目的，直接复用。只有缺失信息会实质改变内容时才问，例如「这是哪次培训」。不再询问是否有口播、是否有数字人、是否会写稿。
- 用户说「先看稿」，只出稿；说「先出5秒」，只渲5秒样片，带该段应有的动画与声音；说「直接剪」则继续到可播放成片。阶段依据用户要求，不套口播技能的问答关卡。
- 素材读取和剪辑均在授权目录内；原片只读，截取、重排、转场在副本和时间轴中完成，不修改或删除原文件。

## 2. 看素材，不看文件名编故事

先运行可复用本地工具，输出到选题目录内独立的过程目录：

```bash
python3 <SKILL_DIR>/scripts/vlog_scan.py \
  --assets <素材目录> --out <选题目录>/剪辑过程/vlog/检视
```

默认只读素材目录的直接子文件；用户指定子文件夹时直接指向它，需要递归才加 `--recursive`。工具只探测时长、旋转、音轨、色彩信息并抽帧，不负责语义识别。

1. 用 Read 真正查看接触表和照片；场景变化多的片段补抽关键帧。
2. 记录每段「能看到什么、可用起止、质量问题、叙事作用、不能证明什么」。有音轨不等于有口播；音频承担信息时再用现有转写能力核验。
3. 拍摄时间是元数据，不等于行程证据。文件名排序不是叙事顺序。不得根据酒店、食物、人物表情杜撰地点、价格、对话或学员反馈。
4. 用户提供的资料、公开活动信息可解释身份和事件；没有课堂视频，不写成已经拍到授课全过程或学员交付成功。涉及儿童、未授权人物、证件和投屏账号时选安全镜头或另做脱敏副本，不靠原图标题判断隐私。
5. 输出 `inventory.json` 和镜头判断。先看素材才能写正文；不得仅把目录名当成已经理解素材。

## 3. 由 Agent 选择形式

根据现有画面选择一个最合适的方案，用一句话说明理由并继续。用户已经明确形式、画幅或风格，遵照执行。

| 素材特征 | 可以选择的形式 |
|---|---|
| 起床、走廊、交通、早餐、工作、休息 | 一天时间线 + 第一人称轻旁白 |
| 多个生活细节，时间顺序不重要 | 音乐卡点蒙太奇 + 短字幕 |
| 少量关键照片、活动画面、背景资料 | 照片视频混剪 + 活动故事 |
| 路程或场景转换明显 | 路线串联 + 地点章标题 |
| 原声有意义，人物没在对镜头讲话 | 环境声主导 + 少量解释文字 |

不强制第一人称旁白、特定长度、竖版或“搞笑”。多数源视频为竖拍时可默认竖版；横拍为主时可默认横版，说明选择即可。横竖混合素材独立构图，不拉伸人物。封面如需制作，可按本期素材与风格重新设计；不自动调用旧的固定人像模板，不自动加小绿书套图。

## 4. 写稿与配音

- 旁白由 Agent 根据镜头事实写，不让用户先提供素材稿子。口语、短句、有细节；事实、主观感受和比喻分清。不把 vlog 写成新闻通稿或模型原理课。
- **第一人称说人话**：说「我也得先吃好早饭，给自己充个电」，不说「先给讲师充个电」这类把自己摘出去的第三人称表达。
- **旁白与画面文字解耦**（最容易被退回旧打法的一条）：
  - 旁白讲当天自然的生活内容，**不要把屏幕上的花字、贴纸、标题一条条念出来**。
  - 画面上的字只要和讲的内容**语义相关**即可，不要求逐字相同；贴纸写「去吃个早饭」，旁白可以说「早上先吃点东西，精神足一点再出发」。
  - 同一句话不做两遍：已经做成花字/大字的文字，别再在底部烧一条一模一样的逐字字幕；底部字幕留给旁白本身，且与花字错开内容或错开位置。
- 旁白长度与可用镜头、必要照片停留、动画节奏一起估算；不能为了长稿反复循环短视频或把一张图硬撑十几秒。
- 用户要求先审稿时停在稿件。否则可以连同形式说明继续制作，涉及付费、上传和音色身份的授权仍单独遵守。
- 按任务中已明确的声音选择处理：已有音频直接复用；明确要本人既有克隆音色时，复用已配置的 MiniMax 语音方法，只生成旁白，不调用 H3，不重新克隆。密钥只在原配置处读取，不写入任务文件、提示词、日志或发布包。
- 没有语音授权或服务不可用时，先用现有环境声或音乐字幕版，不偷偷换公共音色，不为这个功能自动开付费服务。说明哪些声音未生成。
- **加速只做一次**：供应商原速合成 → 本地按用户倍数（常见 1.2×）`atempo` → `ffprobe` 实测加速后时长 → 用实测时长回填时间轴、旁白位置和画面字幕。发现放不下就改稿或改镜头长度，**不再二次加速**。
- 语音合成后以真实音频时长回填时间轴和字幕，不能把估算时间当成实测。配乐在人声下压低；必要时保留脚步、餐厅等环境声，加强生活感。

## 5. 丰富动画，但让生活画面当主角

**不继承口播版式。** 不强制冷深蓝品牌底、三行标题、步骤条、圆形人头、每句一张整屏卡、A/B数字人比例、固定封面、左右分栏，也不强制每个镜头3秒切一次。人物原本在画面里就自然出现，不裁出头像长期贴屏。

- 选一个视觉母题串起全片，例如手账、旅行票据、相机取景框或轻量时间轴。每条视频按内容选字体、配色、构图和工具，不把某一期参数写成通用默认值。
- 丰富的是有意义的过程：时钟数字滚动、日期与地点打出、路线描线、手绘箭头指物、贴纸轻弹、照片叠放滑入、画框逐段展开、关键字卡点、照片轻推近，以及匹配场景方向的转场。
- 一段可同时有真实视频、文字层、动画标记和声音，不把丰富动画等同于堆字卡。镜头本身有动作时留出观看空间；重要活动横幅、人物、食物和设备不要被字幕挡住。
- **花字自己会动，不用旁白解释**：贴纸、箭头、描线在画面上出现即可，不需要念出它的字；文字层放在竖版顶部或中上安全区，底部留给平台 UI 与必要字幕，避免两层文字叠在一起。
- 邻接镜头尽量匹配动作或方向；音乐强拍可快速切，情绪停顿可放慢。统一主转场，少量强调转场，不能每次随便换一个特效。
- 动效要真的有中间过程，不能用静态PNG淡入冒充滚动、描线或弹跳。记录每段效果服务什么内容，不编造图上没有的数字或地名。
- 优先选本机已经可用的工具。内置 `vlog_render.py` 是轻量基础渲染入口，支持逐帧动效和转场；它不是风格上限。更复杂的路线、拼贴、音频反应等可另写任务级渲染器或使用现有合适工具，先核验依赖与许可，不自动安装、不机械照搬旧口播引擎。

## 6. 渲染计划与可执行入口

镜头语义由 Agent 决定；扫描器不自动生成故事。渲染器消费 Agent 写好的 JSON，不要求口播/SRT，也不调用任何生成API。

```json
{
  "schema": "mograph-vlog.plan/v1",
  "source_root": "/absolute/path/to/source",
  "canvas": {
    "width": 1080, "height": 1920, "fps": 30,
    "background": "#202329",
    "font_path": "/absolute/path/to/available-font.ttf", "font_index": 0
  },
  "scenes": [
    {
      "id": "morning", "source": "/absolute/path/to/source/clip.mov",
      "source_in": 0.3, "duration": 2.0, "fit": "contain",
      "source_audio": true, "motion": "none",
      "transition_in": {"type": "cut", "duration": 0},
      "effects": [
        {"type": "typewriter", "text": "早上的出发", "start": 0,
         "duration": 1.8, "x": 0.1, "y": 0.2, "size_px": 56, "color": "#F6F1E8"},
        {"type": "progress", "start": 0, "duration": 2,
         "x": 0.1, "y": 0.75, "size_px": 36, "color": "#F6F1E8"}
      ]
    }
  ],
  "soundtrack": {"source_volume": 0.3, "music_volume": 0.15, "narration_volume": 1}
}
```

- 可用动效：`typewriter`、`stamp`、`arrow`、`progress`、`frame`；只选适合当前镜头的，未知效果报错，不静默忽略。
- 可用转场：`cut`、`fade`、`wipeleft`、`slideleft`、`smoothup`、`circleopen`。`transition_in` 作用于当前镜头入口，重叠时长从全片总时长扣除；第一镜头必须 cut。
- 自己写 ffmpeg 拼 xfade 时（本技能内置渲染器已按此处理）：**xfade 只接受恒定帧率**，每条分支链的末尾都要有 `fps=<帧率>` 且放在 `setpts` 之后，第一段 xfade 之后再来一次 `fps`；否则会报 `The inputs needs to be a constant frame rate; current rate of 1/0 is invalid`，那是滤镜链问题，不是源文件坏了。
- 图片用 `duration` 表示停留时间，`motion=push-in` 可轻推近。视频 `source_in + duration` 必须不超过实测可用长度，不默认循环延长、不截断语音。
- `soundtrack.narration` 与 `soundtrack.music` 如需使用，填写已在本机冻结的音频路径；配音与音乐由前一步准备，不在渲染时联网。
- 参数位置是画幅归一化坐标，文字由可用字体实际测量。不把客户姓名、本人音色标识或任何密钥放进通用模板。
- HDR/HLG素材必须明确做色彩管理；轻量入口拒绝未经处理的HDR，不静默当SDR渲染。转为SDR时另存副本并核验肤色与高光。
- 画幅按发布平台单独排一版：视频号 / 抖音竖版 9:16 1080×1920，B站横版 16:9 1920×1080，**不把已有版本拉伸凑比例**；用户说「只要竖版」时，过程目录里不再产出横版成片，避免拿错文件发布。竖拍手机素材要核对 `-90` 旋转元数据是否真的转正，抽帧确认成片无旋转标记。

```bash
python3 <SKILL_DIR>/scripts/vlog_render.py --plan <计划.json> --out <过程目录>/样片.mp4 --validate-only
python3 <SKILL_DIR>/scripts/vlog_render.py --plan <计划.json> --out <过程目录>/样片.mp4 --preview-seconds 5
# 只在用户要求完整成片时运行，不把整片渲染当成5秒预览的前置步骤
python3 <SKILL_DIR>/scripts/vlog_render.py --plan <计划.json> --out <过程目录>/母版.mp4
```

预览必须只处理覆盖该时间段的镜头，保留原计划的声音和动效；不能先渲全部再截5秒。不要把仅素材检视或未带实际声音的工程截图说成最终视频。

## 7. 验收与交付

1. 检查镜头来源、旋转、画幅、文字安全区、转场接缝；抽开头、中间、结尾与动效中间态，真读图。
2. 实测时长和音轨；核查旁白没被截断，音乐不盖人声、无爆音。镜头有运动不等于特效已实现，单独对比动画中间帧。
3. `--validate-only` 和单元测试只证明输入契约/基础能力；真人素材端到端成片仍需抽帧和播放验收，不虚报测试范围。**特别核一条**：旁白是否在逐条念画面上的字，同一句话是否在贴纸和底部字幕各出现一次。
4. 只生成用户要求的稿件、样片或成片。过程在 `<选题>/剪辑过程/vlog/`，需要发布的成片在 `<选题>/发布包/`；原片不入发布包。
5. 用户要讲制作方法时，按真实流程写：「我只把随手拍的几段视频和照片放进一个目录，没写稿也没录口播，让技能自己看素材、选形式、写旁白、安排字幕和动画。打开 WorkBuddy，进「专家·技能·连接器」的「技能」页，搜「晚枫自动」，认准「晚枫自动剪vlog」点加号添加，再把素材目录给它就能开始。」不要求观众先录口播或写稿，不说全部免费，不把尚未生成的稿件称为已完成视频。

## 8. 防退化用例

- 「这里只有日常碎片，帮我剪」→ 看素材、选形式、写稿并剪；不能问「有没有口播」。
- 「我是培训讲师，素材在目录里，先看稿」→ 按真实场景写第一人称旁白，停在稿件，不生成数字人。
- 「先出5秒，动画丰富」→ 真正5秒片段，真实素材主体 + 有中间过程的动效 + 已授权声音，不套纯动画Demo关卡。
- 「旁白别念屏幕上的字」→ 重写自然的第一人称旁白，画面贴纸保持语义相关即可，删掉与贴纸重复的逐字底部字幕。
- 「配音太慢，加速1.2倍」→ 原速合成后本地一次性 `atempo=1.2`，用实测时长回填镜头和字幕，不做第二次加速。
- 「只要竖版，发视频号」→ 只交 9:16 一版，抽帧确认没有旋转残留，不把横版压成竖版。
- 「这条按老风格给口播弹卡」→ 那是姊妹技能 `mograph-pro` 的口播路径，不在本技能里做，也不把口播版式带进 vlog。
