# 两条路径共用 · 删减规则（cut-rules.md）

> **授权前置**：通用路径与晚枫专用路径都不得默认删减。用户明确允许后才执行本规则；
> 允许删减后要交付完整保留口播稿并继续制作视频；用户拒绝则原片、原稿、顺序、停顿和时长全部不动。
> 「允许删减」不包含重排授权，重排必须另行明确同意。
>
> 这份文档回答三个问题：**我为什么剪**、**我怎么剪**、**以后怎么自动剪**。
>
> 所有数字和规则都来自 `内容更新/视频更新/2-AI工具/20-混元hy4-flash` 的实证
> （184.14s 原片 → 84.36s 底片 → 81.30s 发布版），不是拍脑袋的设计。
> 凡是「听起来合理但没验证过」的写法，都不写进来。

---

## 0. 一句话结论

> **删减不是「按阈值砍停顿」，而是「把平叙改成结构化叙事」。**
>
> 原片 184.14s 里有 **92.50s 是静音（占 50.2%）**——一口气录完的口播，
> 一半时间是废话停顿。剪掉气口只是省时间，剪掉**废录**和**半截句**才是重写内容。

### 1.2 删除量构成

从音频反推 27 个刀口，**总删除 99.80s**，理论值 184.137 − 84.358 = 99.78s，
误差 0.02s。按 50ms 帧 RMS 划分语音/静音后：

| 类别 | 时长 | 占比 |
|---|---|---|
| 静音（气口、废录间隙） | 88.65s | 88.8% |
| 真实语音内容 | 16.15s | 16.2%（有重叠，见下） |

**26 刀中有 20 刀完全落在实测静音区（语音量 = 0）**，另 6 刀落在语音段内
（删的是废录的语音本身，不是空白）。

### 1.3 阈值检验：删减不是阈值驱动的

假设「删减 = 删掉所有 ≥X 秒的停顿」，用实测静音表验证：

| X（秒） | 能命中的刀口占比 |
|---|---|
| 1.0 | 37% |
| 2.0 | 26% |
| 3.0 | 29% |

**最高才 41%，且没有单一阈值能复现人工剪点**。
实证：保留的最长静音是 **1.23s**（用来卡点），删除的最短静音是 **0.75s**。

结论：**判定依据必须来自语义（内容是什么），不能来自时长（有多少秒）。**
时长只用来在已经确定要删的地方**选刀口位置**。

## 2. 四类删除动机

工具 `scripts/cut_plan.py` 只认这四类，人工也是这四类。

### 2.1 重录废稿（保留最后一次）

口播者说错重来，同一句出现在两个时间点。

- 判定：文本相似度 ≥ 0.72，**或**短句是长句的前缀；两块间隔 ≥ 1.2s
- 保留：**最后一次**（后一遍通常更完整、语气更自然）
- 71 号实证：
  - 「看到最后我告诉大家怎么自动剪视频」连录 3 遍，保留第 3 遍（原片 46.91–52.48 是前两遍）
  - 「而且不仅这个技能是免费的…」录 3 遍，保留最后一遍（原片 143.46–153.21 是前两遍）

**前缀规则为什么必要**：「这是我发布。」→「这是我发布上来免费给大家使用的一个技能…」
两句整体相似度只有 **0.29**（长度差太多），整体相似度抓不到，但前缀关系一目了然。

### 2.2 半截句

话说一半停住，后面是大停顿。

- 判定：**结尾是虚词/代词/连词**（话没说完）且后面有 ≥0.8s 停顿
  - 虚词表：这 那 他 她 它 我 你 们 就 把 和 跟 与 或 但 而 且 为 因 所
    如 会 要 能 该 得 着 让 给 对 吧 呀 啊 嗯 哦 嘛 呢 么 及 等
  - 整词表：大家 咱们 我们 你们 他们 这个 那个 而且 然后 所以 但是 不过 就是说
- 或：极短（≤5 字）且后面是 ≥2s 长停顿
- 71 号实证：「它就会。」「大家。」「而且。」

**为什么不能只看「短 + 长停顿」**：「一点积分都不花」也是 7 字 + 4.8s 停顿，
但它是**完整的结论句**，删了会丢掉「0 积分」这个核心卖点。
所以必须叠加语义信号——**实词结尾 = 可能是完整句；虚词结尾 = 半截句**。

### 2.3 孤立口水词

整句只有一个语气词，且两侧都有停顿。

- 判定：归一化后整句 ∈ {而且, 大家, 然后, 就是, 这个, 那个, 对, 啊, 嗯, 哦, 哈, 呃, 喂, 对吧, 是吧, 那么, 所以说, 怎么说呢, 好吧}
- 71 号实证：孤立「大家。」

### 2.4 长停顿（收紧，不删）

两侧都有内容的空白。**不是删掉，是收紧**。

- 判定：间隔 > 2.0s
- 处理：收紧到 **0.7s**（前块留 0.35s + 后块留 0.35s）
- 71 号实证：`config.py` 的 CUTS 里 (22.30, 25.20, "5.4s 长停顿收紧")、
  (163.90, 170.90, "5.1s 停顿 + 孤立「大家。」")

**为什么是收紧不是删除**：句间停顿是「换气」。全砍会让语速失真、听起来像机关枪。

## 3. 刀口怎么落（安全规则）

> **刀口只能落在实测静音区间或整块上，绝不切半个字。**

### 3.1 静音表是唯一可信的时间源

```bash
ffmpeg -i raw.MOV -af silencedetect=noise=-32dB:d=0.55 -f null -
```

- 71 号原片：**45 段静音，合计 92.50s**
- 71 号底片：仅剩 **9 段**（气口被收紧到 0.7s 上下）

**不要用 ASR 的句子边界当刀口**。whisper 的 segment 边界经常落在词中间
（实测「看到最后我告诉大家，怎么?」这种切法），拿它切会切掉半个字。

### 3.2 块（block）的定义

**以实测静音边界切分**，一次连续表达 = 一块。相邻发声区间间隔 < 1.0s 的合并成一块。

工具在这上面拿到 30 块（71 号原片），人工标注的重录单位基本都能对上。

### 3.3 气口分配模型

保留块的气口从两侧静音里取：

```
静默段 S = [head + tail]
   ↑            ↑
前块用 head   后块用 tail
```

| 静默段长度 | 前块拿 | 后块拿 | 合计保留 |
|---|---|---|---|
| ≤ 2.0s | S/2 | S/2 | 全部（原样保留） |
| > 2.0s | 0.35s | 0.35s | 0.7s（收紧） |

**被删的块**：本体全删，两侧气口自动归给相邻保留块——不会留下「删掉一段话、
中间空一个洞」的接缝。

### 3.4 重排后的气口（气口跟着块走）

**每块的气口只从它自己紧贴的那段静音里取，不管那个原片邻居保不保留。**
重排时气口跟着块一起搬到新位置——**不按新邻居重算**。

为什么不是「按新邻居重算」：静音是原片里的**物理事实**，只存在于原片的那个位置。
把 A 块搬到第 1 位，它自带的那 0.35s 静音也跟着走；接缝处自然是
「A 的尾气口 + B 的头气口」两段静音拼起来，听感上是连续的换气。

早前一版按「order 的前后邻居 + 原片时间单调钳位」算气口，保序时碰巧对，
**重排后原片时间乱序，钳位把区间压成了 `[39.34, 39.34]`**。
更糟的是 ffmpeg 的 `-t 0` 表示「不限时长」，零长段会把剩下的整片都吃进来——
计划 88.28s 的成片实际渲染成了 **668.3s**。现在改成：
气口从紧邻静音取 → 区间不重叠 → `apply_plan` 再硬拦一道零长段。

**验证**：保序版与重排版的 keep 区间集合完全相同，总时长一致（114.32s），
只是排列顺序不同。

## 4. 走过的弯路（别再走）

### 4.1 贪心互相关匹配 —— 失败

想从音频反推原片→底片的剪点，第一版用「底片逐窗在原片局部搜索 + 单调推进」。
结果 base 30s 之后全部匹配到 orig ≈ 179s（相似度 0.00–0.23），完全跑飞。

**原因**：一旦某次误匹配就再也回不去，相似语音上不唯一。

**修复**：改成**全局 DP 对齐**（log-mel 倒谱 13 维 + CMN + 三状态 DP，
对「开一段删除」计惩罚使解出的剪点数量最少）。一次跑通，
总删除量与理论值误差 **0.02s**。

### 4.2 音频指纹复核重录 —— 失败

转写模型有「重复转写」幻觉：把上一句的文本贴到下一段上。
想用 log-mel 倒谱指纹做音频层面的复核，把真重录和幻觉区分开。

**实测结果：正负样本完全重叠。**

| 样本 | 倒谱余弦（滑动最佳匹配） | mel 相关 | 能量相关 |
|---|---|---|---|
| 真重录·连录3遍 | 0.355 | 0.358 | 0.628 |
| 真重录·短版→完整版 | 0.252 | 0.392 | 0.815 |
| 真重录·重复的「大家点进这个技能」 | 0.189 | 0.202 | 0.545 |
| 真重录·废录3遍 | 0.231 | 0.246 | 0.536 |
| 幻觉·点击/点进去之后 | 0.362 | 0.370 | 0.557 |
| 幻觉·ASR重复转写 | 0.184 | 0.262 | 0.577 |

重录时语调、语速、麦距都变了，短片段的声学指纹没有区分度。

**替代方案（已采用）**：用**语速合理性**判断文本可信度。
正常中文口播 4–6 字/秒；幻觉块的字数远超时长能承载的量：

| 块 | 时长 | 字数 | 语速 | 判定 |
|---|---|---|---|---|
| 89.91–90.27 | 0.36s | 14 | **39 字/秒** | 文本被污染，不作删除依据 |
| 91.78–92.48 | 0.70s | 14 | **20 字/秒** | 文本被污染 |
| 124.04–124.56 | 0.52s | 11 | **21 字/秒** | 文本被污染 |
| 46.91–52.48 | 5.57s | 33 | 5.9 字/秒 | 可信 |
| 102.98–103.92 | 0.94s | 5 | 5.3 字/秒 | 可信 |

阈值：**12 字/秒**。超过即该块文本不可信，不能作为删除依据。
（实测真删的最慢是 9.4 字/秒，误判的最快是 20 字/秒，分界干净。）

### 4.3 numpy 2.0 + Accelerate BLAS 的假阳性警告

macOS ARM 上 numpy 2.0.2 的 `matmul` 会误报
`invalid value encountered in matmul` / `divide by zero encountered in matmul`，
**随机矩阵也报**，结果本身无 NaN。用 `np.errstate(all="ignore")` 屏蔽。

## 5. 重排（调片段位置）

### 5.1 实证：71 号没有重排

把成片 47 条字幕线性映射回原片时间轴，**0 处时间回退** → 本片严格保序。
16 处跨刀是必然的（字幕按语义断句、刀口按静音断），不是重排。

### 5.2 什么时候值得重排

短视频最稳的重排只有一种：**把「成品展示」提到最前做钩子**——
先让人看到结果，再讲怎么做到的。

工具自动识别每块的叙事角色（成品展示 / 行动号召 / 利益承诺 / 操作方法 / 钩子悬念），
给出候选方案和理由，**但不自动执行**。

### 5.3 重排的代价

- 顺序变了，**字幕时间轴全部失效**，必须重做
- 场景表/动效卡片的落位要重新对
- 71 号最终选的是保序

**结论：先取得删减授权，再按需删减；重排必须另行取得明确授权，默认保序。**
用户不允许删减时，不得借「优化叙事」之名改动片段顺序。

### 5.4 命令

```bash
# 只有用户另行明确同意重排后，才使用工具建议的 --reorder 命令
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --reorder 5,1,2,3,4,6,8
```

`--reorder` 接受**保留块**的完整排列（1-based），被删的块不用写。

### 5.5 重排的端到端实测（用工具自己的 ASR 反读成片）

把「块 5（成品展示）提到最前」跑通后，对成片重新转写，验证开头真的换了：

| 版本 | 第 0 秒起的内容 | 说明 |
|---|---|---|
| 保序版 | 「所有打工人注意了…特别适合办公的混元4 flash…」 | 原片的钩子 |
| 重排版 | 「包括我这里面用到的一些动画…还有一些截图…都是他自己标注的。」 | 块 5 的成品展示，**成了钩子** |
| 重排版 8.60s | 回到「所有打工人注意了…」 | 原片开头被挪到成品展示之后 |

两个版本的 keep 区间集合**完全相同**（只是排列顺序不同），总时长一致（114.32s），
实际成片都是 115.33s（+1.01s 是 23 段拼接的帧边界取整误差）。

## 6. 工具

### 6.1 用法

```bash
# 出计划（JSON + Markdown 报告）
python3 scripts/cut_plan.py --video raw.MOV --out plan.json

# 直接剪出底片
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --apply base.mov

# 手工指定保留段（覆盖自动结果）
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --keep 0-5,20-40

# 调片段位置
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --reorder 5,1,2,3,4,6,8
```

依赖：`ffmpeg` / `ffprobe` 必需；`mlx_whisper` 可选（缺失时只做静音诊断）。

### 6.3 71 号回归结果

工具在 71 号原片上的输出与 `config.py` 里人工标注的 CUTS 对照：

| 工具刀口 | 原片区间 | 类别 | 人工标注 |
|---|---|---|---|
| 1 | 46.91–52.48 | 重录废稿 | 「看到最后我告诉大家怎么」连录 3 遍，保留第 3 遍 |
| 2 | 102.98–103.92 | 重录废稿/半截句 | 半截句「这是我发布。」 |
| 3 | 115.05–115.55 | 半截句 | 半截句「他就会。」 |
| 4 | 121.49–122.66 | 重录废稿 | 重复的「大家点进这个技能。去使用。」 |
| 5 | 143.46–143.83 | 半截句/孤立口水词 | 「而且。」废录 |
| 6 | 150.53–153.21 | 重录废稿 | 「…刚才给大家分享的」废录 |
| 7 | 168.23–168.76 | 半截句/孤立口水词 | 孤立「大家。」 |

**7 处语义刀口 100% 命中人工标注，零误删。**
另有 17 处长停顿被标记为「待收紧」。
人工标注里没被命中的 5 条**全是「停顿收紧」类**——工具只提示不删，
因为收紧是听感问题，不是对错问题。

计划保留 **114.32s / 184.14s（62.1%）**——比人工的 84.36s 保守，
因为工具不会自作主张删「看着像废话但语义完整」的内容。

**已知漏判 1 处**：块 23（144.98–148.21，「不仅这个技能免费刚,它还能用刚才咱们说的那个。」）
人工判它是废录，但工具与保留块的相似度只有 0.545 < 0.72 阈值，也不满足前缀规则
（一个以「不仅」开头，一个以「而且」开头）。选择保守——宁可漏删，不可误删。

**端到端实测**（71 号原片 → 成片）：

| 版本 | 计划时长 | 实际成片 | 规格 | 响度 | 静音段 |
|---|---|---|---|---|---|
| 保序 | 114.32s | 115.33s | 1080×1920 @ 30000/1001 / aac 44.1kHz 2ch | -22.9 LUFS | 35 段 |
| 重排（成品展示提到最前） | 114.32s | 115.33s | 同上 | -22.9 LUFS | 35 段 |

两个版本的 keep 区间集合完全相同，只有排列顺序不同；实际成片时长一致（+1.01s 是
23 段拼接的帧边界取整误差，1 帧 ≈ 0.033s × 23 ≈ 0.77s）。

**回归脚本**：`python3 scripts/verify_cuts.py <plan.json>`，逐条把工具刀口与
`config.py` 的人工 CUTS 对照。

### 6.4 工具的定位

**刀口是候选，不是命令；用户授权是执行前提。**

- 未经用户明确允许，不生成删减计划或底片；用户拒绝时原媒体和原稿不动
- 允许后先读报告第四节（口播块全文），确认每刀删掉的内容你认可，再 `--apply`
- 刀口只落在实测静音或整块上，不会切到半个字
- 长停顿不一定该删：全砍会让语速失真
- 重录默认保留**最后一次**；想用第一遍（通常更自然）就改 `keep`
- 底片之外还要交付完整保留口播稿，并继续用户要的视频制作

## 7. 给 agent 的执行建议

1. **先授权，再决定是否删减。** 用户允许则先删减再动效，并交付完整保留口播稿后继续成片；
   用户拒绝则原样进入包装。底片没定就排卡片，时间轴全要重来。
2. **删减阶段只看静音表和转写，不要碰画面。** 画面问题是动效阶段的事。
3. **删完必须复核文稿与成片**：完整口播稿应对应最终保留内容；`ffprobe` 看实际时长 vs 计划时长，误差应在 ±1s 内。
4. **重排要克制。** 没有用户明确授权不动顺序；71 号实测是保序。
5. **气口别删光。** 成片里保留 0.35–0.7s 的换气，听感才对。
