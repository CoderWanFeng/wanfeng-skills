# mograph · 删减功能说明（cut-feature.md）

> **一句话**：把一口气录完的原始口播，变成一条剪好的干净底片。
>
> **状态**：已实跑验证（71 号原片，184.14s → 114.32s / 7 处刀口 100% 命中人工标注）。
> **可以单独跑**：不依赖动效包装、不依赖字幕、不依赖 Pillow，只用 ffmpeg + 可选的 ASR。

这份文档是**功能视角**的说明书：怎么单独跑、输出什么、跑完核对什么。
规则的**详细推导**在 `cut-rules.md`；**实证数据**在 `cut-rules.md` §1.4 / §1.5，
71 号的完整研究报告在项目目录 `内容更新/short/71-混元hy4-flash/05-真人口播/删减规律研究.md`。

---

## 1. 这个功能做什么、不做什么

| | 做 | 不做（是别的步骤的事） |
|---|---|---|
| 语义删减 | 删重录废稿、删半截句、删孤立口水词 | — |
| 气口处理 | 长停顿收紧到 0.7s，短停顿原样保留 | — |
| 片段重排 | 可选：把「成品展示」提到最前做钩子 | 字幕时间轴重建、场景表重对 |
| 产出 | 一条干净底片（视频+音频同步切）+ 完整保留口播稿 | 提速、字幕、动效卡片、响度归一 |

**边界**：它只做用户授权的「减法」，以及用户另行明确同意的「换顺序」。底片出来之后还是原速、
无字幕、无动效——后面那几步在 `wanfeng-path.md` 的 §7（提速）和 §8（渲染/响度）。

### 1.1 两条路径共用的授权门

**通用路径和晚枫专用路径都一样：原始口播必须先问，用户明确允许后才能删减。**
已经剪好的底片不再询问，直接进入后续包装。

向用户解释清楚：

> 我可以删除重录废稿、半截句和孤立口水词，并把过长停顿收紧到约 0.7 秒；默认保持内容顺序，不做重排。删减后我会给你一份完整保留口播稿，然后直接继续制作视频。是否允许？如果不允许，我会保持原片、原稿、内容顺序、停顿和时长不变，只做后续已授权的视频包装。

| 用户选择 | 必须执行的行为 |
|---|---|
| **允许删减** | 生成计划并复核刀口 → 出 `base.mov` → 整理并交付 `clean-script.md` 完整保留口播稿 → **直接继续制作所选路径的视频，不等二次确认** |
| **不允许删减** | 跳过整个删减步骤，不生成删减方案或底片；原视频、音频、原稿、顺序、停顿和时长全部不动，只做后续已授权的包装 |

「允许删减」不等于允许重排。使用 `--reorder` 前必须另行取得明确同意，否则一律保序。

## 2. 单独怎么跑

**以下命令只能在用户已明确允许删减后运行。** 单独运行工具不等于可以绕过授权；
用户拒绝时不生成计划、不出底片，原媒体和原稿保持不动。

```bash
cd code/wanfeng-skills/skills/mograph/scripts

# ① 出计划（JSON + 人可复核的 Markdown 报告）
python3 cut_plan.py --video /path/to/raw.MOV --out plan.json --report plan.md

# ② 读 plan.md 第四节「口播块全文」，逐条确认刀口认不认可

# ③ 认可就出底片
python3 cut_plan.py --video /path/to/raw.MOV --out plan.json --apply base.mov

# ④（可选）只有用户另行明确同意调顺序时才执行；接受「保留块」的完整排列，1-based
python3 cut_plan.py --video /path/to/raw.MOV --out plan.json --reorder 5,1,2,3,4,6,8
```

**依赖**

| 依赖 | 必需性 | 缺了会怎样 |
|---|---|---|
| `ffmpeg` / `ffprobe` | 必需 | 直接退出 |
| `mlx_whisper` | 可选 | 降级：只做静音诊断（能切块、能收紧气口，但**不做语义判删**） |
| 模型 `mlx-community/whisper-base-mlx` | 可选 | 首次运行自动下载 |

**常用可调参数**（全部有默认值，不用管）

```bash
--noise-db -32        # silencedetect 噪声门限
--silence-min 0.55    # 最短气口
--long-pause 2.0      # 超过此值的停顿算长停顿
--repeat-sim 0.72     # 重录相似度阈值
--repeat-gap 1.2      # 重录最小间隔
--fragment-len 8      # 半截句最大字数
--rate-max 12.0       # 语速上限，超过即判定转写文本被污染
--block-gap 1.0       # 相邻发声区间间隔小于此值算同一块
--no-asr              # 跳过转写，只做静音诊断
--keep 0-5,20-40      # 手工指定保留段（覆盖自动结果）
```

## 3. 输出物

用户允许删减后，交付四类产物：

| 产物 | 内容 | 生成方式 |
|---|---|---|
| `plan.json` | 机器可读计划：`blocks` / `drops` / `keep` / `gaps` / `stats` / `reorder_suggestion` | `cut_plan.py` |
| `plan.md` | 人可复核报告：刀口清单 + 理由 + 保留区间 + 30 块全文 + 重排建议 | `cut_plan.py` |
| `base.mov` | `--apply` 出的干净底片 | `cut_plan.py --apply` |
| `clean-script.md` | **最终保留下来的完整连续口播稿**，可直接用于后续字幕、场景表和动效 | agent 按最终保留块整理，并对照计划与底片复核 |

`clean-script.md` 不是只列 keep 区间、删除原因、口播块表格或差异文本；必须让用户看到删减后
完整要说什么。当前 `cut_plan.py` 不会自动生成这份文稿。完整视频制作流程中，把文稿交给用户后
直接继续后续制作，不等待二次确认。

**plan.json 关键字段**

```jsonc
{
  "blocks": [ { "start": 46.91, "end": 52.48, "text": "...", "role": "钩子悬念" } ],
  "drops":  [ { "block": 6, "from": 46.91, "to": 52.48,
                "kind": "重录废稿", "text": "...", "why": "「...」重复录制（相似度 74%），保留最后一次" } ],
  "keep":   [ [0.33, 7.21], [7.21, 15.24] ],     // 顺序即成片顺序
  "stats":  { "kept": 114.32, "kept_pct": 62.1, "cuts": 7, "long_pauses": 17 }
}
```

**`role` 是叙事角色标签**（成品展示 / 行动号召 / 利益承诺 / 操作方法 / 钩子悬念 / 叙述），
重排建议靠它识别「哪块适合当钩子」。

## 4. 判定规则速查

| 类别 | 判据 | 处理 |
|---|---|---|
| **重录废稿** | 相似度 ≥ 0.72 **或**短句是长句前缀；两块间隔 ≥ 1.2s | 删前一遍，**留最后一次** |
| **半截句** | 结尾是虚词/代词/连词且后接 ≥0.8s 停顿；或 ≤5 字 + ≥2s 停顿 | 删 |
| **孤立口水词** | 整句只有一个语气词，两侧都有停顿 | 删 |
| **长停顿** | 间隔 > 2.0s | **不删**，收紧到 0.7s |

**三条硬约束**

1. **刀口只落在实测静音区间或整块上**——whisper 的句子边界会切在词中间，不能当刀口。
2. **气口跟着块走**——每块的气口只从它自己紧贴的那段静音里取，重排时跟着块一起搬。
3. **文本可信度闸门**——字速 > 12 字/秒的块，其转写文本被污染，**不作删除依据**。

详细规则、虚词表、阈值表、走过的弯路 → `cut-rules.md`。

## 5. 单独测试的检查清单

跑完照着核对这 9 条：

- [ ] **1. 刀口数合理**：原片越长废录越多，一般 5–15 刀。0 刀说明 ASR 没跑起来（看 `--no-asr` 分支）。
- [ ] **2. 零误删**：读 `plan.md` 第四节，确认没有整句实质内容被标成「删」。
- [ ] **3. 关键卖点还在**：像「0 积分」「免费」「不用花钱」这类结论句必须还在。
- [ ] **4. 计划时长合理**：保留率一般 55%–70%。>80% 说明判据太松；<45% 说明阈值太激进。
- [ ] **5. 零长段**：`plan.json` 里 `keep` 不能有 `b - a < 0.05` 的段。
- [ ] **6. 实际成片 ≈ 计划时长**：误差 ≤ 1s。超了就是帧边界取整（23 段约 +0.77s），正常。
- [ ] **7. 静音段数下降**：原片 45 段 → 底片应显著少于原片（但不是 0，句间换气要留）。
- [ ] **8. 响度对齐**：底片 -22~-23 LUFS（母版级）。发布级 -14 LUFS 是后面 `wanfeng-path.md` §8.4 的事。
- [ ] **9. 完整口播稿可交付**：`clean-script.md` 是从头到尾的完整保留内容，与底片一致，不只是刀口或差异清单。

一键核对第 5 条：

```bash
python3 -c "
import json;p=json.load(open('plan.json'))
z=[i for i,(a,b) in enumerate(p['keep']) if b-a<0.05]
print('零长段',len(z),z,'| 保留 %.2fs / %d 段'%(p['stats']['kept'],len(p['keep'])))"
```

## 6. 已知边界与失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 成片时长是计划的好几倍 | 区间里有零长段，ffmpeg 的 `-t 0` 表示**不限时长** | 已在 `apply_plan` 里硬拦；改阈值后重跑 |
| 重排后区间全塌成 `[x, x]` | 气口分配用了原片时间的单调钳位 | 已改为「气口跟着块走」，重排与保序的区间集合应完全相同 |
| 关键短句被误删（「点击。」「点进去之后。」） | ASR 重复转写幻觉，字速爆表 | 语速闸门拦下；阈值 12 字/秒 |
| 完整结论句被误删（「一点积分都不花」） | 只按「短 + 长停顿」判半截句 | 必须叠加实词/虚词结尾判据 |
| 废录没删掉（漏判） | 与保留块相似度 < 0.72 且非前缀 | **有意保守**：宁可漏删，不可误删 |
| 切块只有 1 块 / 0 刀 | 静音参数太严 | 放宽 `--noise-db` 或 `--silence-min` |


| 指标 | 基线 |
