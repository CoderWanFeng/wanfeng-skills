# 晚枫自动剪视频 · mograph

> **一句话**：一条口播视频 + 一份口播稿 → 在人的四周（或前景）按讲话内容定时弹出字幕卡片 → 做成成片。
> **v1 的核心取巧**：**skill 里不塞现成的卡片效果**。社区每个月都在长新的 Remotion / HyperFrames 卡片，硬编码进 skill 就是给自己造过期库存。所以 skill 只沉淀三件不会过期的东西——**卡片该放在哪、每个动作从第几秒开始、去哪儿找最新实现**——把「找最新实现」这一步交给用户本地的 AI 在运行时联网完成。

## 〇、三句话看懂架构

```
口播稿 ──┐
         ├─① make_spec.py ─→ overlay-spec.json（时间轴 + 位置 + 动画意图，引擎无关）
视频/音频┘                         │
                                   ├─② research-protocol.md ─→ 联网找可跑的实现 ─→ research-notes.md
                                   │
                                   └─③ engine-remotion.md / engine-hyperframes.md ─→ 渲染 ─→ final.mp4
```

| 层 | 谁负责 | 产物 |
|---|---|---|
| **骨架层** | 本地脚本 `scripts/make_spec.py`（纯标准库，秒出） | `overlay-spec.json` |
| **肌肉层** | 用户本地 AI 联网检索（Step 2 协议） | `research-notes.md` + 可复制代码片段 |
| **落地层** | Remotion（React）或 HyperFrames（HTML+GSAP）或 ffmpeg 兜底 | `final.mp4` |

**为什么分三层**：骨架层必须离线可跑（没网也能出分镜），肌肉层必须在线（保证不落后社区），落地层必须多选一（用户机器上有什么就用什么）。

## 一、何时使用 / 不使用

**用它的时机**（用户这么说就触发）：

- 「这条口播视频帮我加点动效」「根据我讲的内容在边上弹一些卡片」
- 「口播稿 + 配音已经有了，做成带数据图的成片」
- 「用 Remotion / HyperFrames 给口播视频做叠加」
- 「自动剪辑：说到数字就出数字、说到对比就分屏」

**不要用它**（明确转介）：

| 需求 | 应该用 |
|---|---|
| 只要字幕，不要动效 | `embedded-captions` |
| 从零做一条无人出镜的科普片 | `knowledge-short-video` |
| 只要一个动效短片头/角标 | `motion-graphics` |
| 重新配音、复杂多轨 NLE 剪辑 | v1 不做；原始口播的语义删减按 Step 0.2 取得授权后单独执行 |

## 二、前置条件

1. **一份口播稿**（`.md` / `.txt`，每句一行或带编号最佳）。
2. **一条口播视频或音频**（`.mp4` / `.mov` / `.wav` / `.mp3`）。
3. 可选但强烈建议：**真实时间戳**，任一形式即可 —— `.srt` 字幕、`[{text,start,end}]` 的 JSON、或 `segments.txt`。
   - **没有时间戳也能跑**，但脚本会按「中文 4 字/秒」估算时长，并在输出里打 `"timing_source": "estimated"`。
   - **硬规则：估算时间绝不能当成实测时间交付**。渲染前必须让用户试听校验（见第七节硬规则 R1）。
4. 落地环境三选一，都没有就走 ffmpeg 兜底：
   - Node 18+ → Remotion / HyperFrames
   - ffmpeg → PNG 序列 + `overlay` 滤镜（最朴素但一定能出片）

## 三、7 步流程（agent 按此执行）

![晚枫自动剪视频 · 通用路径执行流](assets/execution-flow.png)

> 一图看懂：输入是「口播稿 + 口播视频」，出口是「成片 + 分镜契约 + 检索记录 + 配图登记」。
> 十步分三段（分镜与素材 / 上肌肉 / 渲染与交付），每一步的产出与验收标准见下面逐段展开。

### Step 0 · 一次性确认 7 个开关（只问一轮）

| 开关 | 选项 | 默认推荐 |
|---|---|---|
| **风格路径** ⭐ | **通用**（检索驱动，任何口播都能用）/ **晚枫专用**（晚枫工作室自有打法，见 `references/wanfeng-path.md`，隐藏彩蛋） | ⭐ **通用**。仅当用户明确是晚枫 / 做晚枫工作室账号的内容时才选晚枫专用；**不确定 → 通用** |
| **素材形态** | 已是剪好的底片 / 一口气录完的原始口播 | 已剪底片直接包装；原始口播必须确认下一项 |
| **原始口播是否允许删减** | 允许 / 不允许 | **不默认删减，必须让用户明确选择**；两条路径都按 Step 0.2 执行 |
| **画幅** | 竖屏 9:16 / 横屏 16:9 | 按源视频自动探测 |
| **动效密度** | 克制（每 8s 一张，同屏 1 张）/ 标准（每 5s 一张，同屏 1 张）/ 高密度（每 2.5s 一张，同屏 2 张） | ⭐ 标准 |
| **渲染引擎** | Remotion / HyperFrames / 自动选 | ⭐ 自动（装了哪个用哪个）；**晚枫专用路径固定用 Pillow 自绘**，此项作废 |
| **要不要前景遮挡**（卡片压在人身前） | 要 / 不要 | ⭐ 不要（需人像抠图，v1 不承诺，见 R3） |

在同一轮把选项和删减的影响解释清楚，不要逐条追问。素材已经是剪好的底片时，不再询问是否删减；
原始口播先完成 Step 0.2 的授权分支，再进入 Step 0.5 的路径分叉。

> **风格路径这一项要先问**。它决定了后面走哪条流程，问晚了要推倒重来。

### Step 0.2 · ⭐ 语义删减授权（两条路径共用）

一口气录完的原始口播往往有大量重录和停顿（71 号实测静音 92.50s / 184.14s = 50.2%），
但是否删除内容只能由用户决定。**通用路径和晚枫专用路径都必须先取得明确授权，不得默认开剪。**

向用户完整说明并询问：

> 我可以先删除重录废稿、半截句和孤立口水词，并把过长停顿收紧到约 0.7 秒；默认保持内容顺序，不做重排。删减后我会给你一份**完整保留口播稿**，然后直接继续制作视频。是否允许我删减？如果不允许，我会保持原片、原稿、内容顺序、停顿和时长不变，只做后续已授权的视频包装。

#### 用户选择「允许删减」

```bash
# 1) 出计划和人可复核的报告
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --report plan.md

# 2) 读报告确认刀口安全，再出干净底片
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --apply base.mov
```

工具识别四类问题并给出刀口与理由：**重录废稿**（当前规则留最后一次）/ **半截句** /
**孤立口水词** / **长停顿**（收紧不删）。刀口只落在实测静音区间或整块上，绝不切半个字。

随后必须完成两个动作：

1. **交付 `clean-script.md`**：由 agent 按最终保留的口播块整理成一份从头到尾可连续阅读的完整文稿，
   对照 `plan.json` 与 `base.mov` 复核，确保只去掉已批准删除的内容。它不是刀口清单、时间区间、
   删除原因或差异摘要；`cut_plan.py` 不会自动生成这份文稿。
2. **继续制作视频**：把完整保留口播稿发给用户后，不再等待二次确认，直接以 `base.mov` 和
   `clean-script.md` 进入所选路径的后续制作，不能把流程停在删减报告或底片阶段。

#### 用户选择「不允许删减」

跳过删减，不运行 `cut_plan.py` 生成删减方案或底片，也不执行 `--apply` / `--reorder`。
**原视频、音频、原稿、内容顺序、停顿和时长全部不动**，直接把原媒体与原稿送入所选路径，
只做用户已授权的动效、字幕或配图包装。

无论哪条路径，`--reorder` 都不包含在「允许删减」的默认授权里；需要调片段顺序时必须另行取得明确同意，
否则一律保序。完整规则见 `references/cut-rules.md`，功能与产物说明见 `references/cut-feature.md`。

### Step 0.5 · ⭐ 路径分叉

Step 0.2 的授权分支完成后：

```
选了「通用」 ──────────────→ 走第三节 Step 1 → Step 7（本文档默认流程）
选了「晚枫专用」 ──────────→ 走 references/wanfeng-path.md 的 Step A → Step H
```

**两条路径是主客关系：通用路径是给所有人的默认流程，晚枫专用路径是晚枫本人的隐藏打法（彩蛋）**，
只在用户明确对号入座时才走（见文首「两条路径怎么选」）。晚枫专用路径**完全绕开**下面 Step 1–5 的内容：

| 通用路径 | 晚枫专用路径 |
|---|---|
| 原始口播先走 Step 0.2；允许删减才出干净底片与完整口播稿，拒绝则原样包装 | 同样先走 Step 0.2，随后从晚枫路径 Step A 继续 |
| Step 1 用正则把句子命中成 8 类动效、自动分配 slot | **手写场景表** `build_scenes()`，一场景讲一件事 |
| Step 2 联网检索社区动效实现 | **不检索**，版式全部自绘（Pillow 2 倍超采样） |
| Step 3 填动画描述（进出场/缓动/元素顺序） | 抄 `wanfeng-path.md` §4 的设计令牌与 §5 的版式库 |
| Step 4 落位校验（避人脸安全区） | 场景级参数 `head_pos` / `head_r` / `sub_dy` 直接指定 |
| Step 5 选引擎渲染 | Pillow 逐帧渲染 + ffmpeg 管道 |
| Step 6 自检三闸 | 静帧复核 → 重渲 → 抽帧终检 → 同步性与基频验证 → 两遍法响度归一 |

> **删减授权与配图采集都是两条路径共有的步骤**。晚枫专用路径说的"不检索"指的是不检索外部动效**代码**，
> 素材（截图、配图）照常联网找、照常做标注。规范见 `references/visual-assets.md`。

**怎么判断用户想要哪条**：只有用户明确表明自己是晚枫 / 做的是晚枫工作室账号的内容时才走晚枫专用
（出现「晚枫专用」「我们自己的风格」「按我们号里的调性」「和上次那条一样」即为明确信号，直接切换，不必再确认）。
**用户身份不确定、用途不明确 → 一律走通用路径**，不要替用户做「升级到晚枫线」的决定。

### Step 1 · 出骨架（本地，离线可跑）

> 通用路径走这里。**晚枫专用路径跳过 Step 1–5**，直接按 `references/wanfeng-path.md` 的 Step A → C 开始建工程。

```bash
python3 scripts/make_spec.py \
  --script 口播稿.md \
  --video  口播.mp4 \
  --srt    字幕.srt \
  --density standard \
  --style-path generic \
  --out    task/<时间戳>_motion/overlay-spec.json

# 没有视频文件、也没字幕时，至少把总时长钉准，别让字数硬估：
#   --duration 85        （优先级：实测媒体 > --duration > 稿件元信息 > 字数硬估）
```

> `--style-path wanfeng` 会切换产出：**不再做正则命中与 slot 分配**，改为输出一份
> `wanfeng-scene-plan.json` 场景骨架（时间区间 + 建议版式 + 该段口播原文），
> 供 agent 按 `references/wanfeng-path.md` §6 手写场景表。详见第四节的参数说明。

产物就是**引擎无关的时间轴契约**：每个 `segment` 含 `start / end / text / keywords / animation.type / slot / layer`。字段含义见 `templates/overlay-spec.example.json`。

跑完先把摘要念给用户听（几张卡、分布在哪些位置、总时长覆盖度），确认没问题再往下走。**不要跳过这个确认**。

### Step 1.5 · ⭐ 配图素材采集（按主题找图、截图、做标注）

按口播讲的主题找图、截图、做标注。**完整规范见 `references/visual-assets.md`**，这里只列执行顺序：

1. **先问用户一次**（不要拆成三轮来回追问）：
   > 配图这块我确认三件事：① 有现成截图可以直接用吗？② 有没有链接或官网地址，我可以自己去截？③ 都没有的话，我按「<主题>」去网上找，找不到就用动效顶上，可以吗？
2. **来源优先级**：用户给的截图 → 用户给的链接（自己截）→ 自己联网找 → 动画兜底。
3. **先定主题再找图**。不要逐句找——逐句找会退化成"给每句话配一张无关的图"。
4. **三条硬判据**（详见规范 §4）：
   - 图上出现的东西，**必须正是那一句口播在讲的东西**；
   - 图上不可见的内容不能当证据（折叠面板、长页超屏、懒加载）；
   - 文件名、OCR 命中、目录里的现成文件，**都不等于证据成立**。
5. **该标注的地方必须标注**：操作类与知识分享类配图要加步骤编号、箭头或高亮框。通用路径的标注在**渲染时叠加**（不烧进图片，同一张图能配不同段落）；晚枫路径用红框（`wanfeng-path.md` §5.6）。
6. **登记来源**：落 `assets/asset-manifest.json`，每张图记 URL、截取日期、`shows`（图上实际有什么）、`proves`（支撑哪句口播）。**写不出 `proves` 的图不要用**。
7. **兜底**：找不到就降级 —— 改用动效卡 → 自绘示意图 → 该场不配图。**绝不拿"看起来相关"的图硬凑**。

配图确定后写进 `overlay-spec.json` 对应 segment 的 `visual` 字段（结构见 `templates/overlay-spec.example.json`）。

### Step 2 · ⭐ 联网补肌肉（本 skill 的核心）

按 `references/research-protocol.md` 执行，**这一步是 agent 现场联网**：

1. 用协议里的**检索词矩阵**（8 类动画 × 中英双轨 + 限定词）搜，**硬预算：≤8 次搜索、≤4 次全文抓取**，超预算直接降级；
2. 命中候选后按**四维评分卡**（能跑 / 许可 / 引擎匹配 / 迁移成本）筛，**至少留 3 个可复制的实现**（≥7 分才入库）；
3. 每个候选落到 `research-notes.md`：来源 URL、许可、许可证边界、最小可跑片段、迁移到本项目要改哪几行；
4. **搜不到就如实降级**：走 `references/animation-brief.md` 里自带的纯 CSS/GSAP 最小实现，绝不假装搜到了。

> 这一步的产物允许为空（离线场景），但**必须显式写明「本次未联网，使用内置最小实现」**。

### Step 3 · 逐条填动画描述

对 `overlay-spec.json` 里每个 segment，按 `references/animation-brief.md` 的 8 类模板把「动画意图」写成具体描述（进出场、时长、缓动、元素级动画顺序），写回 `animation.brief` 字段。

分类靠关键词自动命中，agent 只做**校正**：数字类必须真的用数据组件，别退化成纯文字。

### Step 4 · 落位校验（防遮挡）

按 `references/overlay-layout.md` 检查每张卡的 `slot`：

- **人脸安全区**（竖屏 `x 0.30–0.70`、`y 0.18–0.76`；横屏 `x 0.28–0.72`、`y 0.18–0.70`）内不得放任何卡；
- 同一时刻同屏卡片数受密度上限约束（克制/标准 1 张、高密度 2 张），**超上限的那条直接弃卡**并在 spec 里留 `dropped` 原因，而不是挤进安全区；
- 相邻两卡切换至少留 0.2s 空档，不做叠化打架。

有冲突就挪位置，不要缩卡片尺寸硬塞。

### Step 5 · 选引擎并实现

```bash
# 探测
command -v node >/dev/null && node -v; command -v ffmpeg >/dev/null && ffmpeg -version | head -1
```

| 情况 | 走哪条 |
|---|---|
| 有 Node，且用户装了 Remotion 生态 | `references/engine-remotion.md` |
| 有 Node，且已在用 HyperFrames（含本仓库其他 skill 的链路） | `references/engine-hyperframes.md` |
| 只有 ffmpeg | 兜底：`make_spec.py --emit-png-plan` 出计划，agent 生成 HTML → 截图 PNG 序列 → `ffmpeg -filter_complex overlay` 合成 |
| 都没有 | 只交付 `overlay-spec.json` + `research-notes.md`，明确说「本机无渲染环境，已交付分镜与检索结果」 |

**实现要求**：每张卡的文案来自 `segment.text` / `keywords`，**不许自己编数据**（R2）。

### Step 5.5 · ⭐ 样片确认（可选，默认建议做）

位置在 Step 5 之后、Step 6 之前。此时**版式、卡片、配图、文案、渲染引擎全都定下来了** —— 这是唯一一次"改起来最便宜"的时刻。

**主动问用户**（不要等用户开口）：

> 全部选择都定好了。要不要先出 5 秒样片看看效果？也可以指定别的时长或哪一段。

| 项 | 做法 |
|---|---|
| 选哪一段 | 默认取信息密度最高的一段（既有口播、又有卡片、又有配图）；用户可指定 |
| 多长 | **默认 5 秒**；也可 10 秒或更短；用户可指定 |
| 怎么出 | **只渲选中的那一小段，不渲全片** |
| 产出 | `task/<时间戳>_motion/sample.mp4` |

各引擎的只渲一段的做法：

```bash
# Remotion：只渲这一段
npx remotion render <entry> out/sample.mp4 --frames=<startFrame>-<endFrame>

# ffmpeg 兜底：先截源视频片段，再走同一套 overlay
ffmpeg -ss <t> -t <len> -i 源视频.mp4 -c copy /tmp/clip.mp4
# 再用只覆盖该片段的 overlay-spec 渲 PNG 序列并合成
```

**样片不满意就重出样片，不要直接进 Step 6 渲全片** —— 全片渲染的几分钟成本远高于几秒样片。

### Step 6 · 自检三闸

渲染完必须跑，且把结果如实汇报：

1. **覆盖闸**：动效总时长 / 视频总时长 ≥ 40%（低于此说明包装太薄，回 Step 3 补卡）；
2. **遮挡闸**：抽 6 帧（均匀取样），确认无卡片压脸、无卡片超出安全边距；
3. **节奏闸**：任意连续 5 秒画面内至少 1 个可见变化（新卡出现 / 已有卡数值变化）。

抽帧：`ffmpeg -ss <t> -i final.mp4 -frames:v 1 check.png`（看完即删，不在 task 目录留验证图）。

### Step 7 · 交付

```
task/<时间戳>_motion/
├── overlay-spec.json     # ⭐ 可复跑：换引擎不用重做分镜
├── research-notes.md     # 联网检索结果（来源 + 许可 + 片段）
├── plan.json / plan.md   # 原始口播且用户允许删减时：计划与复核报告
├── base.mov              # 原始口播且用户允许删减时：干净底片
├── clean-script.md       # 原始口播且用户允许删减时：完整保留口播稿（agent 整理复核）
├── assets/               # 配图素材 + asset-manifest.json（来源登记）
│   ├── asset-manifest.json
│   └── *.png
├── src/                  # 引擎实现代码
├── sample.mp4            # 样片（Step 5.5，出 5–10 秒片段）
└── final.mp4             # 成片
```

交付时必带三句话：**时间戳是实测还是估算**、**本次有没有联网**、**前景遮挡做没做**。
外加一句：**配图是用户给的、网上找的、还是动画兜底的**。
原始口播还要说明是否执行了删减；允许删减时交付完整保留口播稿，拒绝时明确原内容未改。

## 四、`make_spec.py` 参数

| 参数 | 作用 |
|---|---|
| `--script` | 口播稿路径（必需） |
| `--video` / `--audio` | 源媒体，用于实测时长与画幅探测 |
| `--duration` | 手给成片总时长（秒）。时长优先级：**实测媒体 > `--duration` > 稿件元信息（「时长：~85s」）> 字数硬估**，来源会打进输出摘要 |
| `--srt` / `--timestamps` | 真实时间戳（`.srt` 或 `[{text,start,end}]` JSON） |
| `--density` | `sparse` / `standard` / `high`（默认 standard，见 Step 0 的间隔/同屏数） |
| `--style-path` | `generic`（默认，正则命中 + slot 分配，出 `overlay-spec.json`）/ `wanfeng`（出 `wanfeng-scene-plan.json` 场景骨架，见 `references/wanfeng-path.md`） |
| `--aspect` | `9:16` / `16:9` / `auto`（默认按视频探测） |
| `--max-slots` | **同屏并发卡上限**，覆盖密度默认值。超出上限的那条命中项会被弃卡并在 spec 里写 `dropped` 原因 |
| `--engine` | `auto` / `remotion` / `hyperframes` / `none`（写进 spec 供下游参考） |
| `--keep-meta-lines` | 把标题 / 表格 / 元信息行也当口播内容（**默认丢弃**，否则分镜时长会被非口播内容灌水） |
| `--no-net-hint` | 显式声明本次未联网，写进 `warnings`（R4） |
| `--emit-png-plan` | 额外输出 ffmpeg 兜底路线的 `ffmpeg-plan.json` |
| `--out` / `--stdout` | 写出 `overlay-spec.json` / 只打印不写文件（预览用） |

## 六、输出示例

下面两段是**本仓库真实稿件跑出来的**（`test/video/20260629_210000_什么是Token/01-Script/script.md`），不是示意。

**A. 只有稿件 + 手给时长（估算时间戳）**

```
$ python3 scripts/make_spec.py --script script.md --duration 85
== 口播动效骨架 ==
源视频：未提供｜85.0s（时长来源：given）｜9:16
时间戳：估算（4 字/秒）｜动画卡：8 张｜覆盖 26.1%｜单屏最多 1 张｜弃卡 0 条
分布：bottom 1｜left 1｜right 3｜top 3
类型：分屏对比(split-compare) 3｜清单逐条(checklist) 2｜品牌/产品名卡(logo-card) 2｜数字滚动卡(number-roll) 1
⚠️ 时间戳为估算（4 字/秒），交付前必须试听对齐 —— 见 SKILL.md 硬规则 R1
提示：覆盖率 26.1%，低于 Step 6 的 40% 交付闸 —— 回 Step 3 手工补卡（SKILL.md）
```

**B. 有真实时间戳（`[{text,start,end}]`）**

```
$ python3 scripts/make_spec.py --script script.md --timestamps timeline.json
== 口播动效骨架 ==
源视频：未提供｜85.0s（时长来源：script-hint）｜9:16
时间戳：实测｜动画卡：4 张｜覆盖 14.0%｜单屏最多 1 张｜弃卡 0 条
分布：right 2｜top 2
类型：品牌/产品名卡(logo-card) 3｜分屏对比(split-compare) 1
提示：覆盖率 14.0%，低于 Step 6 的 40% 交付闸 —— 回 Step 3 手工补卡（SKILL.md）
```

**怎么读这两段**：

- **卡少 ≠ 出错**。正则只吃显式结构（阿拉伯数字+单位、「不是 A 而是 B」、「第一/第二」）。中文数字、隐含对比、抽象概念**留给 Step 3 由 agent 补卡**——所以「覆盖率低于 40%」是骨架阶段的正常状态，不是交付状态。
- **B 比 A 更少是正常的**：实测模式下分句粒度跟着字幕走，不再按稿件重新切句。**不要因为数字好看就退回估算**（R1）。
- 出现「弃卡 N 条」时，说明这些句子命中了动画但同屏已满，spec 里对应段会有 `"dropped": "同屏已达上限（1 张），本条弃卡"`。想留卡就放宽上限（`--density high`，或直接 `--max-slots 2`）——但**上限是安全阀不是数字游戏**，放宽后必须回 Step 4 复核两张卡是否真的错开了。

## 七、硬规则（v1 不许违反）

| # | 规则 | 违反的后果 |
|---|---|---|
| **R1** | 估算时长必须标注 `estimated`，交付前必须让用户试听对齐 | 卡点和讲话错位，整片废 |
| **R2** | 卡上所有数字 / 名称 / 引语只能来自口播稿或用户提供的资料 | 编造数据，发出去就是事故 |
| **R3** | 不做人像抠图 / 前景遮挡，除非用户明确要求且接受降级（默认 `layer=behind`） | 抠图质量差会直接毁掉真人出镜 |
| **R4** | 联网没做成的事必须显式写明「本次未联网 / 未命中 / 用动画兜底」，不得假装引用了社区实现 | 许可与来源不可追溯 |
| **R5** | 引入任何外部代码前先确认许可；GPL / 不明许可的模板**不用**，MIT-0 / Apache-2.0 优先，并记进 `research-notes.md` | 商单成片有法律风险 |
| **R6** | 不调用任何付费接口（TTS / 生成 / 云渲染）；纯本地渲染 | 试错成本 |
| **R7** | 验证用截图看完即删，task 目录只留最终产物 | 目录脏 |
| **R8** | 配图必须与它所配的那句口播**严格对应**：图上出现的东西要真是那句在讲的 | 画面与口播对不上，观众当场看出来 |
| **R9** | 外部图片必须登记来源（URL / 截取日期 / `shows` / `proves`），进 `assets/asset-manifest.json` | 素材不可追溯，商用有版权风险 |
| **R10** | 操作类与知识分享类的配图**必须做标注**（步骤编号、箭头或高亮框） | 观众不知道该看哪儿，图等于没配 |
| **R11** | 原始口播未经用户明确授权不得删减；允许后必须交付完整保留口播稿并直接继续成片，拒绝则原片原稿不动 | 擅自改内容，或把流程停在删减阶段 |

> **选了「晚枫专用」路径后，R1–R10 中的 R3（前景遮挡）、R4（联网声明）、R5（许可核对）不适用**
> —— 那条路径不检索外部实现、也不做前景遮挡。
> 但 **R8 / R9 / R10 依然适用**：晚枫路径照样联网找素材，配图照样要对得上、照样要标注、照样要记来源
> （对应 `wanfeng-path.md` 的 W13–W15）。**R11 同样在两条路径适用**（对应 W16）。
> 取而代之的是 `references/wanfeng-path.md` §11 的 **W1–W16**（静帧先过、基线锚点、语速双改、
> fs 必配步骤条与人头、终检逐张读图、双版本交付、设计令牌勿改、交接文档必写本轮改动、
> 配图与口播严格对应、配图必须标注、外部图片必须记来源、删减必须授权）。

## 八、已知限制（v1 的坦白）

1. **不自带动效库** —— 这是设计选择，不是没做完。代价是首次运行要花 3–8 分钟联网检索；收益是不用追库存。想换成自带库，见 README「进阶：把检索结果固化成缓存」。
2. **不擅自剪辑** —— 原始口播只在用户明确授权后按 Step 0.2 做语义删减；拒绝删减时，包装时间轴严格按原输入走。重新配音与复杂多轨 NLE 不在 v1 范围。
3. **不做前景遮挡** —— 需要抠图（R3），默认卡片一律在人后面或画面空白处。
4. **图表数据不核实** —— 只搬运稿件里的数字，不联网查证、也不算账。
5. **中文优先** —— 分句、字数估算、关键词命中都按中文调；英文稿能跑但切分质量下降。
6. **渲染质量取决于本机环境** —— 没有 Node 只能走 ffmpeg 兜底，动效会明显朴素一档。
7. **`--timestamps` 模式不重新分句** —— 给了真实时间戳后，句子粒度完全跟着字幕走，命中率可能低于估算模式（估算会把稿件重新切成更细的句子）。这是取舍而非 bug：时间准确性 > 卡片数量，缺的卡在 Step 3 补。
8. **晚枫专用路径没有自动分镜** —— `--style-path wanfeng` 只出**场景骨架**（时间区间 + 建议版式），
   场景内容、版式选择、文案仍要 agent 按 `references/wanfeng-path.md` 手写。
   这是刻意的：晚枫的成片靠人手审美把关，自动正则命中只会出来一堆平庸的通用卡。
9. **晚枫专用路径绑死中文字体** —— Hiragino Sans GB 是 macOS 自带，换到没装这个字体的机器要手工换字体并重跑静帧。
10. **配图靠自己找，不保证有** —— 小众工具往往没有公开的界面截图。找不到就退自动效卡，这是设计内的降级。
    但**配图与口播对不上就是事故**，宁可少配几张。

```
knowledge-short-video（写口播稿）
```
