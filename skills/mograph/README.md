# 晚枫自动剪辑 · mograph

一句话：**给一条真人口播视频，按你讲话的内容，自动在人的上下左右弹出字卡 / 数据 / 图表 / 对比框，渲染成片。**

- v1 采用「**检索驱动**」架构：skill 不自带动效素材库，运行时由你本地的 AI 联网拉社区最新实现
- 零第三方 Python 依赖（骨架脚本只用标准库）
- **不调用任何付费接口**（不联网生成、不云渲染）
- 三条落地路线：Remotion → HyperFrames → 纯 ffmpeg 兜底

---

## 一、30 秒看懂它怎么用

```bash
cd mograph

# ① 先出骨架（离线、秒级、零风险）——看看它会给你出几张卡、放在哪
python3 scripts/make_spec.py \
  --script 我的口播稿.md --video 我的口播.mp4 --duration 85 --stdout

# ② 满意了再在对话里说：
#    「用 mograph 自动剪辑这条口播视频，稿子和视频在这儿」
#    agent 会联网找实现（Step 2）→ 填动画描述 → 选引擎渲染 → 自检交付
```

期望先看到这样一段（下面是本仓库真实稿件 `什么是Token` 跑出来的）：

```
== 口播动效骨架 ==
源视频：未提供｜85.0s（时长来源：given）｜9:16
时间戳：估算（4 字/秒）｜动画卡：8 张｜覆盖 26.1%｜单屏最多 1 张｜弃卡 0 条
分布：bottom 1｜left 1｜right 3｜top 3
类型：分屏对比(split-compare) 3｜清单逐条(checklist) 2｜品牌/产品名卡(logo-card) 2｜数字滚动卡(number-roll) 1
⚠️ 时间戳为估算（4 字/秒），交付前必须试听对齐
提示：覆盖率 26.1%，低于 Step 6 的 40% 交付闸 —— 回 Step 3 手工补卡
```

**为什么骨架只出 8 张、覆盖率 26%**：正则只能命中「阿拉伯数字 + 单位」「不是 A 而是 B」「第一/第二」这类显式结构。中文数字（一到两个）、隐含对比、需要视觉化的抽象概念，**留给 agent 在 Step 3 补**——这是设计分工，不是没做完。

## 二、为什么做成「联网现搜」而不是自带素材库

| 自带素材库 | 检索驱动（本 skill） |
|---|---|
| 发布即开始过期 | 每次运行都是社区当下最新 |
| 体积大（组件 + demo + 依赖） | 一个脚本 + 五份文档 |
| 风格被素材库锁死 | 风格由你的账号 / 参考片决定 |
| 许可责任在我（每次分发都要核对） | 许可责任在运行时确认（协议里有硬规则 R5 要求核对并记录） |
| 首次运行快 | 首次多花 3–8 分钟联网 |

**代价说清楚**：联网这一步的质量取决于你本地 agent 的检索能力。离线也能跑——走内置最小实现，动效会朴素一档，但**流程不会断**。

## 三、你要准备什么

| 必需 | 建议 | 可选 |
|---|---|---|
| 口播稿（`.md`/`.txt`） | 源视频或音频（用来实测时长与画幅） | SRT 字幕 / 词级时间戳 JSON |
| | 参考片链接（「我要这种感觉」） | 账号风格档（色板 / 字体） |

**没有真实时间戳会怎样**：按 4 字/秒估算，并在产物里打 `timing_source: "estimated"`。交付前必须试听对齐——卡点错位在口播视频里是最致命的返工原因。

## 四、三种机器的选择

| 你的机器 | 走哪条 | 效果 |
|---|---|---|
| 有 Node 18+，做数据/图表类动效 | Remotion | 最精细，组件可参数化复用。⚠️ Remotion 授权不是标准开源，商用先查官网 |
| 有 Node，且已在用 HyperFrames / 本仓库其他 skill | HyperFrames | MIT，HTML+GSAP，与封面/短视频链路视觉同源 |
| 只有 ffmpeg | 兜底路线 | 一定能出片，但数值滚动、逐条 stagger 会退化 |
| 什么都没有 | 只交付 `overlay-spec.json` + `research-notes.md` | 分镜与检索结果可带去别的机器渲染 |

## 五、拍视频可以这么走（约 2 分钟）

| 段落 | 画面 | 口播要点 |
|---|---|---|
| 0–15s 痛点 | 一条干讲 60 秒的口播原片 vs 加了动效的同一条 | "同一段话，信息密度差三倍" |
| 15–40s 骨架 | 跑 `make_spec.py --stdout`，滚动出卡片分布 | "先不渲染，先看它打算在哪几秒放什么卡、放左边还是右边" |
| 40–80s 联网 | agent 按 `research-protocol.md` 搜社区实现，`research-notes.md` 一行行写下来 | "它不靠自己脑补，它去搜——搜到谁、什么许可、几行能迁移，全记下来" |
| 80–110s 成片 | 渲染 + 抽帧自检 | "卡片永远不压脸，因为有个安全区在拦着" |
| 110–120s 收尾 | 打开 `overlay-spec.json` | "换引擎不用重做分镜，这才是能长期用的东西" |

**演示时最好现场踩到的三个点**（观众最信这个）：

1. 卡片和人脸安全区冲突时**位置被自动挪走**，而不是叠上去；
2. 时间戳是估的 → 屏幕上明晃晃打出 `⚠️ 估算` —— 建立"它不会装_done_"的信任；
3. 搜不到实现时，它明说"本次未联网，走内置最小实现"，仍然出片。

## 六、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一张卡都没出 | 稿件太叙述化（没有数字 / 没有列举 / 没有对比） | `--density high` 再看；仍为 0 就是稿子问题，回稿件加"可视觉化的钩子" |
| 卡片时间和讲话对不上 | 你没用真实时间戳 | 给 `--srt` 或 `--timestamps`；或 `--duration` 至少把总时长钉准 |
| 覆盖率一直 <40% | 骨架只吃显式结构 | 正常，Step 3 由 agent 补卡；不要为了让数字好看硬塞无意义卡 |
| 横屏卡片挡住人 | 人物不在画面中间 | 按 `overlay-layout.md §2` 手动收紧安全区 x 范围 |
| 想要卡片浮在人前面 | 需要逐帧抠图 | v1 明确不做（R3）；坚持要就先把 `layer` 改 `front` 并接受质量风险 |
| 商用时发现组件是 Noncommercial | 检索到的社区库许可限制 | 按协议换 MIT/Apache 候选；实在要用只借鉴方法论不搬代码 |
