# repowiki 格式规范详解

本文档是 popdf repowiki 格式规范的提炼与抽象，用于指导 AI Agent 在任意目标项目下生成同风格、同结构的 wiki 内容，输出目录统一为 `.wanfeng-wiki/`。

参考来源：popdf repowiki。若本地存在 popdf 仓库，可对照其历史产物 `popdf/.qoder/repowiki/zh/`（旧目录名，内容结构与本规范的 `.wanfeng-wiki/` 完全一致）；不存在时以本文档为准。

## 1. 顶层目录结构

```
<project_root>/.wanfeng-wiki/<lang>/
├── meta/
│   └── repowiki-metadata.json        # 元数据：项目代码片段索引
└── content/                          # 所有 Markdown 文档
    ├── 项目概述.md                    # 一级：项目整体概览
    ├── 快速入门.md                    # 一级：5 分钟上手
    ├── 安装指南.md                    # 一级：依赖与安装
    ├── 命令行使用.md                  # 一级：CLI 用法（可选）
    ├── GUI使用指南.md                 # 一级：GUI 使用（可选）
    ├── Web界面使用.md                 # 一级：Web 前端使用（可选）
    ├── 批量处理.md                    # 一级：批量场景（可选）
    ├── 核心功能详解/                  # 二级：按功能分组
    │   ├── 核心功能详解.md            # 总览文档（必填）
    │   ├── <功能大类A>/               # 三级：具体功能子目录
    │   │   ├── <功能大类A>.md         # 该类总览
    │   │   └── <具体功能1>.md
    │   └── <功能大类B>/
    │       └── ...
    ├── API参考/                       # 二级：API 文档
    │   ├── API参考.md                 # 总览文档（必填）
    │   └── <API大类>/
    │       └── ...
    └── 开发者指南/                    # 二级：面向贡献者
        ├── 开发者指南.md
        ├── 代码结构说明.md
        ├── 测试策略与实践.md
        └── 贡献代码指南.md
```

`<lang>` 是语言代码，默认 `zh`，可扩展为 `en`、`ja` 等。

`meta/repowiki-metadata.json` 是机器可读元数据，记录生成 repowiki 时所用到的代码片段（用于后续自动增量更新）。

## 2. Markdown 文件通用结构

每个 `.md` 文件必须包含以下五部分，缺一不可。

### 2.1 H1 标题

文件第一行必须是 H1，与文件名同名。

```markdown
# 项目概述
```

### 2.2 `<cite>` 引用块

`<cite>` 是自定义 HTML 标签，列出本文引用的所有源文件路径。

```markdown
<cite>
**本文引用的文件**
- [README.md](file://README.md)
- [pyproject.toml](file://pyproject.toml)
- [src/main.py](file://src/main.py#L1-L120)
</cite>
```

要点：
- 文件名与项目内相对路径，使用 `file://` 协议
- 行号范围仅在确知且确实重要时使用，格式 `#L<start>-L<end>`
- 引用必须真实存在，不允许指向未生成的虚构文件

### 2.3 目录

二级标题 `## 目录` + 有序列表，所有锚点指向本文档内的章节。

```markdown
## 目录
1. [简介](#简介)
2. [项目结构](#项目结构)
3. [核心组件](#核心组件)
4. [架构总览](#架构总览)
5. [依赖关系分析](#依赖关系分析)
```

要点：
- 二级子章节用 `   1. [子标题](#子标题)` 缩进表示
- 不写章节编号后的点号（如 `(1)`），只用数字加 `.`

### 2.4 正文章节

正文章节使用 H2/H3/H4 标题。不要使用 H5 以下标题。

每个章节末尾通常用以下三种引用块之一收尾：

| 引用块名称 | 用途 | 出现位置 |
|------------|------|----------|
| `**章节来源**` | 标注本章节引用的源文件 | 章节末尾 |
| `**图表来源**` | 标注前一个 mermaid 图的源文件 | mermaid 图后 |
| `**Section sources**` | 同上，英文场景使用 | 章节末尾 |
| `**Diagram sources**` | 同上 | mermaid 图后 |
| `**图示来源**` | 同上 | mermaid 图后 |
| `**图源**` | 同上，简化版 | mermaid 图后 |
| `**文档来源**` | 同上 | 章节末尾 |

> 经验：在中文项目中统一使用 `**章节来源**` / `**图表来源**` 即可。

引用块写法：

```markdown
**章节来源**
- [src/main.py](file://src/main.py#L1-L120)
- [README.md](file://README.md#L10-L30)
```

### 2.5 mermaid 图

每个核心概念必须配 1+ 个 mermaid 图。图必须紧跟一个引用块（`**图表来源**` / `**Section sources**`）。

mermaid 类型选择参考 [mermaid-patterns.md](mermaid-patterns.md)。

## 4. 引用链接格式

### 4.1 文件引用（不带行号）

```markdown
[README.md](file://README.md)
[src/main.py](file://src/main.py)
```

### 4.2 文件引用（带行号范围）

```markdown
[src/main.py](file://src/main.py#L1-L120)
[src/main.py](file://src/main.py#L50-L80)
```

行号格式：
- 闭区间 `[start, end]`
- 范围用 `L<start>-L<end>` 表示，左闭右闭
- 单行用 `L<start>` 表示

### 4.3 锚点引用（章节内跳转）

```markdown
[简介](#简介)
[核心组件](#核心组件)
[项目结构](#项目结构)
```

锚点规则：
- 把标题文本中的中英文标点去掉，空格替换为 `-`
- 小写（中文不变）
- 完整章节路径直接拼接，如 `[二级章节](#二级章节)`

### 4.4 跨文档引用

popdf 中跨文档引用较少。如果需要，使用相对路径：

```markdown
详见 [API参考](../API参考/API参考.md)
```

但更推荐在每个文档的 `<cite>` 块中直接列出源码路径。

## 5. repowiki-metadata.json

文件位于 `meta/repowiki-metadata.json`。当前 popdf 中的结构：

```json
{
  "code_snippets": [
    {
      "id": "uuid-like-string",
      "path": "src/main.py",
      "line_range": "1-200",
      "gmt_create": "2026-01-03T20:27:18.4240418+08:00",
      "gmt_modified": "2026-01-03T20:27:18.4240418+08:00"
    },
    ...
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一 ID，可用文件路径 + 行号哈希 |
| `path` | string | 相对项目根的源文件路径 |
| `line_range` | string | 行号范围 `start-end` |
| `gmt_create` | string | ISO 8601 时间戳，记录首次扫描时间 |
| `gmt_modified` | string | ISO 8601 时间戳，记录最近修改时间 |

`code_snippets` 中每个元素对应 repowiki 中引用过的一段代码。生成时只需覆盖 repowiki 中实际引用的文件，无需全量索引。

## 6. 中英文排版规范

- **中英文之间**：保留一个空格。例：`使用 popdf 库` 不要写成 `使用popdf库`。
- **标点**：中文文案用全角标点（，。：；？！），代码块、命令行、文件名内用半角。
- **数字与单位**：数字与单位之间保留一个空格。例：`1 分钟`、`100 MB`。
- **行内代码**：使用反引号包裹代码标识符、文件名、API 名。例：`popdf.pdf2docx()`。
- **强调**：粗体用 `**text**`，斜体用 `*text*`，避免使用下划线强调。
- **列表**：无序列表用 `-`，有序列表用 `1.`（数字递增，但 Markdown 渲染会自动编号）。

## 7. 禁用项

- ❌ 不要在 mermaid 图内使用 `style` 或 `classDef`（会导致部分渲染器异常）
- ❌ 不要使用 HTML `<table>` 标签（Markdown 表格即可）
- ❌ 不要使用 H5/H6 标题
- ❌ 不要在文档中嵌入外链图片（除非用户明确要求；可使用 `file://` 路径）
- ❌ 不要省略 `<cite>` 块或目录
- ❌ 不要使用 emoji（除非用户明确要求）
- ❌ 不要写营销文案、夸大宣传
