# 输出目录结构

本文档说明 repowiki 输出目录的完整结构、命名规则与裁剪策略。

## 完整结构

```
<project_root>/wiki/<lang>/
├── meta/
│   └── repowiki-metadata.json
└── content/
    ├── 00-overview.md                # 推荐：项目概述（顶层）
    ├── 快速入门.md
    ├── 安装指南.md
    ├── 命令行使用.md                  # 可选
    ├── GUI使用指南.md                 # 可选
    ├── Web界面使用.md                 # 可选
    ├── 批量处理.md                    # 可选
    ├── 核心功能详解/
    │   ├── 核心功能详解.md            # 必填：总览
    │   ├── <功能大类A>/
    │   │   ├── <功能大类A>.md        # 可选：该类总览
    │   │   ├── <具体功能1>.md
    │   │   └── <具体功能2>.md
    │   └── <功能大类B>/
    │       └── ...
    ├── API参考/
    │   ├── API参考.md                # 必填：总览
    │   └── <API大类>/
    │       ├── <API大类>.md          # 可选：该类总览
    │       └── <具体API>.md
    └── 开发者指南/
        ├── 开发者指南.md              # 必填：总览
        ├── 代码结构说明.md
        ├── 测试策略与实践.md
        └── 贡献代码指南.md
```

> 注意：popdf 参考中文件命名直接用中文（如 `项目概述.md`、`快速入门.md`），不需要 `00-` 前缀。建议直接沿用 popdf 命名风格。

## 命名规则

### 顶层文档

| 文件名 | 用途 | 是否必选 |
|--------|------|----------|
| `项目概述.md` | 项目整体介绍 | 必选 |
| `快速入门.md` | 5 分钟上手 | 必选 |
| `安装指南.md` | 安装与依赖 | 必选 |
| `命令行使用.md` | CLI 用法 | 仅 CLI 项目 |
| `GUI使用指南.md` | 桌面应用 | 仅 GUI 项目 |
| `Web界面使用.md` | Web 前端 | 仅前端项目 |
| `批量处理.md` | 批量场景 | 仅含批量能力的项目 |

### 二级目录

| 目录 | 用途 | 是否必选 |
|------|------|----------|
| `核心功能详解/` | 按业务/功能划分 | 必选 |
| `API参考/` | 按 API 大类划分 | 仅公开 API 项目 |
| `开发者指南/` | 面向贡献者 | 必选 |

### 三级目录命名

**核心功能子目录**：使用业务名词，如 `用户管理/`、`订单系统/`、`PDF转换/`、`PDF安全/`、`PDF编辑/`、`PDF组织/`。

**API 子目录**：使用 API 大类名词，如 `用户管理API/`、`认证API/`、`PDF转换API/`。

### 文件命名

- 中文文件名：直接使用中文（如 `项目概述.md`），不用空格分隔
- 英文文件名：使用 `-` 或 `_` 分隔（如 `getting-started.md`、`getting_started.md`）
- 文件名长度 ≤ 30 字
- 避免使用纯数字文件名

## 核心功能详解子目录设计

每个子目录代表一个"功能大类"，命名规则：

1. **业务导向**：使用项目业务名词。例：`用户管理`、`订单处理`、`内容审核`
2. **分层导向**：当项目是工具库时，按输出/操作类型划分。例：`PDF转换`、`PDF编辑`、`PDF安全`
3. **子目录必须有 2+ 个子项**：如果只有一个子项，合并到上级目录

子目录典型内容：

```
核心功能详解/
├── 核心功能详解.md                       # 总览：所有大类的简介与索引
├── 用户管理/
│   ├── 用户管理.md                       # 该类总览（可选）
│   ├── 用户注册.md
│   ├── 用户登录.md
│   └── 密码重置.md
└── 订单系统/
    ├── 订单系统.md
    ├── 下单.md
    └── 订单查询.md
```

## API 参考子目录设计

每个子目录代表一个"API 大类"，命名规则：

1. **资源导向**：使用 RESTful 资源名。例：`用户API`、`订单API`、`商品API`
2. **能力导向**：使用功能分类。例：`认证API`、`授权API`、`搜索API`
3. **协议导向**：按通信协议划分。例：`REST API`、`GraphQL API`、`WebSocket API`

子目录典型内容：

```
API参考/
├── API参考.md                            # 总览：所有 API 大类的简介
├── 用户API/
│   ├── 用户API.md                        # 该类总览
│   ├── 用户注册接口.md
│   ├── 用户登录接口.md
│   └── 用户信息接口.md
└── 订单API/
    ├── 订单API.md
    ├── 创建订单.md
    └── 查询订单.md
```

## 开发者指南子目录设计

```bash
开发者指南/
├── 开发者指南.md          # 必填：概述项目结构、贡献流程
├── 代码结构说明.md        # 必填：分层架构说明
├── 测试策略与实践.md      # 推荐：测试组织、覆盖率
└── 贡献代码指南.md        # 推荐：PR 流程、Code Review
```

可按需扩展：

- `环境搭建.md` —— 详细本地开发环境配置
- `发布流程.md` —— 版本号、CHANGELOG、打包发布
- `性能优化.md` —— 性能瓶颈、调优记录
- `国际化指南.md` —— i18n / l10n 流程
- `安全审计.md` —— 安全规范

## meta/repowiki-metadata.json 字段说明

```json
{
  "code_snippets": [
    {
      "id": "<唯一 ID>",
      "path": "<相对项目根的源文件路径>",
      "line_range": "<start>-<end>",
      "gmt_create": "<ISO 8601 时间戳>",
      "gmt_modified": "<ISO 8601 时间戳>"
    }
  ]
}
```

`id` 推荐生成方式：

- 哈希：MD5(`<path>:<line_range>`) 取前 32 位
- 或：`snippet-<8位hash>`

`gmt_create` 与 `gmt_modified` 默认使用当前时间；增量更新场景下，使用文件实际修改时间。

## 与 popdf 的差异调整建议

| popdf 原貌 | 一般项目调整 |
|------------|--------------|
| 只有 `zh` 一种语言 | 默认生成 `zh/`；可按用户选择同步生成 `en/`（双语）或只生成 `en/` |
| `meta/repowiki-metadata.json` 是单层 | 不变 |
| 顶层文档用中文文件名 | 同左，或视项目惯例用英文 |
| `核心功能详解/` 文档数较多 | 按本项目实际功能裁剪 |
| `API参考/` 文档数较多 | 按本项目实际 API 裁剪 |
| 包含 `GUI使用指南.md`、`Web界面使用.md` | 按项目实际入口裁剪 |

## 输出前自检清单

- [ ] 输出目录存在且为空（或用户允许覆盖）
- [ ] 每个 `<lang>/content/` 下的 `.md` 文件符合五段式骨架
- [ ] 每个 `<lang>/content/` 下的 `.md` 文件都包含 `<cite>` 块
- [ ] `meta/repowiki-metadata.json` 是合法 JSON
- [ ] 不包含冗余文档（如纯 CLI 项目的 GUI/Web 文档）
- [ ] 不包含虚构的源文件引用
- [ ] 所有 mermaid 图都有引用块
- [ ] 所有 `file://` 路径在目标项目下真实存在
