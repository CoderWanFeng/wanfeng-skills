# 口播稿写法与镜头标记

文稿是整条链路的源头，后面每一步都从它派生。没有稿就谈不上拆解。

## 5 条写作规则

1. **短句、口语、一句一个信息点**。阅读体的长句要拆成口播短句，超过 45 字基本就该拆了。
2. **表格不逐条念**。清单类内容放画面上，口播只念分组词和合计——画面讲逻辑，口播讲结论。
3. **限定口径必须保留**。数字、资格、条件的表述要写准，不能变成标题党。
4. **链接、二维码、"扫码/点击"字样不进稿、不进画面**。
5. **标好镜头类型**。哪段出镜、哪段用 MG 画面。

## 标记语法

| 写法 | 含义 |
| --- | --- |
| 不写任何标记 | 默认全部是出镜口播（A-roll），费用最高 |
| `[[A]]` | 显式切回出镜口播 |
| `[[A:happy]]` | 出镜 + 指定情绪 |
| `[[A:happy\|scene=明亮的书房]]` | 出镜 + 情绪 + 场景，场景会写进视频提示词 |
| `[[B]]` 或 `[[BROLL]]` | 之后的台词属于 B-roll：只合成音频，不生成画面 |
| `[[BROLL:展示聊天界面录屏]]` | B-roll + 画面提示，提示会写进时间码表给剪辑看 |

规则细节：

- 标记可独占一行，也可内联在行首。
- **分组不会跨越镜头边界**，所以标记之后的句子归下一个镜头。
- `[[BROLL:提示]]` 里的提示如果要点名素材文件，**文件名（不含扩展名）必须完整出现**，否则占位预览片里该段只是深灰块。

## 9 种合法情绪

`happy` / `sad` / `angry` / `fearful` / `disgusted` / `surprised` / `calm` / `fluent` / `whisper`

- **没有 `neutral`**，中性就是 `calm`。写错的值会被忽略并给出警告。
- 不标情绪时，模型会自己匹配，长稿容易出现「整条一个调」。
- 情绪和场景**不额外计费**，只是请求体字段，放心逐段标。

## 正例

```
[[A:happy|scene=明亮的书房]]
大家好，我是这个账号的作者。今天这条视频，声音和画面都是我自己的克隆。

[[BROLL:展示聊天界面]]
这条消息是我自己发的，时间是凌晨一点。

[[A:calm|scene=夜晚的办公室]]
先说结论：整条流水线跑下来，成本远低于你想象的。
```

## 反例（真实踩过的坑）

**反例一：单括号标记**

```
[A]
大家好，我是这个账号的作者。
```

引擎只认 `[[A]]`。单括号 `[A]` 会被当成正文，配音里会念出「A」——一次废掉整条配音，还得重付一次钱。

如果手里的稿子是单括号格式，必须先转换，**并且验证实际解析结果**（打印分段正文，确认没有残留标签）。只把 `[A]` 替换成 `[[A]]` 不代表一定解析正确。

**反例二：全片不标 B-roll**

两分钟的稿子一句 `[[BROLL]]` 都没有 → 系统认为是全程出镜 → 视频费用直接拉到最高档。演示、录屏、图表类段落都该标成 B-roll。

**反例三：长句**

> 我今天想跟大家分享的是关于如何用AI工具在没有任何技术背景的情况下完成一条高质量视频的制作流程。

口播念到一半就该断气了。拆成三句，每句一个信息点。

## 分段与时长

- 默认单段目标上限 13 秒，超长会自动切。想更细的字幕时间码可以用 `--segment-seconds 8` 调小。
- 数字人视频按**每次请求的秒数**计费，不是按最终剪进成片的秒数。所以分段不是越细越好：段数多、每段有 4 秒最低请求时长，反而更贵。
- 一段 A-roll 的台词最好不要超过 15 秒，超过就得拆，否则单次请求会超接口上限。

## 快速自检

写完稿子先跑一次零费用体检，它会检查单括号、非法情绪、B-roll 缺失、长句、链接字样，并给出报价：

```bash
python3 <skill>/scripts/preflight.py --root . --stage broll
```
