# 平台差异对照（切段与提示词的地基）

这份文档只做一件事：**告诉你去哪家数字人平台开工前，本地要把哪些字段准备好**。本 skill 不调用任何平台 API，也不代你选平台——它只负责把长稿切成"任何平台都能吃"的分段脚本、把每段提示词按目标平台的规范排好、把参考素材按各家底线体检。

各家平台的字段名、单段上限、素材规格会随版本迭代变动。**下表是方向性参考，最终一定以平台官方文档为准**。发现与实际不一致，改本文件的对应行即可，不必回来改 skill 主流程。

## 1. 一张表看懂

| 平台 | 单段上限（约） | 需要的参考素材 | Prompt 风格 | 备注 |
| --- | --- | --- | --- | --- |
| MiniMax H3 | ≤ 15 秒（口播建议 ≤ 10 秒） | 正脸参考（照片或 2-15 秒视频）+ 参考音频（可选，克隆音色用） | 自然语言长句 | 需要"参考音频 → 口型对齐"能力时首选 |
| 可灵 Kling | ≤ 10 秒 | 正脸参考（1 张） | 自然语言 + 关键词 | 有专门的"对口型"入口，需要单独走 |
| Vidu | ≤ 8 秒 | 正脸参考（1 张） | 自然语言 | 主打分镜一致性，人物参考图越干净越好 |
| HeyGen | 无硬切段（按脚本整段生成） | 正面照 + 半身照 + 音频 | 结构化字段（tts + avatar + background） | 有 API 但本 skill 不调 |
| D-ID | ≤ 30 秒 | 正脸照 + 音频（TTS 或原声） | 结构化字段（source_url + script） | 老牌的说话头像工具 |
| 阿里万相 / 腾讯智影 / 火山数字人 | 各家产品不同 | 正脸 + 音频 | 后台向导填字段 | 一般要在控制台点选，脚本化程度低 |
| 自托管 ComfyUI（H3 REF2VA 之类） | 由工作流决定 | 正脸 + 参考音频 | 工作流节点参数 | 本仓库有 v2 遗留实现，见 `legacy-integration.md` |
| 通用 / 未知平台 | 按 4-10 秒切 | 正脸 + 参考音频（可选） | 六要素模板 | 拿不准就走这条 |

## 2. 为什么通用视频大模型不算数字人

数字人出镜段的技术要求是「**参考音频 + 参考形象 → 口型对得上的说话视频**」。

Sora、Veo、Runway、PixVerse 通用档这一类模型是「文字/图片 → 视频」，**不接受参考音频**，所以：

- 做不了按配音对齐的口型；
- 硬拼出来的画面会「嘴在动但不对词」，观众一眼看出假。

它们只用于 B-roll：片头、空镜、示意图、情绪镜头。真要出镜口播，走上面这张表里的"数字人向"平台。

用户如果坚持要用通用模型做口型，正确说法是：需要额外的对口型后处理（lip-sync），本 skill 不含这一步，不要承诺。

## 3. `segments.json` 字段与平台的映射

本 skill 产出的 `segments.json` 用一组通用字段承载所有平台需要的所有信息。到具体平台时按下表映射：

| 本 skill 字段 | MiniMax | 可灵 | Vidu | HeyGen | D-ID | 通用 |
| --- | --- | --- | --- | --- | --- | --- |
| `text`（本段台词） | `prompt` 的主体 | `lyrics` / 台词字段 | 台词字段 | `content[].text` | `script.input` | 直接放进 prompt |
| `duration_hint`（预计秒数） | `duration` | 时长选择 | 时长选择 | 自动 | 自动 | 附在 prompt 里 |
| `emotion`（9 值之一） | `emotion` 字段 | 融进 prompt | 融进 prompt | 融进 prompt | 不支持 | 融进 prompt |
| `scene`（背景/氛围） | 融进 prompt | `image_tail` / prompt | prompt | `background` | 不支持 | prompt |
| `refs.persona`（正脸参考） | 参考形象上传 | 参考图上传 | 参考图上传 | Avatar 图片 | source_url | 手动上传 |
| `refs.voice`（参考音频） | 音色克隆 voice_id | 视产品 | 视产品 | TTS 或音频 | audio_url | 手动上传 |

**规则**：字段名不重要，重要的是**每一段有独立的台词、时长、素材、情绪、场景**这五件事。目标平台缺哪个字段就在 prompt 里补描述，缺不了就不切这段。

## 4. 提示词风格：两种范式

### A. 自然语言长句型（MiniMax / 可灵 / Vidu）

把六要素拼成一段连贯的话。示例：

```
一位 30 岁左右的亚洲男性在明亮的书房里，正面中景，自然光从左侧窗户斜射，
面带微笑、语气轻松地对着镜头说"……"。他微微点头，双手自然垂放在桌面上，
背景是浅木色书架和米色墙壁。竖屏 9:16，浅景深，纪实感。
```

### B. 结构化字段型（HeyGen / D-ID / 云厂商控制台）

按平台后台的字段一栏一栏填。本 skill 输出的 `prompts/seg_XXX.txt` 会用行首标签的方式给到，例如：

```
subject: 30 岁亚洲男性
shot: medium-frontal
lighting: 自然光 侧顺
emotion: calm
action: 说话 + 微微点头
background: 明亮书房 浅木色书架
```

用户可以直接复制每一行贴到对应输入框。

### 通用六要素（无平台模板时）

- **主体**（谁）：年龄段、性别、明显特征
- **景别**（特写 / 中景 / 全景）
- **光线**（自然光 / 三点布光 / 冷光 / 逆光）
- **情绪**（走 9 值：`happy` `sad` `angry` `fearful` `disgusted` `surprised` `calm` `fluent` `whisper`）
- **动作**（说话 / 微微点头 / 手势）
- **背景**（纯色 / 书房 / 办公室 / 具体物件）

## 5. 单段时长怎么定

各家平台上限不同，切段前先在下面这张表里查：

| 目标平台 | 建议单段上限 |
| --- | --- |
| MiniMax H3 | 10 秒（硬约束 15 秒） |
| 可灵 | 10 秒 |
| Vidu | 8 秒 |
| HeyGen | 无硬切段；建议 ≤ 30 秒避免长时间口型疲劳 |
| D-ID | 30 秒 |
| 自托管 ComfyUI | 由工作流决定，参考 `legacy-integration.md` |
| 通用 | 6 秒 |

**估算方法**：中文口播按 **4 字/秒** 折算。一段 40 字的台词大约 10 秒，正好卡在 MiniMax 与可灵的建议上限。

**不要为省段数硬堆时长**：MiniMax 每段有 4 秒最低计费，超过平台上限会直接拒。宁少勿长。

## 6. 平台未列在上面怎么办

选「通用」：

- 切段按 6 秒/段；
- 提示词按六要素模板；
- 素材按 `material-prep.md` §2 的通用底线；
- 交付时 `segments.json` 的 `target_platform` 字段填 `"generic"`，同时在 `README-for-platform.md` 里把用户提到的平台特性以文字形式写清。

用户下一次说"其实我要用 XX 平台"，只要重新跑 S3（提示词排版）就行，切段结果可以复用。

## 7. 变更验证状态

本 skill 不调任何平台，因此**不承诺上表数据的实时性**。发现字段名、上限或素材要求与官方不一致：

1. 直接改本文档对应行；
2. 在提交信息里写清"根据 X 平台官方文档 YYYY-MM-DD 更新"；
3. 不需要动 SKILL.md 主流程与 engine 代码。
