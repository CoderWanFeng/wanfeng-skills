# 素材准备与本地体检

v3 主流程的第二步（S2）就是照着这份文档逐项过素材。**全部动作在本地完成，不发起任何网络请求，不上传任何内容**。用户素材留在自己的电脑上。

## 1. 三类必查素材

| 类别 | 是不是必需 | 用来做什么 |
| --- | --- | --- |
| **正脸参考**（照片或短视频） | 必需 | 决定数字人长什么样，几乎所有平台都要 |
| **参考音频**（本人清晰说话） | 仅在需要克隆音色时必需 | 决定数字人用什么声音说话；不克隆可跳过 |
| **风格锚点**（可选） | 可选 | 服装、背景、色温、氛围的一致性参考 |

## 2. 通用底线（跨平台都成立的最低要求）

**正脸参考**

- 单人画面，无遮挡脸部（墨镜、口罩、帽子、头发挡眼都不行）
- 分辨率 ≥ 512×512，短边像素够
- 光照均匀，不逆光、不半侧脸阴影
- 背景简单（纯色 / 弱纹理），别在杂物堆里拍
- 常见格式：jpg / png（照片），mp4 / mov（视频）

**参考音频**

- 时长：10 秒 – 5 分钟（MiniMax 音色克隆的常用区间，其他平台略有差异）
- 单人说话，无背景音乐、无他人插话、无强回声
- 采样率 ≥ 16kHz，格式 mp3 / m4a / wav 均可
- 内容就是普通说话，不必念特定文本；越接近你未来口播的语气，克隆效果越好

**风格锚点**（可选）

- 一张能代表"我就是希望视频长这样"的参考帧，比如过往成片截图、色卡、场景照
- 只在平台支持"氛围参考"或"多帧一致性"时才有用（可灵、Vidu、HeyGen 的 avatar 风格设置）

## 3. 各家平台的加严项

`platform-notes.md` §1 有一张对照表，这里只列**比通用底线更严**的点：

| 平台 | 加严点 |
| --- | --- |
| MiniMax H3 | 参考视频：单段 2–15 秒、总长 ≤ 15 秒、≤ 50MB、宽高比 5:2 ~ 2:5；参考音频：≤ 20MB |
| 可灵 Kling | 参考图必须正脸；建议单张 ≤ 10MB |
| Vidu | 主打分镜一致性，参考图越干净越好，避免复杂背景 |
| HeyGen | 建议正面照 + 半身照两张；半身照需露肩以上 |
| D-ID | 只吃 source_url（可上传后拿到的公网链接），需要用户先在 D-ID 后台生成 |
| 万相 / 智影 / 火山 | 后台上传向导会限制体积与像素，具体看当次引导 |

拿不准时按通用底线准备，缺口 S2 会明确指出**要不要补、去哪儿补**，不会让你带着有问题的素材去开工。

## 4. 本地体检怎么做（零 API、零上传）

只读文件属性，不改内容、不上传。macOS 与 Linux 上常用两条命令：

```bash
# 图片素材（macOS）
sips -g pixelWidth -g pixelHeight -g format <文件.jpg|png>

# 图片素材（跨平台，含 exif）
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,codec_name,pix_fmt \
  -of default=noprint_wrappers=1 <文件>

# 音频素材
ffprobe -v error -show_entries format=duration,bit_rate \
  -show_entries stream=codec_name,sample_rate,channels \
  -of default=noprint_wrappers=1 <文件.mp3|wav|m4a>

# 视频素材（抽正脸参考帧用）
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,duration,r_frame_rate,codec_name \
  -of default=noprint_wrappers=1 <文件.mp4|mov>
```

体检方法：

- **图片**：短边 ≥ 512？宽高比是否落在 5:2 ~ 2:5 之间？格式在支持列表里？
- **音频**：时长在 10 秒 – 5 分钟之间？采样率 ≥ 16kHz？单人（这个要人耳判断，skill 只报硬件指标）？
- **视频**：时长 ≤ 15 秒？体积 ≤ 50MB？能不能正常解出一帧正脸（用 `ffmpeg -ss 1 -vframes 1` 抽一帧看看）？

**只做这些**。不要跑人脸检测、不要跑 ASR、不要联网比对——这些动作要么需要第三方 SDK，要么就把素材送出去了。

## 5. 常见缺素材情形的应对

| 缺什么 | 怎么快速补 |
| --- | --- |
| 有自拍视频但没录音 | 从视频抽音轨当参考音频：`ffmpeg -i 自拍.mov -vn -ac 1 -ar 32000 -b:a 128k voice.mp3` |
| 只有照片没有视频 | 大多数平台接受单张正脸照，够用 |
| 正脸照分辨率不够 | 让用户体验重拍：**手机前置摄像头 + 白天窗边 + 纯色墙**，一张就够 |
| 背景很乱 | 用平台自带的"背景替换"能力（HeyGen、智影、万相都有），或在 prompt 里显式指定背景 |
| 参考音频有 BGM | 换一段更干净的；实在没有就在 checklist 里标 🔄「建议替换」，让用户知道效果会打折 |
| 多人混入 | 直接标 ⚠️ 缺失，要求重录；不能靠切段修 |

## 6. `asset-checklist.md` 三档状态

在 S2 输出的清单文件里，每项素材用三档标记：

- ✅ **已到位**：分辨率 / 时长 / 格式都过；人眼初检合格
- ⚠️ **缺失**：目标平台需要但用户没有
- 🔄 **建议替换**：有但明显不合适（模糊、多人、有 BGM、比例不对）

清单模板：

```markdown
# 素材体检清单

## 正脸参考
- 文件：input/persona/face.jpg
- 状态：✅ 已到位
- 实测：1080×1440, jpg, 单人正脸、光照均匀
- 目标平台（MiniMax H3）要求：短边 ≥ 512、宽高比 5:2 ~ 2:5、≤ 50MB —— 全部符合

## 参考音频
- 文件：input/voice/source.mp3
- 状态：🔄 建议替换
- 实测：32.4 秒, 44.1kHz, 单声道, 128kbps
- 问题：底噪偏大（用户自述在马路边录制）
- 建议：在室内重录一段 30 秒左右的清晰单人朗读，替换后重跑 S2

## 风格锚点（可选）
- 状态：⚠️ 缺失
- 建议：如需保持系列一致，提供 1 张过往成片截图
```

## 7. 「素材到位」的验收清单（进 S3 前）

- [ ] 至少一张正脸参考，标 ✅
- [ ] 需要克隆音色时，参考音频标 ✅
- [ ] 目标平台专属的加严项全部核对过（对照 §3）
- [ ] 用户明确回复"就用这些素材，不再补了"，或同意带着 🔄 项继续

只有以上全部满足，才进 S3 生成提示词。带着 ⚠️ 缺项进 S3 会让产物变成"看起来对但一开工就报错"的施工图，得不偿失。
