# 画幅适配（6 种画幅手册）

**给谁看**：SKILL.md 第 2 步选完画幅之后，Agent 按这份文档决定"要不要人工介入、介入到什么程度"。选 9:16（默认）基本不用读这份，直接往下走。

**核心原则**：

- **画幅和风格是两个独立的选择**——任何风格都能出任何画幅，互不影响
- **设计画布恒为 1080×1920**——渲染器里的坐标、字号、卡片尺寸全是按这个尺寸手调的，画幅差异只在**输出端**映射（`mgkit/canvas.py`），所以改画幅**不需要动一行版式代码**
- **竖版系全自动，横版半自动**——横版是"竖版内容 + 横版容器"，框架给自动底板，想要真正的横版排版得人工重排（§3 给了四档做法，按成本从低到高）
- **不要为了适配画幅去改渲染器里的 `W, H`**——除非你确实要走 §3 的 D 档（全量重排），否则会破坏零回归

---

## 0. 六种画幅对照（先决定出哪个）

| 代号 | 画幅 | 输出尺寸 | 适合平台 | 适配方式 | 一句话预期 |
|---|---|---|---|---|---|
| 1 | **9:16** | 1080×1920 | 抖音 / 视频号 / 小红书 / B站竖屏 | `design` 原样 | 默认，和历史样片逐像素一致 |
| 2 | **2:3** | 1080×1620 | 小红书封面 / 竖版海报 | `fit` 等比缩放 | 内容缩到 0.844x，左右各补 84px 底色 |
| 3 | **4:5** | 1080×1350 | Instagram / 公众号长图 | `fit` 等比缩放 | 内容缩到 0.703x，左右各补 160px 底色 |
| 4 | **1:1** | 1080×1080 | 朋友圈 / 公众号方形配图 | `fit` 等比缩放 | 内容缩到 0.562x，左右各补 236px（可换延展背景，见 §2.2） |
| 5 | **16:9** | 1920×1080 | B站 / YouTube / 公众号横版 | `relayout` 重排 | 竖版主画面 + 模糊延展背景，可加右侧标题栏 |
| 6 | **4:3** | 1440×1080 | 展板 / 培训课件 | `relayout` 重排 | 同上，容器窄一点 |

**怎么选**：

- 用户没说投哪儿 → **9:16**，别自作主张换
- 只发小红书 / 只发朋友圈 → 2 或 4，画幅本身就够了，不用重排
- 要上 B站 / YouTube 横版 → 5，**并且必须跟用户讲清楚横版是"竖版内容放进横版容器"**（§3），不是重新排的横版
- 一个选题要出多平台 → **同一份内容建两份工程**（或一份工程改 canvas.json 跑两遍），别指望一次出全部

## 1. 画幅怎么定（三种入口）

### 1.1 新建工程时（推荐）

画幅是 `新建选题.sh` 的第 3 个参数，和第 2 个参数（风格代号）互不影响：

```bash
bash "<Skill>/模板/新建选题.sh" "<选题名>" D 16:9      # 故障艺术 + 横屏
bash "<Skill>/模板/新建选题.sh" "<选题名>" H 4:5       # 工笔画 + 竖版方
bash "<Skill>/模板/新建选题.sh" "<选题名>" E 5         # 代号也行，5 = 16:9
```

代号 1–6 和比例字符串都认，`16x9` / `16：9` 这种写法也会自动归一。写错了直接报错退出，不会默默用默认值。

结果写进 `<选题>/canvas.json`，渲染器启动时自己读：

```json
{
  "ratio": "16:9"
}
```

### 1.2 已有工程换画幅

改 `canvas.json` 里的 `ratio`，重跑就行，**风格不用动、版式代码不用动**：

```bash
cd "<选题>" && cat > canvas.json <<'EOF'
{
  "ratio": "1:1"
}
EOF
cd MG样片-<风格名> && python3 build_mg_*.py --preview
```

临时试一下不想改文件，用环境变量（优先级高于 canvas.json）：

```bash
MG_CANVAS=4:3 python3 build_mg_*.py --preview
```

### 1.3 老工程（画幅功能上线前建的）先升级

**症状**：改了 `canvas.json` 一点反应没有，帧还是 1080×1920。

**原因**：工程建的时候会把 `mgkit/` 复制进去做自包含，所以老工程里躺着一份**过期的 mgkit 副本**（没有 `canvas.py`），渲染器也没接 `CANVAS`。

**解法**：跑升级工具，它会同步最新 mgkit、给渲染器接画幅、补 `canvas.json`，可重复执行：

```bash
cd "<选题>"
python3 "<Skill>/模板/工具-升级画幅.py"                    # 只升级，画幅不动
python3 "<Skill>/模板/工具-升级画幅.py" 16:9 "主标题" "副标题"   # 升级顺便把横版定了
```

**只要改过 Skill 的 `模板/mgkit/`，老工程就得重跑一次这个工具。** 这是工程自包含设计的固有代价，不是 bug。

## 2. 竖版系（9:16 / 2:3 / 4:5 / 1:1）—— 自动，基本不用管

### 2.1 `fit` 干了什么

整帧等比缩放 → 居中 → 用画面四角的中位数底色补边。风格背景基本都是纯色或纯纹理，补边接缝肉眼看不出来。

| 画幅 | 缩放比 | 主画面 | 左右补边 | 上下补边 |
|---|---|---|---|---|
| 9:16 | 1.000x | 1080×1920 | 0 | 0（`design`，原样输出） |
| 2:3 | 0.844x | 911×1620 | 各 84px | 0 |
| 4:5 | 0.703x | 759×1350 | 各 160px | 0 |
| 1:1 | 0.562x | 608×1080 | 各 236px | 0 |

**要提醒用户的只有一件事**：缩放比越低，字越小。4:5 之后正文小字（≤28px 那档）在手机上已经开始吃力，1:1 更明显。**字看不清就砍文案、放大字号，别指望补边帮你救。**

### 2.2 嫌左右补边太素 —— 用 `mode` 覆盖

竖版系默认 `fit`（纯色补边）。想要横版那种"模糊延展背景"的效果，在 `canvas.json` 里覆盖适配方式：

```json
{
  "ratio": "1:1",
  "mode": "relayout"
}
```

`mode` 可选 `design` / `fit` / `relayout`，不给就用画幅预设的默认值。

两种效果的取舍：

| | `fit`（默认） | `relayout` |
|---|---|---|
| 主画面大小 | 更大（顶满画布高度） | 更小（四周留呼吸，缩到 0.45x 左右） |
| 边缘 | 纯色底，接缝取决于背景是否纯色 | 模糊放大的同帧背景，永远没有接缝 |
| 适合 | 背景纯色 / 用户想信息量最大化 | 背景有渐变、纹理、截图铺底；或想要"卡片感" |

**判断方法**：先跑 `fit` 出检查图，看补边和画面边缘有没有明显色差带。有 → 换 `relayout`；没有就别折腾。

## 3. 横版（16:9 / 4:3）—— 四档做法，按成本挑

横版必须让用户知道一件事：**竖版内容不会自动变成横版构图**。框架能做到的是"把竖版画面体面地放进横版容器"，做不到的是"重排成左右分栏的横版信息架构"——后者要人工决策。

四档做法，**默认停在 B，用户明确要"真正的横版"才上 C/D**。

### 3.1 A 档：纯自动底板（零配置）

`canvas.json` 只写 `{"ratio": "16:9"}`，不给标题。

效果：竖版主画面按高度缩到 0.45x（486×864）**居中**，四周是模糊延展的同帧背景，主画面带一圈细边框 + 轻投影。

适合：先看看横版长什么样、或者画面本身不需要额外文字。**这是最保险的一档，不会出错也不会好看。**

### 3.2 B 档：自动底板 + 右侧标题栏（推荐默认）

给标题，主画面自动**左置**，右侧空出来排标题——这就是横版左右分栏的雏形。

```json
{
  "ratio": "16:9",
  "title": "你最想先试哪个",
  "subtitle": "评论区告诉我，下期实测",
  "title_role": "sans_bold",
  "subtitle_role": "sans_regular"
}
```

16:9 下右侧可用区实测是 **(683, 64) 1122×908**；主画面落在 x=115，宽 486。

**字体角色一定要挑对**（`title_role` / `subtitle_role` 取 `fonts.py` 的六个角色名）：

| 风格 | 建议角色 | 理由 |
|---|---|---|
| A 深色科技 / B 亮色杂志 / D 故障 / E 像素 / F 暖色 / G 简笔画 | `sans_bold` + `sans_regular` | 黑体系，和画面正文字重一致 |
| C 复古拼贴 / H 工笔重彩 | `serif_bold` + `serif_regular` | 衬线系，配画面里的宋体/衬线标题 |
| 想要品牌感 | `brand_bold` + `brand_regular` | 斜体大字，只适合强钩子那两句 |

角色名写错不会报错，但会**退回 PIL 默认位图字体**——表现为字号极小、像没渲染。**副标题字特别小就是踩了这个坑。**

折行规则：按栏宽自动折，中文逐字断、英文退到空格，**最多 4 行**，超出加省略号。标题栏不是放正文的地方，主标题控制在 20 字内、副标题 25 字内。

### 3.3 C 档：自动底板 + 自己画右侧栏（B 档不够用时的精修）

B 档的标题栏是通用样式（字号按画布高度推、颜色固定）。想要风格化的侧栏（配色、层级、图标、数据卡），就让 `fit_frame` 出**不带标题**的底板，然后在返回的横版帧上自己画：

```python
frame = CANVAS.fit_frame(base.convert("RGB"), title="")   # 只要底板，不画标题
x, y, w, h = CANVAS.panel()                                # 右侧可用区 (683,64,1122,908)
d = ImageDraw.Draw(frame)
# 按风格自己的配色 / 字号 / 层级在 (x, y, w, h) 里排版
```

`panel()` 在 relayout 模式下返回右侧矩形，竖版系返回整幅画布。**这是推荐的横版精修路径**：改动集中在"多画一个侧栏"，不用碰原有 9 个场景的坐标，成本约 20–40 行。

### 3.4 D 档：全量横版重排（只在用户硬要时做）

真正的横版信息架构（左主画面 + 右三张证据卡横排之类）。**成本约 60–80 处坐标改动，等于重做一版渲染器**，做之前一定跟用户确认值不值。

步骤：

1. 渲染器顶部 `W, H = 1080, 1920` → `W, H = 1920, 1080`
2. `canvas.json` 加 `"mode": "design"`——让 `fit_frame` 直通。帧尺寸已经等于目标画幅时本来就会直通（`fit_frame` 第二道判断），但写明意图更保险，也免得下次改尺寸又绕回去
3. `GUARD = OverlapGuard(W, H, ...)` 的四个 safe 值换成 `CANVAS.safe_px()` 的横版值（§4）
4. 9 个场景的 Y 序列、卡片尺寸、字号**整体重排**：原来按 1920 高推的字号，画布高只剩 1080，不重推会字大到糊
5. 重跑 `--preview`，**重叠检测报告必须全绿**——横版重排最容易让文字撞车

**做完 D 档，这个工程就只能出横版了**（设计画布已经改成横版）。要同时留竖版就另建一份工程，别在同一份里来回切。

## 4. 安全区（重排时按这个留白）

平台 UI 会遮的位置不放字。`CANVAS.safe_px()` 返回像素值：

| 画幅 | top | bottom | left | right | 备注 |
|---|---|---|---|---|---|
| 9:16 | 192 | 422 | 84 | 150 | 底部 22% 是评论/点赞栏，右侧 15% 是头像栏 |
| 2:3 | 129 | 259 | 84 | 84 | 小红书封面上下留白更大 |
| 4:5 | 94 | 189 | 84 | 84 | Instagram |
| 1:1 | 64 | 129 | 75 | 75 | 朋友圈 |
| 16:9 | 64 | 108 | 115 | 115 | B站进度条 / YouTube 相关视频栏 |
| 4:3 | 64 | 108 | 86 | 86 | 展板 / 课件，实际约束最松 |

竖版（`fit`）的安全区**只在设计画布 1080×1920 上生效**——渲染器已经按它排版了，缩放是整体的，不用重算。横版自己加内容时才需要查这张表。

## 5. 验收清单（换画幅后必须过一遍）

```bash
cd "<选题>/MG样片-<风格名>"
python3 build_mg_*.py --preview
```

1. **关键帧尺寸对**：`帧*.png` 的宽高必须等于画幅表里的输出尺寸。
   ```bash
   python3 -c "from PIL import Image; print(Image.open('帧D-04-3.1s.png').size)"
   ```
2. **检查图不变形**：缩略图按目标宽高比重算过（16:9 是 240×135，不是 240×427）。格子被压扁说明 `CANVAS.thumb()` 没接上。
3. **重叠检测报告全绿**：横版加了标题栏之后，右侧栏文字也要进检测——C/D 档自绘的文字**必须调 `mark_text_layer`**，否则报告测不到。
4. **成片尺寸对**：`ffprobe` 看 `width×height`。帧尺寸和 `-s` 不一致时 ffmpeg 会**拉伸而不是报错**，这是最阴的坑。
   ```bash
   ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 MG-样片*.mp4
   ```
5. **9:16 零回归自查**（改过 mgkit 之后）：同一份内容出 9:16，帧应该和改之前逐像素一致。

## 6. 常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 改 canvas.json 没反应 | 老工程的 mgkit 是过期副本 | §1.3 跑升级工具 |
| 横版画面被拉伸变形 | 帧还是 1080×1920，但 `-s` 已是 1920×1080 | 渲染器 `render_frame` 出口没接 `CANVAS.fit_frame`；重跑升级工具 |
| 右侧标题字号小得像没渲染 | `title_role`/`subtitle_role` 写了不存在的角色名 | 只能填 `fonts.py` 的六个角色（§3.2） |
| 标题栏没出现，画面居中 | 标题三个来源都没给 | 检查 canvas.json 的 `title`，或 `MG_TITLE` 环境变量 |
| 竖版换过去字太小 | `fit` 整体缩放，4:5 缩到 0.703x | 砍文案 / 放大字号；或换 9:16、2:3 这种缩得少的 |
| 补边和画面边缘有色差带 | 背景是渐变，四角取中位数取不准 | `mode` 改 `relayout`（§2.2） |
| 检查图格子压扁 | `cw, ch` 还是硬编码像素 | 改成 `CANVAS.thumb(w, h)` |
| D 档重排后重叠报告全是红 | 横版栏位比竖版窄，字撞车 | 收窄卡片 / 减字号 / 拆场景，别硬塞 |
| 同一份工程切画幅后版式怪 | 已经走过 D 档改了设计画布 | D 档是一次性决策，要双版本就建两份工程 |
