# 配音方案（V1 / V2 手册）

**给谁看**：SKILL.md 里第 3 步选完 V1 或 V2 之后，Agent 按这份文档一步步带用户跑；选 S 静音不用看这份。

**核心原则**：
- **不装任何付费 API**——所有方案都本地跑，`say` / `espeak-ng` / `System.Speech` / GPT-SoVITS / CosyVoice2 / F5-TTS 全开源
- **能不加依赖就不加**——V1 零依赖，只有 V2 才需要装 Python + 模型
- **门槛不达标就回头改 V1**——不要硬装模型跑到一半崩了

---

## 0. 三方案对照（先决定走哪条）

| 代号 | 一句话 | 装什么 | 用户给什么 | 门槛 | 效果预期 |
|---|---|---|---|---|---|
| S | 静音 | 无 | 无 | 无 | 无声，观众自行脑补 |
| V1 | 系统电子音 | 无 | 一份口播稿 | 无 | 机器味重但清晰，能听懂 |
| V2 | 本地模型克隆 | Python 3.10 + 模型权重 | 5–10s 参考音频 + 口播稿 | 见 §3.1 | 接近真人，可**听得出是用户自己的音色** |

**决策建议**：
- 只想看流程能不能跑通 → V1，5 分钟出结果
- 用户明确说"想用我自己的声音" / "想要接近真人的效果" → V2
- 用户电脑跑不动 V2 但想试 → 老实告诉他回 V1，别硬撑

## 1. 口播稿规范（V1 / V2 通用）

**位置**：`<选题>/口播稿.md`

**格式**：一段一行，9 段对应 9 个场景。段与段之间空一行。Markdown 装饰（`#`、`**`、`-`）在合成前会被剥掉，但**尽量写纯文本**、别混表格。

**字数上限**：中文按 5 字/秒估，24–25 秒视频 → **≤ 125 字**。超了先砍文案，别指望 `say -r` 加速——加速后机器味会顶上来，V2 会听感失真。

**示例**（虚构产品）：

```
Workspace 2.0 上线了，这次直接给了免费额度。

打开官网首页就能看到公告横幅，往下滑有快速开始。

三种同步方式，都能离线跑。

配置只要三步：填地址、贴 Token、点连接。

多人协作这次跟进了，附件也能版本回溯。

试用额度：个人版每月 100 GB，团队版另算。

需要注意：免费版不能导出 API 报表。

对比同赛道，价格是三家里最低。

具体链接放评论区，用不上的可以先收藏。
```

**数字、单位、专有名词**：全部用中文写法（"百分之三十" 而不是 "30%"；"GPT-4" 可以说 "GPT 四"）。V1 对英文/符号识别差，V2 好一些但仍不完美。

## 2. V1：系统电子音（零依赖）

### 2.1 macOS

**默认音色**（`say -v '?' | grep -i zh` 查全部）：

| Voice | 语言 | 特点 |
|---|---|---|
| `Tingting` | 普通话女 | 系统默认，最稳 |
| `Mei-Jia` | 国语女（繁） | 稍软 |
| `Sin-ji` | 粤语女 | 港式 |

**一行合成**（推荐语速 200 wpm 左右，中文念得比默认慢一点更像人）：

```bash
cd "<选题>"
say -v Tingting -r 200 -f 口播稿.md -o /tmp/口播全轨.aiff
ffmpeg -y -i /tmp/口播全轨.aiff -c:a aac -b:a 160k -ar 48000 口播全轨.m4a
```

没有 `ffmpeg` 时先 `brew install ffmpeg`（一次装终身用）。

### 2.2 Linux

**首选 espeak-ng**（包管理器就能装）：

```bash
sudo apt install espeak-ng ffmpeg
cd "<选题>"
espeak-ng -v zh -s 175 -w /tmp/口播全轨.wav -f 口播稿.md
ffmpeg -y -i /tmp/口播全轨.wav -c:a aac -b:a 160k -ar 48000 口播全轨.m4a
```

`-s 175` 是 wpm，中文默认 175 稍快，可以试 160–190。

**质量更好**：`pico2wave`（Google 早期方案，需 `sudo apt install libttspico-utils`），或 `festival`——但都比 V2 差一个档次，别抱太高期待。

### 2.3 Windows

**PowerShell 一行**（用系统自带的 `System.Speech`）：

```powershell
cd "<选题路径>"
$ErrorActionPreference = "Stop"
Add-Type -AssemblyName System.Speech
$synth = New-Object System.Speech.Synthesis.SpeechSynthesizer
$synth.Rate = 0                       # -10 到 10，0 = 正常
$fmt = New-Object System.Speech.Synthesis.SpeechAudioFormatInfo(48000, [System.Speech.Synthesis.AudioBitsPerSample]::Sixteen, [System.Speech.Synthesis.AudioChannel]::Stereo)
$synth.SetOutputToWaveFile("$PWD\口播全轨.wav", $fmt)
$synth.Speak((Get-Content -Raw .\口播稿.md))
$synth.Dispose()
ffmpeg -y -i .\口播全轨.wav -c:a aac -b:a 160k -ar 48000 .\口播全轨.m4a
```

中文音色：`$synth.GetInstalledVoices() | ? { $_.Enabled -and $_.VoiceInfo.Culture.Name -like 'zh*' } | % { $_.VoiceInfo.Name }` 查有没有 `Microsoft Huihui` / `Kangkang`，有就 `$synth.SelectVoice("Microsoft Huihui Desktop")`。

### 2.4 V1 常见问题

| 症状 | 原因 | 解法 |
|---|---|---|
| 出来的 wav 是空的 | 口播稿文件编码不是 UTF-8 | `file 口播稿.md` 查，转 UTF-8 无 BOM |
| 语速太快听不清 | 默认 wpm 高 | macOS `say -r 180`；Linux `espeak-ng -s 150`；Win `$synth.Rate = -2` |
| 数字念错 | TTS 对 `2.0` / `3%` / `100GB` 处理各异 | 全部改成中文写法（"二点零" / "百分之三" / "一百 G"） |
| 断句很怪 | Markdown 段落间空行没被识别 | 手动在段间加两个换行符 |

## 3. V2：本地模型克隆音色

### 3.1 硬件门槛自查（三条命令）

**先跑这三条，再决定要不要装**——不达标就回头改 V1，不要硬装跑到一半崩。

```bash
# CPU / 架构
uname -m && (sysctl -n machdep.cpu.brand_string 2>/dev/null || grep 'model name' /proc/cpuinfo | head -1)

# 内存（GB）
echo $(( ($(sysctl -n hw.memsize 2>/dev/null || awk '/MemTotal/ {print $2*1024}' /proc/meminfo)) / 1073741824 ))

# 显卡（有独显 / Apple Silicon 才算达标）
(system_profiler SPDisplaysDataType 2>/dev/null | grep -E 'Chipset|Vendor' | head -4) || (nvidia-smi --query-gpu=name,memory.total --format=csv 2>/dev/null)
```

**通过线**：

| 平台 | CPU | 内存 | GPU |
|---|---|---|---|
| Apple Silicon（M1 及以上） | ✅ 都算通过 | ≥ 8 GB | 内置 MPS 即可 |
| Intel Mac | 8 代起 | ≥ 16 GB | 需要独显或干脆放弃 V2 |
| Linux | 任意 | ≥ 16 GB | NVIDIA ≥ 6 GB VRAM |
| Windows | 任意 | ≥ 16 GB | NVIDIA ≥ 6 GB VRAM |

**不达标怎么办**：老实告诉用户"这台机器跑 V2 会很慢或跑不动，建议改选 V1，效果差一档但能出"。别偷偷装。

### 3.2 候选模型（都开源、都免费、都支持中文）

| 模型 | 参数量 | 首次权重下载 | 中文效果 | 克隆方式 | 推荐度 |
|---|---|---|---|---|---|
| **GPT-SoVITS v2** | ~100M | ~2 GB | ⭐⭐⭐⭐⭐ 原生最好 | 5–10 秒参考音频，**zero-shot** | **默认推荐** |
| CosyVoice2-0.5B | 0.5B | ~4 GB | ⭐⭐⭐⭐⭐ | 3–10 秒参考音频 | 更好但对硬件更挑 |
| F5-TTS | 336M | ~1.2 GB | ⭐⭐⭐⭐ | 参考音频 + 参考文本 | 权重小、跑得快、英文也强 |

**为什么默认推 GPT-SoVITS**：
1. 官方带 **WebUI**（`webui.py`）——用户点两下就能出结果，不用写脚本
2. 有整合包（Windows 一键解压即用），Mac 装依赖也简单
3. 中文社区教程最多，出问题好搜
4. 参考音频**不需要单独微调训练**，5 秒就能出效果，用户体感最好

### 3.3 GPT-SoVITS 安装（引导用户装，Agent 不代跑）

**注意**：这一步**必须让用户自己在终端跑**（时间 5–15 分钟，取决于网速）。Agent 负责告诉他命令、检查产物、下一步做什么；**不要**在 Agent 会话里直接执行 `install.sh`——一旦中断很难恢复。

**前置**：装好 Python 3.9–3.10（推荐 `miniforge3`，跨平台）+ ffmpeg。

**macOS / Linux**：

```bash
git clone https://github.com/RVC-Boss/GPT-SoVITS.git
cd GPT-SoVITS
conda create -n GPTSoVits python=3.10 -y
conda activate GPTSoVits
bash install.sh --device <CU126|CU128|ROCM|MPS> --source <HF|HF-Mirror|ModelScope> [--download-uvr5]
```

- Mac（Apple Silicon）用 `--device MPS`
- NVIDIA 用 `--device CU126`（CUDA 12.6）或 `CU128`
- AMD 用 `--device ROCM`
- `--source` 国内选 `HF-Mirror` 或 `ModelScope` 快

**Windows**：**用官方整合包**（解压即用，不用装依赖）—— https://github.com/RVC-Boss/GPT-SoVITS 首页 README 有网盘链接，找 `GPT-SoVITS-v2pro-<日期>-<CUDA版本>.7z`。

**装完跑一次自检**（在 GPT-SoVITS 目录下）：

```bash
conda activate GPTSoVits
python -c "import torch, GPT_SoVITS.config as c; print('torch:', torch.__version__, 'mps:', torch.backends.mps.is_available(), 'cuda:', torch.cuda.is_available())"
```

三个字段里至少一个 True 才算装好。全是 False → 硬件门槛没过，回头改 V1。

### 3.4 参考音频规范（决定克隆像不像本人）

**位置**：`<选题>/素材-参考音频/reference.wav`

| 项 | 要求 | 为什么 |
|---|---|---|
| 时长 | **5–10 秒**（< 3s 或 > 15s 都会掉效果） | 太短音色学不像，太长模型会截 |
| 采样率 | 44.1 kHz 或 48 kHz | 低于 22.05 kHz 会被拉伸糊掉 |
| 声道 | 单声道 / 立体声都行，模型会转 | — |
| 内容 | 用户随便念一段话（例："这是一段用于音色克隆的参考音频，一二三四五六七八"） | 内容不重要，**音色、语速、语气**才重要 |
| 环境 | **安静、无 BGM、无回声、无他人声** | 有 BGM 会被模型当成用户音色一起学 |
| 语言 | 和口播稿同语言最好 | 中文口播 + 英文参考 → 效果打折 |

**录**：iPhone 语音备忘录 / Mac QuickTime 都行；导出 m4a 后转一下：

```bash
ffmpeg -i 用户录音.m4a -ac 1 -ar 44100 -y "<选题>/素材-参考音频/reference.wav"
```

### 3.5 使用（WebUI 手动 or API 自动）

**方式 A：WebUI 手动，最直观**

```bash
cd GPT-SoVITS && conda activate GPTSoVits && python webui.py
```

浏览器会自动打开 `http://127.0.0.1:9874`：

1. 顶部切到 **1-GPT-SoVITS-TTS** → **1C-推理**
2. 勾选 `开启TTS推理WebUI` → 会另开一个 `http://127.0.0.1:9872`
3. 在推理页：
   - **参考音频**：上传 `reference.wav`
   - **参考音频文本**：手打用户上传时念的那句（很重要，模型靠它对齐鲁语）
   - **待合成文本**：粘贴 `<选题>/口播稿.md` 全文
   - **语种**：中文
4. 点"合成" → 页面出结果 → 右键保存为 wav → 挪到 `<选题>/口播全轨.wav`

**方式 B：API 自动（Agent 可以带跑）**

```bash
# 起 API 服务（另开终端）
cd GPT-SoVITS && conda activate GPTSoVits && python api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml
```

```bash
# Agent 帮用户合成一条
cd "<选题>"
python3 "<Skill>/模板/工具-GPTSoVITS合成.py" \
  --text-file 口播稿.md \
  --ref-audio 素材-参考音频/reference.wav \
  --ref-text "这是用户参考音频里念的那句话" \
  --out 口播全轨.wav
```

（`工具-GPTSoVITS合成.py` 是把 curl 包了一层，处理 UTF-8 / 分段 / 重试；本仓库当前**尚未**内置，第一次跑请走方式 A 的 WebUI。）

**统一转 m4a**（两种方式都要）：

```bash
ffmpeg -y -i 口播全轨.wav -c:a aac -b:a 160k -ar 48000 口播全轨.m4a
```

然后回到 SKILL.md Step 7.3 混流。

### 3.6 V2 常见问题

| 症状 | 原因 | 解法 |
|---|---|---|
| 合成 3 秒后报错 `MPS backend not available` | Mac 装了 CUDA 版依赖 | 重装时用 `--device MPS` |
| 出来的声音不像用户 | 参考音频有 BGM / 太短 / 语速太快 | 让用户重录一段 5–10 秒安静朗读 |
| 断句很怪 | 口播稿没标点 | 每段末尾加句号，逗号处保留逗号 |
| 首字被吞 | 参考音频末尾留白 > 1s | ffmpeg 裁掉尾部静音：`silenceremove=stop_periods=-1:stop_threshold=-50dB` |
| 长文本合成时间 > 5 分钟 | 一次性喂整段（>200 字） | 按 9 段分别合成，再 concat（见 §4） |

## 4. 分段合成 + concat（长口播 / 逐场景对齐用）

**什么时候用**：想严格按 9 个场景的时间点各配一段音（比如钩子必须 0–3s 结束）。默认不做，只在整个口播一次合成搞不定时才拆。

**流程**：

1. 把 `口播稿.md` 按段拆成 `seg01.txt ... seg09.txt`
2. 每段各自 TTS 出 `seg01.wav ... seg09.wav`（V1 / V2 都可以）
3. 用 ffmpeg concat 拼成整轨，段间留白对齐场景时长（例：每段前加 0.15s 静音）：

   ```bash
   cd "<选题>/配音/"
   for i in 01 02 03 04 05 06 07 08 09; do
     ffmpeg -y -f lavfi -t 0.15 -i anullsrc -i seg$i.wav -filter_complex "[0][1]concat=n=2:v=0:a=1" pad_$i.wav
   done
   ls pad_*.wav | sed "s/^/file '/;s/$/'/" > list.txt
   ffmpeg -y -f concat -safe 0 -i list.txt -c copy 口播全轨.wav
   ```

**对齐口径**：SKILL.md 场景时长默认 24-25s / 9 = 每段约 2.7s；如果口播稿某段超 2.7s，说明文案要砍。

## 5. ffmpeg 混流（V1 / V2 通用）

**核心命令**（在 SKILL.md Step 7.3 已经写过，这里给完整解释）：

```bash
cd "<选题>/MG样片-<风格名>"
VIDEO_DUR=$(ffprobe -v error -show_entries format=duration -of csv=p=0 MG-样片*.mp4)
ffmpeg -y \
  -i MG-样片*.mp4 \
  -i ../../口播全轨.m4a \
  -map 0:v -map 1:a \
  -c:v copy \
  -c:a aac -b:a 160k -ar 48000 \
  -t "$VIDEO_DUR" \
  -movflags +faststart \
  MG-样片-有声.mp4
```

**参数逐条解释**：

| 参数 | 作用 | 为什么这么写 |
|---|---|---|
| `-c:v copy` | **不重编码视频**，直接 container 层搬运 | 几秒钟完成、画质零损失 |
| `-map 0:v -map 1:a` | 视频取 input 0，音频取 input 1 | 明确映射，防止误合并多流 |
| `-ar 48000` | 统一 48 kHz | `say` 出来 22050、GPT-SoVITS 是 32k，视频平台按 48k 收 |
| `-t "$VIDEO_DUR"` | **以视频长度为准**截输出 | 见下面这段 |
| `-movflags +faststart` | moov box 前置 | 微信视频号 / 抖音上传更快 |

**为什么不用 `-shortest`**：`-shortest` 的语义是"最短流结束就停"——口播 20s、视频 25s 时它会把**视频**截到 20s，最后一段画面消失。这是最常见的翻车点。用 `-t "$VIDEO_DUR"` 让**视频始终是主角**：
- 音频比视频短 → 尾部自然静音补齐，画面完整
- 音频比视频长 → 音频截到视频长度，超出部分丢弃（**这时候应该回头砍稿，不是让成片缺尾**）

**音量归一**（可选，让口播不会忽大忽小）：

```bash
ffmpeg -y -i 口播全轨.m4a -af loudnorm=I=-16:TP=-1.5:LRA=11 口播全轨-归一.m4a
```

`-16 LUFS` 是短视频平台推荐响度（B站/抖音/视频号大致都是这个口径）。

## 6. 交付前自检清单

- [ ] `ffprobe -v error -show_streams -select_streams a MG-样片-有声.mp4 | head -20` 能看到 AAC 流、48000 Hz、有 duration
- [ ] 播放器从头看到尾：**最后 3 秒视频不能被截**（若被截，说明口播超长）
- [ ] **前 3 秒有口播**——不能画面在动、声音 3 秒后才起
- [ ] 音量：用手机外放正常距离听，**能听清**、不破音（V1 电子音有时会破）
- [ ] V2 时确认参考音频不进成片（只学音色，不进交付物）
- [ ] 静音版（`MG-样片*.mp4`）**同时交付**——用户后续想改稿重混，直接用无声底片重跑 §5，不用重渲染画面（省 5-10 分钟）

## 7. 什么时候明确回绝 V2

以下情况 Agent **直接告诉用户不适合跑 V2**，走 V1 或 S：

- Intel Mac（无独显 / 独显是 AMD 老款）——MPS 不可用，CPU 跑一次 25 秒合成要 15+ 分钟
- 内存 < 8 GB
- 用户明确说"参考音频我不方便录"（如共用办公电脑、环境噪音大）
- 用户在赶时间——V2 首次装环境 + 权重下载至少 20 分钟起步

**不要为了显得 skill 强大硬推 V2**。用户跑不完更挫败。
