# 免费 AI 工具短视频｜内容编排方法论

> 适用范围：抖音 / 视频号等国内主流短视频平台，AI 工具教程类内容。  
> 定位：面向想用 AI 工具省钱、想白嫖能力的普通用户，不面向纯开发者。  
> 核心目标：**完播率优先**，一条片子只解决一个问题。

---

## 一、编排方法论本身（内容结构）

### 1.1 四段式骨架（可复用模板）

短视频的流失是分段发生的，不是"整条太长"造成的。按观看时间切四段，每段的病因和药方不同：

| 段落 | 时间 | 唯一任务 | 典型死法 | 正确做法 |
|---|---|---|---|---|
| 钩子区 | 0–3s | 让用户停下来 | 自我介绍、铺垫、报菜名、固定片头 | 第一句直接给结论 / 反常识 / 冲突画面 |
| 兑现区 | 3–8s | 兑现钩子的承诺 | 钩子开了空头支票，正题拖到中段 | 钩子承诺什么，第 4 秒就给什么 |
| 正文区 | 8–45s | 交付可复制的方法 | 一个点讲太久、画面静止、语速慢 | 一个信息点 2–3 秒讲完，每 10–15 秒给个小爽点 |
| 收尾区 | 45s+ | 给出看到最后的理由 | 信息讲完还在拖、硬凑时长 | 说完就收，或给一句金句 / 反转 / 下一条钩子 |

### 1.2 开场钩子的四种写法（挑一种，别混用）

按"停留成本"从低到高排列：

1. **结论前置**：`Agnes 的文本模型，现在是真 0 块。` —— 直接给结论，最稳。
2. **数字对比**：`同一个活儿，我花 0 块和花 200 块，差距在这儿。` —— 用数字制造落差。
3. **反常识**：`免费工具的坑，比付费的还多。` —— 制造认知冲突。
4. **悬念缺口**：`这个免费 API，能白嫖到视频生成。` —— 留信息缺口。

### 1.3 黄金 3 秒公式

> **3 秒冲突 + 5 秒提问 + 10 秒福利**

- **3 秒冲突**：一句话制造落差（"90% 的人找免费工具都找错了"）。
- **5 秒提问**：把观众变成解题人（"你知道哪些 AI 接口是真免费？"）。
- **10 秒福利**：立刻兑现（"5 步就能用上，全免费"）。

### 1.4 字数与节奏的硬约束

- **语速**：每秒 3–4 字。
- **单条时长**：15–30 秒讲 1 个重点，只聚焦最核心那一个优势。
- **总字数**：80–120 字（15–30 秒段）；60 秒长条控制在 300 字以内。
- **一个信息点 2–3 秒**讲完；超过 5 秒还在说同一件事就该剪。

### 1.5 信息密度：单屏承载上限

- 一屏一个信息点，超过 8 个字就拆成两屏。
- 同一时刻**最多两个元素**在争夺注意力（标题 + 标注，或标题 + 字幕），第三个必须让位。
- 字幕 1–2 行，每行约 32–42 字。

### 1.6 结尾互动（最后 5 秒闭环）

- 用提问 / 引导关注收尾，**明确互动引导能把点赞、收藏率提升约 35%**。
- 模板：`你最想白嫖哪个 AI？评论区告诉我，我下期测。`
- 反例：`谢谢观看，记得点赞关注。` —— 无信息量、无互动诱因。

## 二、画面编排

### 2.1 竖屏安全区（1080×1920）

平台 UI 会遮住画面，必须把内容放在**保护区**内：

| 区域 | 占比 | 处理 |
|---|---|---|
| 顶部 UI（标签、搜索） | 约 8–10% | **不放文字** |
| 右侧按钮列（点赞/评论/分享） | 约 15% 宽 | **不放文字** |
| 底部 UI（用户名、描述） | 约 20–25% | **不放正文** |
| 中部安全框 | 剩余 | 标题、字幕、CTA 都放这里 |

**最常见的错误**：剪映默认字幕位置正好落在底部 UI 上（用户名和描述压住字幕），必须把字幕上移到保护区的下三分之一。

### 2.2 文字层级表（1080×1920 基准）

| 角色 | 最多字数 | 字号 | 位置 | 停留 |
|---|---|---|---|---|
| 钩子标题 | 3–6 字 | 90–120px 粗体 | 上三分之一，居中 | 1.5–3s |
| 段落标题 | 2–5 字 | 70–90px 粗体 | 上三分之一或居中 | 1–2s |
| 辅助标注 | 3–8 字 | 45–60px 常规 | 贴着它解释的东西 | 2–4s |
| 下三分之一字幕 | 1–2 行 | 50–65px 中粗 | 底部 UI 之上 | 跟语音同步 |
| CTA | 2–5 字 | 60–80px 粗体 | 居中或上三分之一 | 2–3s |

关键原则：
- **用字号和字重做层级，不要用颜色做层级**。颜色只用来强调 1–2 个词。
- 如果标题和辅助文字一样大，那就没有标题。
- 全屏文字块要避免；一屏超过约 8 个字就拆屏。

### 2.3 主体形式的选择

| 形式 | 适合 | 不适合 |
|---|---|---|
| 纯 MG 动画 | 讲机制、讲步骤、讲"为什么免费" | 需要可信度的操作演示 |
| 录屏 + 标注 | 教怎么点、怎么填参数 | 讲抽象机制 |
| 截图卡片式 | 给结论、给价格、给对比 | 连续讲多个步骤 |

**混合原则**：MG 负责"结构和结论"，截图/录屏负责"证据和操作"。截图永远只做**高亮框选 / 箭头标注**，不改动原图内容（价格、模型名必须原样）。

### 2.4 节奏控制

- 每 2–3 秒必须有一次视觉变化（换元素、切分屏、位移）。
- 留白是有代价的：画面完全静止超过 5 秒就是流失点。
- 关键数据用**大数字** + 单色强调，配合下划线 / 进度条做计数感。

### 2.5 随机帧可读性测试（发布前必做）

导出后在手机上、50% 亮度下，随机暂停 5 帧。
**只要有一帧需要眯眼看，就必须返工**改字号、对比度或位置——不要去改动画。

## 三、颜色搭配

### 3.1 账号色卡（固定一套，不逐条换）

AI 工具教程类内容在深色底上信息密度更高、也更贴"开发者工具"的气质。推荐这套**深色科技风**：

| 角色 | 色值 | 用途 |
|---|---|---|
| 背景底色 | `#0A0E14` | 全片统一背景 |
| 卡片面 | `#141A24` | 卡片、面板底 |
| 描边 | `#232B39` | 卡片边框、分隔线 |
| 主强调 | `#00E5A0`（荧光绿） | 数字、免费标记、CTA、关键词 |
| 次强调 | `#3B82F6`（蓝） | 链接、URL、第二层级标注 |
| 警示 | `#FF7A45`（橙） | 价格、限制、"但不是永久免费" |
| 正文 | `#E8ECF2` | 主文本 |
| 次要文本 | `#8A93A3` | 说明、免责 |

**纪律**：一屏最多一个强调色。绿和蓝不能同屏抢焦点，橙只出现在"需要提醒"的地方。

### 3.2 配色禁忌

| 不要做 | 为什么坏 | 改成 |
|---|---|---|
| 纯白底 + 纯黑字 | 手机户外强光下完全糊掉 | 深色底 + 高亮文字 |
| 一屏 3 个以上强调色 | 焦点丢失，等于没有强调 | 留 1 个强调色，其余降为灰阶 |
| 荧光色大面积铺底 | 刺眼、易疲劳，且让文字失去对比 | 荧光只用于小面积元素 |
| 截图原样贴上去不处理 | 原图配色与成片冲突，割裂 | 统一裁切 + 描边 + 高亮框 |
| 渐变滥用 | 廉价感、信息层级被冲淡 | 渐变只在背景层做一次 |

### 3.3 对比度底线

- 正文与背景对比度 ≥ 4.5:1（WCAG AA）。
- 文字压在不熟悉的截图上时，加描边或半透明底板。
- **所有视觉决策最后在手机上、50% 亮度下判断，不在电脑显示器上判断。**

## 四、动画制作

### 4.1 动画的第一原则：服务于阅读

> **readability beats decoration** —— 如果某个字体、动画或颜色让文字更难读，就去掉，不管它在预览里多好看。

### 4.2 入场/出场动画参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| 入场时长 | 5–10 帧（约 0.17–0.33s） | 长了会推迟文字变得可读的时刻 |
| 出场时长 | 5–8 帧 | 比入场稍快，收得更干脆 |
| 缓动 | ease-out 为主 | 自然加速减速，不要线性 |
| 位移距离 | 16–30px | 小幅上移即可，不要飞入 |
| 缩放 | 0.96 → 1.0 | 轻微，不要弹跳 |

### 4.3 分组错峰（Stagger）

一组元素**不要同时出现**。每个元素延后 2–4 帧依次入场，观众的眼睛会被"牵着走"，这是 MG 动画最省力的节奏感来源。

错峰量级参考：同组 3–5 个元素，每个延后 0.08–0.15 秒。

### 4.4 文字入场时机

- 标题在它概括的那句**重读音节**上出现，或提前 2–4 帧。
- 早出现 = 剧透台词；晚出现 = 看起来像失误。
- 一屏文字停留时间要够读两遍：约 0.3–0.4 秒/字，且**不少于 1 秒**。

### 4.5 动画禁忌

| 不要做 | 为什么坏 |
|---|---|
| 逐字蹦出（逐字 reveal） | 关键信息被拖慢，破坏可读性 |
| 文字持续晃动 / 弹跳 | 干扰阅读 |
| 动画比文字更长 | 画面在"演"，信息没在"传" |
| 元素同时全部出现 | 无视觉引导，观众不知道先看哪 |
| 用花哨转场掩盖内容单薄 | 转场是锦上添花，不是内容 |

### 4.6 音效与转场

- 转场加"叮"的一声，画面切换更自然。
- 关键知识点给一个轻快背景音乐，抓注意力。
- 音效是辅助，不喧宾夺主。

## 五、快速执行流程（一次成片）

```
1. 定一个点        → 只选 1 个重点，15–30s
2. 写钩子          → 4 种写法挑 1 种，写进第一句
3. 拆四段          → 钩子 / 兑现 / 正文 / 收尾，标好每段秒数
4. 配画面          → 每段指定：MG 元素 or 截图 or 录屏
5. 截图处理        → 裁切 + 高亮框 + 描边，原图内容不改
6. 渲染            → 统一色卡 + 字号层级表 + 5-10 帧入场
7. 手机自测        → 50% 亮度随机帧测试
8. 配音 + 合成     → 先出音频再定时间轴，画面按段内相对位置挂载
9. 发布前核对      → 价格、口径、API Key 不外露
```

## 六、发布前检查清单

- [ ] 前 3 秒是结论/冲突/悬念，没有自我介绍和片头
- [ ] 钩子承诺在第 4 秒内兑现
- [ ] 一个信息点不超过 3 秒
- [ ] 文字全在竖屏安全区内，字幕没被底部 UI 压住
- [ ] 一屏最多一个强调色
- [ ] 文字在手机 50% 亮度下能一眼读清
- [ ] 元素错峰入场，没有全部同时出现
- [ ] 入场动画 5–10 帧，不逐字蹦出
- [ ] 结尾给了互动诱因，不是"谢谢观看"
- [ ] 截图里的价格、模型名与官网一致
- [ ] API Key、账户信息未出现在画面里
