# AI 免费视频创作流水线

面向「程序员晚枫」这类**国内主流短视频平台**的 AI 工具账号，产出**竖屏静音 MG 样片**。

> 本 Skill 位于 `wanfeng-skills/skills/ai-free-video/`。下文用 `<Skill>` 指代这个目录，用 `<选题>` 指代你正在做的那一条选题工程目录。

## 定位与口吻

- **账号人设**：程序员晚枫。结尾固定话术「科技不高冷，AI 很好用，我是晚枫。」
- **内容内核**：白嫖——免费、真能白嫖、有条件白嫖。
- **受众**：想用 AI 工具省钱、想白嫖能力的普通用户，不只是开发者。
- **交付边界**：本 Skill 当前只做到**静音样片**。配音、字幕烧录、时间轴对齐不在本次范围内。

## 四阶段流程（必须按序执行，每阶段停下来等用户）

```
阶段 1  采集证据  →  保存本地截图 + 裁成证据图  →  交付用户确认事实
阶段 2  选风格    →  给出 8 种风格说明与差异  →  用户选定
阶段 3  做样片    →  渲染静音 MP4 + 检查图       →  交付用户
阶段 4  收反馈    →  用户提修改意见             →  回到阶段 3 迭代
```

**不要跳过阶段 2。** 风格选择必须由用户拍板，不要自作主张定风格。

## 快速开始

```bash
# 1. 建选题工程（自动复制对应风格渲染器 + mgkit + 方法论 + 资料模板）
#    选题目录默认建在当前工作目录下，可用 MG_TOPIC_ROOT 指定别的根目录
cd <你想放选题的目录>
bash "<Skill>/模板/新建选题.sh" "<选题名>" <风格代号>

# 2. 用 2x 像素密度截图，存进 <选题>/素材-官网截图-HD/
node "<Skill>/模板/工具-重截高清图.mjs" "<选题>/素材-官网截图-HD"

# 3. 裁成证据图（改 SPECS 后运行，必须在选题根目录下跑）
cd "<选题>" && python3 "<Skill>/模板/工具-切证据图.py"

# 4. 写场景（在渲染器的 build_scenes() 里改文案和截图框位）

# 5. 渲染
cd "<选题>/MG样片-<风格名>" && python3 build_mg_*.py --preview   # 检查图
cd "<选题>/MG样片-<风格名>" && python3 build_mg_*.py             # 成片
```

**渲染器自带路径解析**，不依赖任何固定路径：
- `mgkit` 位置：`MG_MGKIT_DIR` 环境变量 → 向上探测 → Skill 自带的 `模板/mgkit`
- 素材位置：`MG_EVID_DIR` / `MG_SHOTS_DIR` / `MG_SHOTS_HD_DIR` 环境变量 → 向上探测 → 当前工作目录
- 选题根目录：`MG_ROOT` 环境变量（给 patch 脚本和切图脚本用），不设则取当前目录

## 阶段 1：采集证据

### 1.1 打开网站截图

用内置浏览器（先加载 `TRAE-browseruse` skill）。参考实现见 `模板/工具-重截高清图.mjs`。

**关键：必须 2x 像素密度截图。**

```bash
# 用 Playwright + 本机 Chrome for Testing，避免再下载 chromium
const ctx = await browser.newContext({
  viewport: { width: 1396, height: 900 },
  deviceScaleFactor: 2,          // 关键：输出 2792 宽
  locale: 'zh-CN',
});
```

### 1.2 为什么必须是 2x

这是本项目踩过最贵的坑：

| 截图密度 | 宽度 | 裁切后放进 1080 宽视频 | 结果 |
|---|---|---|---|
| 1x | 1396 | 缩到 **0.65x** | 二次降采样，小字糊 |
| 2x | 2792 | 缩到 **0.78x** | 文字清楚 |

**缩放比低于 0.75x 就不要用这张图**——小字必然读不清。宁可把裁切框收窄。

### 1.3 裁成证据图

```bash
cd "<选题>" && python3 "<Skill>/模板/工具-切证据图.py"   # 改里面的 SPECS 后运行
```

每张证据图要：
- **裁切框收紧**：只装下关键证据行，不要整页塞进去
- **自动加高亮框**：框住关键数字（价格、¥0、模型名），半透明底 + 描边，不遮挡原字
- **出两个版本**：
  - `原版` —— 官网原始配色
  - `-亮` —— 适配亮色系 MG 的版本

**亮版生成逻辑**（不要用固定反相）：

```python
mean = ImageStat.Stat(im.convert("L")).mean[0]
if mean < 128:
    # 暗底（campaign 卡片）→ 反相成浅底，并把灰底压向暖白
else:
    # 亮底（定价页表格）→ 保持浅底，只做暖调
```

反相后必须把中间调压向暖白，否则灰底证据图和米白/奶油色画面割裂。

### 1.4 交付用户

给出版面清单：每条事实 → 对应证据图 → 一句话结论。

**必须标注证据边界**，例如：
- 「当前体验价 0 元」≠「永久免费」
- 「default 用户免费」≠「所有套餐免费」
- 官网首页 Hero 可能已更新，截图要现取

## 阶段 2：选风格

给用户看 8 种风格的差异（详见 `参考/风格库.md`），必须**给出对比表**而不是只列名字。

| 代号 | 风格 | 底色 | 字体 | 核心动效 | 气质 | 适合 |
|---|---|---|---|---|---|---|
| A | 深色科技 | `#0A0E14` | 腾讯 Sans 斜体 | 淡入淡出 | 冷静专业 | 硬核评测、API 教程 |
| B | 亮色杂志 | `#F7F5F0` | Hiragino W6 | 弹性回弹 | 亲切生活化 | 泛用户、工具推荐 |
| C | 复古拼贴 | 牛皮纸 | 宋体 | 盖章/打字机 | 手作有故事 | 系列化、封面片头 |
| D | 故障艺术 | 深空+噪点 | Hiragino+乱码 | 解码/色差/撕裂 | 锐利实验 | 封面吸睛、钩子 |
| E | 像素游戏 | 深蓝+抖动 | 自绘点阵 | 精灵/血条/金币雨 | 好玩想玩 | 泛用户、破圈 |
| F | 暖色治愈 | 奶油 | Hiragino W6 | 弹簧/挤压/柔光 | 温暖亲和 | 生活向、白嫖技巧 |
| G | 简笔画 | 纸白+点阵 | Hiragino W6 | 手绘线稿逐笔画出/boil 抖动 | 轻松、白板讲解 | 教程、原理拆解、泛用户 |
| H | 工笔画 | 绢本米黄 | 宋体标题+黑体小字 | 三矾九染叠色/落印/圈点/花瓣 | 雅致重彩、有记忆点 | 国潮调性、系列封面、差异化 |

**推荐组合**：D/E 做钩子 + A/B 做正文，既有陌生感又不伤专业度。
G/H 气质独特，更适合当**整片的统一风格**，不建议只拿来做一个钩子片段。

## 阶段 3：做样片

### 3.1 复制模板

```bash
cp -R "<Skill>/模板/风格库/<风格目录>" <新选题目录>/MG样片-<风格名>/
```

每个风格目录里是一个独立渲染器 `build_mg_*.py`。

### 3.2 接入工具链

新渲染器必须接上 mgkit（重叠检测 + 高清证据图）：

```bash
cd "<选题>"
python3 "<Skill>/模板/mgkit/patch_renderers.py"    # 打重叠检测补丁
python3 "<Skill>/模板/mgkit/patch_evidence.py"     # 切高清证据图
```

或在 `make_contact()` 末尾手动加一行：

```python
write_report(GUARD, HERE, "<风格代号> <风格名>")
```

### 3.3 写场景

按《内容编排方法论》四段式：

| 段 | 时间 | 唯一任务 | 画面 |
|---|---|---|---|
| 钩子 | 0–3s | 让人停下 | 结论前置 + 核心证据 |
| 兑现 | 3–8s | 兑现承诺 | 首页/入口证据 |
| 正文 | 8–45s | 交付方法 | 步骤 / 对比 / 价格拆解 |
| 收尾 | 45s+ | 给看到最后的理由 | 互动提问 + 固定话术 |

### 3.4 渲染

```bash
cd <选题目录>/MG样片-<风格名>/
python3 build_mg_*.py --preview   # 先出检查图，确认无误
python3 build_mg_*.py             # 出无声 MP4
```

**技术规格**（硬性）：
- 1080×1920 / 30fps / H.264 / yuv420p / `-movflags +faststart`
- 音频轨**不加**（当前阶段只做静音样片）
- 单条 15–30 秒讲一个重点

### 3.5 交付用户

给：MP4 链接 + 检查图链接 + 重叠检测报告结论。

## 阶段 4：收反馈

用户提意见后，回到阶段 3 迭代。常见修改方向：

| 反馈 | 改法 |
|---|---|
| 字看不清 | 证据图裁切框收窄，或加大显示尺寸到 ≥150px 高 |
| 画面太空 | 提高 YOFF，把内容重心压向下半屏 |
| 颜色刺眼 | 截图降亮度/降饱和，或换亮版证据图 |
| 想要更多动感 | 加错峰入场、弹性回弹、呼吸脉冲 |
| 觉得太正经/太轻浮 | 换风格代号（A/D ↔ F/E/G） |
| 想要辨识度、不想撞脸 | 换 C（复古拼贴）或 H（工笔重彩） |

## 硬性规则

### 绝不能出现

1. **文字重叠**——用 mgkit 检测，不要靠肉眼。报告必须全绿。
2. **越界**——底部 22%、右侧 15%、顶部 10% 不放字（平台 UI 会遮）。
3. **截图缩放比 < 0.75x**——小字看不清等于没放。
4. **改原图内容**——价格、模型名必须和官网一致，只允许裁切、标注、调明度。
5. **夸大免费口径**——「阶段性优惠」不说成「永久免费」；「Flash 免费」不说成「所有模型免费」。
6. **API Key / 账户信息出现在画面里**。

### 元素层级

- 用**字号和字重**做层级，颜色只强调 1–2 个词
- 一屏最多一个强调色
- 入场 5–10 帧、ease-out、位移 16–30px、缩放 0.96→1.0
- 同组元素错峰 0.08–0.15 秒依次入场
- 禁止逐字蹦出、文字持续晃动、用花哨转场掩盖内容单薄

### 竖屏安全区（1080×1920）

| 区域 | 占比 | 处理 |
|---|---|---|
| 顶部 UI | 8–10% | 不放文字 |
| 右侧按钮列 | 15% 宽 | 不放文字 |
| 底部 UI | 20–25% | 不放正文，字幕上移 |
| 中部安全框 | 剩余 | 标题、字幕、CTA |

## 常见踩坑（详见 `参考/踩坑清单.md`）

1. **补丁误删绘制语句**——自动改 `place()` 时，`base.alpha_composite(layer, (xx, yy))` 必须保留，检测登记只能追加不能替换。
2. **`lru_cache` 共享卡片对象**——卡片上要画字，就不能缓存整个卡片；只缓存不变的部分（如阴影层）。
3. **半透明填充在 RGB 图上无效**——`fill` 传 alpha 会被忽略，要用 RGBA 图 `alpha_composite`。
4. **证据图文件名带 `.png` 时拼接失败**——查找时要同时兼容带/不带后缀。
5. **场景淡出与入场交叉**——淡出 0.26s 和下一场入场 0.26s 会有 0.02s 重叠，文字重影。两段之间留 0.26s 空隙。
6. **`timeout` 命令在 zsh 不可用**——别在 zsh 里用 `timeout`。
7. **截图会过期**——官网 Hero、价格页会更新，每次选题重新截。
