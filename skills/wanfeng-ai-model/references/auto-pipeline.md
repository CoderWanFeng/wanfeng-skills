# 晚枫模特换装：全自动流水线（A1–A5）

> **一句话**：用户不用挑路线 —— 第一问只问「素材谁出」，之后按 5 项一步步确认，换装、卡点音乐、合成短片**全部自动跑完**，直接给一条能发的 mp4。
> 本路径**不打开网页、不手动拖拽**，全部用 WorkBuddy 内置生成能力 + 本地 ffmpeg 完成。
> 本流程只有这一条主路径，全程按 A1–A5 执行。

---

## 1. 交互流程：第一问 + 之后 5 项分步确认

### 1.1 第一问：素材从哪来（唯一一次二选一）

```
① 我提供模特和衣服            → 收图、逐张读图、定稿 → 进 A2
② WorkBuddy 自己生成模特和衣服 → 代生成 1 张模特 + GARMENTS 张衣服多面拼图 → 读图定稿 → 进 A2
```

只问「素材谁出」，**不问动作、不问模型、不问档位**；两个选项后面流程完全一样，差别只在 A1 是「收图」还是「生图」。
选 ② 代生成前必须报积分（§3 A1）；选 ① 时图不合格（不是全身 / 背景杂乱 / 拼图缺面），先明确告诉用户补哪一张，别硬跑。

### 1.2 之后按全自动路径，一步步确认 5 项

**顺序固定、一次只问一项**，用户答完再问下一项；每项都有缺省值，说「按默认 / 你定」就直接跳过。5 项问完 → 汇总「本次参数表」+ 积分估算 → **用户确认一次** → 开工跑 A1–A5。中途不要再插别的问题（比例、BPM、每镜头时长一律走缺省）。

| 步 | 问用户什么 | 落到哪个参数 | 不答就按这个 |
|---|---|---|---|
| Q1 | 素材从哪来（§1.1，已问） | `SOURCE` | ② WorkBuddy 代生成 |
| Q2 | **衣服做几套？** | `GARMENTS` | **3 套**（起号卡点变装可扩 5–7） |
| Q3 | **什么拍摄角度？** | `CAMERA_ANGLE` | **平视正面全身** |
| Q4 | **要不要生成视频？** | `NEED_VIDEO` | **要**（静帧推近卡点换装片） |
| Q5 | **要不要生成「走的」视频？** | `MOTION_MODE` | **不要**（`static`）；要 → `video` |
| Q6 | **要不要生成「其他姿态」的视频？** | `POSE_MODE` | **不要**（`single`）；要 → `multi` |

**Q3 角度选项**：平视全身 / **俯拍（头顶向下，模特抬头看镜头、上身微微前倾）** / 45° 斜俯 / 仰拍 / **复刻截图**（用户给一张角度参考图，以该图作 `image1`，机位、构图、人物位置一字不改，只换衣服、擦字幕）。提示词模板见 `prompts.md` §0.6。
**角度一旦选定，A1 模特图、A2 每张试衣图、A4 每段真动片段都必须是同一个机位**；跨套串角度（一张俯拍一张平视）一票否决。

**Q4 选「只要图片」** → Q5 / Q6 自动跳过；A2 出完试衣图就收尾，交付试衣图 + 联络表 + 提示词卡，不跑 A3–A5。
**Q5 / Q6 可以叠加** → 都要即最贵档（§1.3 D 档），必须先报积分再开工。

> **判断口径（与旧版相反，别再按老习惯）**：不再摆两条入口让用户二选一，也不再「一次列全 4 档」让用户挑。改成**第一问问素材来源、之后一问一问确认这 5 项**；比例、时长、BPM 等仍走缺省，不单独追问。

### 1.3 出片档位（5 项问答的内部换算表，Agent 自己用）

> 这张表是 **Q4–Q6 答完后的结果**，用来算积分和脚本参数，**不要整张摔给用户让他一次挑**。

```
SOURCE       = user | generated                # Q1 素材来源
GARMENTS     = 3                                # Q2 服装套数
CAMERA_ANGLE = eye | top | 45top | low | ref   # Q3 机位
NEED_VIDEO   = yes | no                        # Q4 要不要视频
MOTION_MODE  = static | video                  # Q5 要不要真走（VideoGen）
POSE_MODE    = single | multi                  # Q6 要不要其他姿态
POSES        = 3                               # multi 时每套姿势数，可扩
SHOTS        = GARMENTS × (POSES if POSE_MODE=multi else 1)   # 出场镜头数
SEG          = 2.0s (single) / 1.0s (multi)                   # 1.0s = 120BPM 的 2 拍，仍卡拍
```

| 组合（由 Q5/Q6 推得） | 姿势 | 动效 | 出场镜头 | ImageGen | VideoGen | 积分估算 | 片长 |
|---|---|---|---|---|---|---|---|
| **A 基础（都不开）** | 每套 1 张站立 | 静帧推近 | 3 段 | 7 张 | 0 | **35–70 分** | 6.0s |
| **B 多姿势**（Q6 要） | 每套 3 张 | 静帧推近 | 9 段 | 13 张 | 0 | **65–130 分** | 9.0s |
| **C 真走秀**（Q5 要） | 每套 1 张站立 | VideoGen | 3 段 | 7 张 | 3 段 | **35–70 + 150–300 分** | 6.0s |
| **D 全开**（Q5+Q6 都要） | 每套 3 张 | VideoGen | 9 段 | 13 张 | 9 段 | **65–130 + 450–900 分** | 9.0s |

> 估算：`ImageGen ≈ 5–10 分/张`、`VideoGen ≈ 50–100 分/5 秒片段`。**开工前按本次组合把积分全报给用户，确认后才调用**。D 档最贵、9 段各等 1–3 分钟，建议先 A/B 看效果再上。
> `VideoGen` 无模型参数，本流程不指定或承诺具体模型版本。

**multi 出场顺序**（按套分组，一套衣服连拍 3 个姿势再切下一套）：
```
衣服01-站立 / 衣服01-叉腰 / 衣服01-回眸 / 衣服02-站立 / … / 衣服03-回眸
```

## 2. 资产规格（A1 = 1 + GARMENTS 张；试衣图张数随问答结果变）

| 资产 | 数量 | 规格 | 谁产出 |
|---|---|---|---|
| 模特全身照 | **1 张** | 9:16 竖版、全身、自然站立、纯色背景、白色紧身底版、商业人像摄影；**机位按 Q3** | 用户上传 / `ImageGen` 文生图 |
| 衣服多面拼图 | **每套 1 张，共 GARMENTS 张** | 一张图里 **2×2 四宫格：正面 / 背面 / 侧面 / 细节特写**，纯白底、平铺或挂拍、无模特 | 用户上传 / `ImageGen` 文生图 |
| A1 合计 | **1 + GARMENTS 张**（默认 4 张，不随档位变） | — | — |
| A2 试衣图 | **single 档 GARMENTS 张；multi 档 GARMENTS × POSES 张** | 同一张定稿模特的脸、**同一个机位**，每套每个姿势 1 张 | `ImageGen` 图生图 |

**为什么每件衣服是「一张多面拼图」**：一次生成就把四个角度交给换装模型，服装配色/版型/图案/领型还原度最高；又不用为每个面单独调一次生成，成本与耗时都最省。这是带货视频的生命线。

**可配置参数**（别写死在流程里，全部由 §1.2 的 5 项问答得出）：

```
SOURCE       = generated   # Q1：user | generated
GARMENTS     = 3           # Q2：服装套数，可扩到 5–7
CAMERA_ANGLE = eye         # Q3：eye | top | 45top | low | ref（复刻截图）
NEED_VIDEO   = yes         # Q4：yes | no（no 时 A2 后收尾，不跑 A3–A5）
FACES        = 4           # 每套衣服拼图的面数（2×2 四宫格）
MOTION_MODE  = static      # Q5：static | video
POSE_MODE    = single      # Q6：single | multi
POSES        = 3           # multi 时每套姿势数：站立 / 叉腰 / 回眸，可扩
SHOTS        = GARMENTS × (POSES if POSE_MODE=multi else 1)
BPM          = 120         # 卡点速度
SEG          = 2.0 if POSE_MODE=single else 1.0   # 每镜头秒数；1.0s = 2 拍，仍落在拍线上
SIZE         = 1080x1920
```

改套数 / 姿势数时**音乐、切点、拼接全部跟着变**：`beat_music.py --segments SHOTS` 与 `compose_video.py` 的 `SHOTS` 张图必须一致，**`--segments` 是出场镜头数，不是套数**。

## 3. 五个自动阶段（A1–A5）

### A1 素材归位 / 代生成

**Q1 选 ①（有素材）**：收进 `<选题>/模特/` 和 `<选题>/服装/`，逐张 `ViewImage` 读图，确认是全身、纯色背景、多面拼图清晰、机位符合 Q3。

**Q1 选 ②（没素材 → 我代生成）**（一次性列全提示词，参数从用户的话里抽，不写死；机位句按 Q3 / `prompts.md` §0.6）：

| 生成什么 | 工具 | 提示词要点 |
|---|---|---|
| 1 张模特全身照 | `ImageGen`，`size="1024x1536"`，`quality="high"` | `<年龄段><气质>亚洲女装模特，<发型>，<身材>，自然裸妆，<Q3 机位句>，自然站立，白色紧身衣，纯色背景，商业人像摄影风格，9:16`；明确「不露品牌 logo、不擦边」 |
| GARMENTS 张衣服多面拼图 | `ImageGen` × GARMENTS | 每套一条提示词：`2×2 四格拼图，同一件<服装品类>的正面/背面/侧面/细节特写四张平铺图，纯白背景，电商商品图风格，四格之间留白均匀，无人物`，每套换 `<颜色/图案/版型>`，各套风格明显不同（换装才有看头） |

> 生成前**必须告知用户积分消耗**：`ImageGen` 约 5–10 积分/张，本步 `1 + GARMENTS` 张（默认 4 张 ≈ 20–40 积分）。用户确认后再调用。

**过闸**：模特图脸/手完整、9:16 全身、纯色背景、**机位与 Q3 一致**；衣服拼图四格齐全、同一件衣服、白底干净。定稿模特图存 `<选题>/模特/模特-定稿.png`，是后续所有换装的**人物锚点**。

### A2 换装（按 `POSE_MODE` 分叉）

**所有档位共用**：对每张试衣图跑一次 `ImageGen` **图生图**，`image1 = 模特-定稿.png`、`image2 = 服装-0X-多面.png`、`input_fidelity="high"`、`size="1024x1536"`、`quality="high"`。提示词模板见 `prompts.md` §0.3，**机位句统一用 Q3 / §0.6，每张一字不改**。

```
# single（Q6 不开）：每套 1 张站立试衣图 → GARMENTS 张
image1 = 模特-定稿.png
image2 = 服装-0X-多面.png
prompt = 把 image2 四格展示的这件衣服穿到 image1 模特身上；
         <Q3 机位句，与 image1 完全一致>；
         脸、发型、身材、姿势与 image1 完全一致，不重画人脸；
         服装的配色/版型/图案/领型严格按 image2 正面那一格，背面与侧面细节一致；
         纯色背景，商业服装摄影，写实，9:16 竖构图

# multi（Q6 要）：每套换 3 个姿势，共 GARMENTS × POSES 张
# 站立沿用上面模板；叉腰 / 回眸用 prompts.md §0.3.1 的「多姿势变体」模板，
# 只改姿势描述，机位 / 脸 / 服装描述一字不改，保证还是同一个人、同一件衣服、同一个机位
```

> `ImageGen` 最多接 3 张输入图，这里只用 2 张，够用且稳。
> **Q3 选「复刻截图」时**：以用户给的角度参考图作 `image1`，机位、构图、人物位置严格保持，只换衣服与擦字幕；脸若被重画，追加「脸部与 image1 完全一致，不改变五官」重跑**这一套**，不要连坐其它套。
> 生成前**必须告知用户**：single 档本步 `GARMENTS` 张（默认 3 张 ≈ 15–30 积分，一轮共 7 张 ≈ 35–70 分）；multi 档本步 `GARMENTS × POSES` 张（默认 9 张 ≈ 45–90 积分，一轮共 13 张 ≈ 65–130 分）。用户确认后再调用。

**过闸**（`ViewImage` 逐张亲眼看，按 `qc-gates.md` 图四查）：脸与定稿一致、服装还原、手指正常、无渗色、**机位与 Q3 一致**。
**multi 档加查**：同一套 3 张必须是**同一张脸、同一件衣服、同一个机位**，且 3 个姿势确实有差异（叉腰/转身/回眸）；姿势没变出来 = 白花钱，重跑这一姿势。
不合格**只重跑这一张**，带上「哪里不像」改提示词。输出 `<选题>/试衣/`。

**Q4 选「只要图片」时到此收尾**：交付 `<选题>/试衣/` 全部试衣图 + 联络表 + `prompts.md` 对应提示词卡，不跑 A3–A5。

### A3 卡点音乐（程序化，自己生成，不用外部音源）

```bash
python3 scripts/beat_music.py --out <选题>/音乐/卡点音乐.wav \
    --segments $SHOTS --seg $SEG --bpm 120 --report <选题>/音乐/beat-report.json
```

- `--segments` = **SHOTS（出场镜头数）**：single 档 = GARMENTS、multi 档 = GARMENTS × POSES。
- `--seg`：single 档 2.0s（4 拍一小节）；multi 档 1.0s（2 拍，仍落在拍线上，切得更密、节奏更强）。
- 纯 `numpy` + 标准库合成：4/4 拍鼓组（kick / snare / hihat）+ bass + 和弦 pad + **每个切换点的 impact/riser**。切点写在 `report.json` 的 `cut_points`，与画面硬切一一对齐。**不依赖任何音乐素材、不产生版权问题**。

### A4 出片（两种画面来源，按 `MOTION_MODE` 分叉）

**static 档（Q5 不开，缺省）** —— 静帧推近动效，零视频生成成本：

```bash
python3 scripts/compose_video.py \
    --images <选题>/试衣/试衣-01.png … <选题>/试衣/试衣-<SHOTS>.png \
    --music  <选题>/音乐/卡点音乐.wav \
    --out    <选题>/成片/换装成片.mp4 --seg $SEG --bpm 120 \
    --report <选题>/成片/compose-report.json
```

**video 档（Q5 要）** —— 让模特真的走起来：

1. 对**每个出场镜头**调一次 `VideoGen`：`image=<该镜头试衣图>` 作首帧、`aspect_ratio="9:16"`、`seconds` 取模型支持的最短值（生成 5s 也没关系，脚本会 `trim` 到 `--seg`），提示词用 `prompts.md` §0.4 的「真动片段」模板，**并带上 Q3 机位句**，统一「模特朝镜头自信走来、自然摆臂、镜头缓慢跟随、写实」。
2. 把 **SHOTS 个 mp4** 按出场顺序传给 `compose_video.py --motion`（数量必须与 `--images` 一致，脚本会校验）：

```bash
python3 scripts/compose_video.py \
    --images <选题>/试衣/试衣-01.png … --motion <选题>/真动/clip-01.mp4 … \
    --music  <选题>/音乐/卡点音乐.wav \
    --out    <选题>/成片/换装成片.mp4 --seg $SEG --bpm 120 \
    --report <选题>/成片/compose-report.json
```

> ⚠️ 开 video 档前**必须告知**：`VideoGen` 约 50–100 积分 / 5 秒片段 —— C 档 3 段 ≈ 150–300 积分，D 档 9 段 ≈ 450–900 积分，且**每段要等 1–3 分钟**。缺省先测 static 档，效果不满意再上。
> 真动片段质检：首帧必须与对应试衣图的脸/服装/**机位**一致；跨镜头不许换脸、不许串衣服、不许串机位。

脚本自动完成：每段精确 `trim` → 硬切 concat → 音乐 `-14 LUFS` 归一 → H.264/AAC → **faststart**，并输出 `report.json`（时长、切点、音轨、atom 顺序、`motion_source`）。

### A5 质检与发布包

1. 跑 `scripts/qc_frames.py` 抽帧，`ViewImage` 逐帧读：脸是否漂移、**机位是否跨镜头一致**、服装是否跨套串色、切点是否干净；video 档另查动作流畅与首帧一致。
2. `ffprobe` 复核：时长 = `SHOTS × SEG`、1080×1920、有音轨、`moov` 在前。
3. 发布包 `<选题>/发布包/`：`换装成片.mp4` + `发布文案.md`（按 `ops-playbook.md` 模板，**必带 AI 生成标注提醒**）。
4. 台账 `<选题>/台账.json`：**本次 5 项问答结论（`SOURCE` / `GARMENTS` / `CAMERA_ANGLE` / `NEED_VIDEO` / `MOTION_MODE` / `POSE_MODE`）** + 4 项资产与全部试衣图（+ 真动片段）的提示词、参数、`SHOTS` / `SEG`、积分、日期、质检结论 —— 复现与迭代全靠它。

## 5. 合规（发布前逐条打勾）

1. **AI 标注**：发布时打开平台「内容由 AI 生成」标识。
2. **肖像权**：用户上传的真人照片造模特，须确认本人同意；代生成的 AI 脸无此问题。
3. **不冒充真人**：文案不得暗示真人实拍，账号简介写明 AI 内容。
4. **服装图权利**：代生成的衣服是虚构款，可直接做内容；用户上传别家商品图带货需自有或授权。
5. **尺度**：避免擦边运镜与文案 —— 「AI 美女」类目平台审得最严的是擦边，不是 AI 本身。
