# 晚枫模特换装（wanfeng-ai-model）

> **一句话**：参考图 → 专属模特 → 多套衣服上身 → 卡点音乐 → 一条能直接发的换装短片。
>
> **开工只有一条路径，问法固定**：第一问只问「素材谁出」（用户提供 / WorkBuddy 代生成），之后沿全自动流水线**一步步**问清 5 项（几套衣服 / 什么角度 / 要不要视频 / 要不要真走 / 要不要其他姿态），问完汇总参数与积分、确认一次，再跑 A1–A5。
>
> **不再摆「默认 / 自定义」两个入口，也不再让用户一次挑 4 档矩阵** —— 一问一问来。
>
> **工具口径**：本流程只用 WorkBuddy 内置 `ImageGen` / `VideoGen` + 本地 ffmpeg，不打开任何网页；`VideoGen` 不指定或承诺具体模型版本。

## 一、何时使用

- 「帮我做 AI 模特试衣视频」「让 AI 模特穿上这件衣服走一段」
- 「把这件衣服换到我的 AI 模特身上」「批量生成服装上身图」
- 「批量生产模特视频 / 一套模特配 N 套衣服」「卡点换装视频」
- 「AI 美女账号起号，教我做这种视频」

**不适用**：真人口播混剪 → `晚枫自动剪视频-Pro`；口播数字人 → `wanfeng-digital-human(-pro)`；给已剪好的视频加包装 → `晚枫自动剪视频`。本 Skill 出的是**无口播、纯画面**的模特展示视频。

## 二、第一问：素材从哪来（唯一一次二选一）

| 选项 | 用户给什么 | A1 怎么走 |
|---|---|---|
| **① 我提供模特和衣服** | 1 张模特全身照 + N 套衣服图（每套 1 张，四宫格多面图最佳） | 收进 `<选题>/模特/`、`<选题>/服装/`，逐张 `ViewImage` 读图 → 定稿 → 直接进 A2 |
| **② WorkBuddy 自己生成模特和衣服** | 什么都不用给；也可口头说风格（年龄段 / 气质 / 服装风格） | 代生成 1 张模特全身照 + N 套衣服多面拼图 → 读图定稿 → 进 A2 |

> 这一问**只问素材谁出**，不问动作、不问模型、不问档位；选完立刻进入 §三 的分步确认。
> 选 ② 时代生成前必须报积分（§3.5）；选 ① 时若图不合格（不是全身 / 背景杂乱 / 拼图缺面），先明确告诉用户补哪一张，别硬跑。
> 两个选项**殊途同归**：后面 5 项、A1–A5、脚本、质检完全一样，差别只在 A1 是「收图」还是「生图」。

## 三、之后按全自动路径，一步步确认 5 项

> **顺序固定、一次只问一项**，用户答完再问下一项；每项都有缺省值，用户说「按默认 / 你定」就直接跳过。
> 五项问完，Agent 汇总成一张「本次参数表」+ 积分估算 → **用户确认一次** → 开工跑 A1–A5。
> 中途不要再插别的问题：比例、BPM、每镜头时长等一律走缺省（§3.4）。

| 步 | 问用户什么 | 落到哪个参数 | 不答就按这个 |
|---|---|---|---|
| **Q1** | 素材从哪来（§二，已问） | `SOURCE` | ② WorkBuddy 代生成 |
| **Q2** | **衣服做几套？** | `GARMENTS` | **3 套**（起号卡点变装可扩到 5–7） |
| **Q3** | **什么拍摄角度？** | `CAMERA_ANGLE` | **平视正面全身** |
| **Q4** | **要不要生成视频？** | `NEED_VIDEO` | **要**（静帧推近卡点换装片） |
| **Q5** | **要不要生成「走的」视频？** | `MOTION_MODE` | **不要**（`static`）；要 → `video` |
| **Q6** | **要不要生成「其他姿态」的视频？** | `POSE_MODE` | **不要**（`single`）；要 → `multi` |

**Q3 角度选项**（说编号即可，也可以丢一张截图让我照着复刻）：

| 角度 | 画面特征 | 提示词 |
|---|---|---|
| 平视全身 | 相机与人物齐平、正面、头到脚完整 | `references/prompts.md` §0.6 |
| **俯拍（头顶向下）** | 镜头在人物头顶上方从上向下拍，模特抬头看镜头、上身微微前倾、单手叉腰 | §0.6（最近实测还原度最高，机位写进提示词才稳） |
| 45° 斜俯 | 斜上方 45°，显腿长、有纵深 | §0.6 |
| 仰拍 | 低机位向上，气场强，易变形慎用 | §0.6 |
| **复刻截图** | 用户给一张角度参考图 → 以该图作 `image1`，**机位 / 构图 / 人物位置一字不改**，只换衣服、擦字幕 | §0.6 |

> **Q4 选「只要图片」** → Q5 / Q6 自动跳过；A2 出完试衣图就收尾，交付试衣图 + 联络表 + 提示词卡，不跑 A3–A5。
> **Q5 / Q6 可以叠加**：都要 = 多姿势真走秀（最贵档），必须先报积分再开工。
> **角度一旦选定，A1 模特图、A2 每一张试衣图、video 档每一段真动片段都必须是同一个机位**；跨套串角度一票否决（§四、§3.5）。

### 3.1 出片档位（五项问答的内部换算表，Agent 自己用）

> 这张表是 **Q4–Q6 答完后的结果**，用来算积分和脚本参数，**不要整张摔给用户让他一次挑**。用户只回答那 5 个「要不要 / 几套 / 什么角度」。

```
SOURCE       = user | generated        # Q1 素材来源
GARMENTS     = 3                        # Q2 服装套数
CAMERA_ANGLE = eye | top | 45top | low | ref   # Q3 机位
NEED_VIDEO   = yes | no                # Q4 要不要视频
MOTION_MODE  = static | video          # Q5 要不要真走（VideoGen）
POSE_MODE    = single | multi          # Q6 要不要其他姿态
POSES        = 3                        # multi 时每套姿势数，可扩
SHOTS        = GARMENTS × (POSES if POSE_MODE=multi else 1)   # 出场镜头数
SEG          = 2.0s (single) / 1.0s (multi)                   # 1.0s = 120BPM 的 2 拍，仍卡拍
```

| 组合（由 Q5/Q6 推得） | 姿势 | 动效 | 出场镜头 | ImageGen | VideoGen | 积分估算 | 片长 |
|---|---|---|---|---|---|---|---|
| **A 基础（都不开）** | 每套 1 张站立 | 静帧推近 | 3 段 | 7 张 | 0 | **35–70 分** | 6.0s |
| **B 多姿势**（Q6 要） | 每套 3 张 | 静帧推近 | 9 段 | 13 张 | 0 | **65–130 分** | 9.0s |
| **C 真走秀**（Q5 要） | 每套 1 张站立 | VideoGen 真动 | 3 段 | 7 张 | 3 段 | **35–70 + 150–300 分** | 6.0s |
| **D 全开**（Q5+Q6 都要） | 每套 3 张 | VideoGen 真动 | 9 段 | 13 张 | 9 段 | **65–130 + 450–900 分** | 9.0s |

> 估算口径：`ImageGen ≈ 5–10 分/张`、`VideoGen ≈ 50–100 分/5 秒片段`；**开工前必须按本次组合报给用户并等确认**（§3.5）。D 档最贵且 9 段各等 1–3 分钟，建议先跑 A/B 看效果再上。
> `VideoGen` **没有模型参数**，本流程不指定或承诺具体模型版本。

**multi 出场顺序**（按套分组，一套衣服连拍 3 个姿势再切下一套，换装感最强）：
```
衣服01-站立 / 衣服01-叉腰 / 衣服01-回眸 / 衣服02-站立 / … / 衣服03-回眸
```

### 3.2 资产规格

| 资产 | 数量 | 规格 |
|---|---|---|
| 模特全身照 | **1 张** | 9:16 全身、自然站立、纯色背景、白色紧身底版、商业人像；**机位按 Q3** |
| 衣服多面拼图 | **每套 1 张 × GARMENTS 套** | 一张 2×2 四宫格：**正面 / 背面 / 侧面 / 细节特写**，白底、无模特、同一件衣服 |
| A1 合计 | **1 + GARMENTS 张** | 4 个角度一起喂换装，还原度最高 |
| 试衣图（A2） | **single 档 GARMENTS 张；multi 档 GARMENTS × POSES 张** | 同一张定稿模特的脸、**同一个机位**，每套每个姿势 1 张 |

> 「一套衣服多个面是一张照片」—— 面数定为 **4**（2×2 四宫格）；套数由 **Q2** 决定（默认 3，可扩到 5–7），角度由 **Q3** 决定，都不写死在流程里。

### 3.3 五个自动阶段

```
A1 素材归位 / 代生成   → Q1：有就上传；没有就代生成 1 张模特 + GARMENTS 张衣服多面拼图
A2 自动换装            → Q3 机位 + Q6：single 每套 1 张站立；multi 每套 3 个姿势（叉腰/转身/回眸）
A3 卡点音乐            → --segments = SHOTS，--seg = SEG；程序化合成，不用外部音源
A4 合成短片            → Q4/Q5：不出片就停；static 静帧推近；video 每镜头 1 段 VideoGen 真动 → --motion
A5 质检与发布包        → 抽帧逐帧读 → ffprobe 复核 → 发布文案 → 台账
```

### 3.4 关键可执行命令（细节见 `references/auto-pipeline.md`）

```bash
# A3 卡点音乐：--segments 必须等于 SHOTS（出场镜头数，不是套数）
python3 scripts/beat_music.py --out <选题>/音乐/卡点音乐.wav \
    --segments $SHOTS --seg $SEG --bpm 120 --report <选题>/音乐/beat-report.json

# A4 静帧档（Q5 不开）：--images 按出场顺序传 SHOTS 张试衣图
python3 scripts/compose_video.py --images 试衣-01.png … 试衣-09.png \
    --music 卡点音乐.wav --out 换装成片.mp4 --seg $SEG --bpm 120 \
    --report <选题>/成片/compose-report.json

# A4 真走档（Q5 要）：VideoGen 对每个镜头出 1 段（image=该镜头试衣图作首帧），
# 再把 SHOTS 个 mp4 按顺序传给 --motion（数量必须与 --images 一致，脚本会校验）
python3 scripts/compose_video.py --images 试衣-01.png … --motion clip-01.mp4 … \
    --music 卡点音乐.wav --out 换装成片.mp4 --seg $SEG --bpm 120 --report …

# A5 抽帧质检
python3 scripts/qc_frames.py --video <成片.mp4> --out <选题>/成片/抽帧/ --n 8 --mode auto
```

脚本自动完成：每段精确 `trim` → 硬切 concat → 音乐 `-14 LUFS` 归一 → H.264/AAC → **faststart**。

### 3.5 四条硬约束

1. **换装必须复用同一张定稿模特图** —— 跨套、跨姿势、跨条人物一致全靠它；换脸等于重新起号。multi 档每套 3 个姿势也必须是同一张脸。
2. **角度必须全程一致** —— Q3 选定的机位写进 A1 / A2 / A4 每一条提示词；跨套串机位（一张俯拍一张平视）等于换了个视频，抽帧质检一票否决。复刻截图时以截图为 `image1`，机位与构图一字不改。
3. **生成前告知积分** —— 按 §3.1 本次组合报全：`ImageGen` 约 5–10 分/张（A1 `1+GARMENTS` 张、A2 `SHOTS` 张），`VideoGen` 约 50–100 分/5 秒片段（C 档 3 段 ≈ 150–300 分，D 档 9 段 ≈ 450–900 分，每段等 1–3 分钟）。**用户确认后才调用**。
4. **不许冒充真走** —— Q5 不开时是静帧推近动效，不是模特真的在走；用户要「走来走去」必须开 `MOTION_MODE=video`，且成本明显上升。

## 四、质检（Agent 必须亲眼读图，不能只听用户说）

- **图**：`ViewImage` 读模特图 / 衣服拼图 / 试衣图，按 `references/qc-gates.md` 图四查（人脸一致 / 服装还原 / 肢体手指 / 边缘瑕疵）。服装还原不合格**一票否决**，只重跑那一套；multi 档还要查**同一套 3 个姿势确实是同一张脸、姿势有差异、衣服没变**；**加查 Q3 机位一致**（尤其俯拍，别一张俯一张平）。
- **视频**：`scripts/qc_frames.py` 抽帧 → 逐帧读，查脸部漂移、**机位跨镜头一致**、服装跨套串色、切点是否干净；video 档额外查首帧与试衣图一致、动作流畅无崩坏。
- **技术复核**：`ffprobe` 查时长 = `SHOTS × SEG`、1080×1920、有音轨、`moov` 在前。
- 台账 `<选题>/台账.json` 登记每次提示词、参数、**本次问答结论（`SOURCE` / `GARMENTS` / `CAMERA_ANGLE` / `NEED_VIDEO` / `MOTION_MODE` / `POSE_MODE`）**、积分、日期、质检结论。

## 五、合规红线（发布前最后一道闸）

1. **AI 内容标识**：发布时打开平台「内容由 AI 生成」标注，不标注有限流与处罚风险。
2. **肖像权**：上传的真人照片造模特须取得本人同意；代生成的 AI 脸无此问题；**绝不**用明星/网红脸带货。
3. **不冒充真人**：文案不得暗示真人实拍，账号简介注明 AI 内容。
4. **服装图权利**：代生成的是虚构款可直接用；上传别家商品图带货需自有或授权。
5. **内容尺度**：避免擦边运镜与文案 —— 平台审「AI 美女」类目最严的是擦边，不是 AI 本身。

## 六、起号打法

批量节奏、卡点变装（5–7 套一条片）、多姿势档位怎么配节奏、发布文案模板、数据复盘 → `references/ops-playbook.md`。
核心口径：**一套定稿模特是资产**，配 N 套服装就是 N 条视频。

## 七、已知限制（对用户坦白）

1. 本流程用 WorkBuddy 内置 `ImageGen` / `VideoGen`：**调用前必须告知积分消耗**，生成要等 1–3 分钟。
2. `VideoGen` **没有模型参数**，本流程不指定或承诺具体模型版本。
3. Q5 不开时画面是**静帧推近动效**，不是模特真的在走；要「走来走去」需开 `MOTION_MODE=video`，成本明显上升。
4. Q6 的多姿势仍是**静帧图**，只是镜头切得更快；要「边走边换姿势」只能 Q5+Q6 都开，且 9 段 VideoGen 成本高、耗时长。
5. 俯拍等非平视机位对提示词更敏感，必须把机位句写全并逐张核对；复刻截图时人脸可能被重画，需按 §3.5 只重跑那一套。
6. 手指、服饰细节、人脸跨帧一致性是模型弱项，抽帧质检是硬要求不是可选项。
7. 平台审核规则会变，发布前以当期规则为准。
