## 1. 仓库（Repository / Repo）

**人话**：网上的一个文件夹，装着你整个项目。

```
比喻：你家的「房间」——你的代码、文档、图片都住在这里。
       GitHub / Gitee 上的「房间」就叫「仓库」。
```

**为什么需要它**：本地文件夹只在你自己电脑里，仓库是放网上的「云端房间」，换电脑也能访问。

---

## 2. 提交（Commit）

**人话**：给代码拍一张「快照」，附上文字说明改了啥。

```
比喻：玩游戏的「存档」——你可以随时回到这个存档点。
       每次 commit 就是一个存档。
```

**为什么需要它**：改错了能回到之前的状态；和别人协作时知道谁改了什么。

**常见误解**：
- ❌「commit = 保存」→ 不对，保存是 Ctrl+S
- ✅「commit = 写日志」→ 对，是「记录这一刻的代码状态」

---

## 3. 分支（Branch）

**人话**：同一条时间线上岔出去的小路，可以分开改东西最后合并。

```
比喻：写论文时，先复制一份改，改完了再合并回去。
       主线叫 main，岔出去叫 feature/xxx。
```

**为什么需要它**：你写新功能时不会影响主代码；想试错时不会搞坏已有功能。

---

## 4. 远程（Remote）

**人话**：代码在网上的备份地址。

```
比喻：你家房间（本地）+ 网上房间（远程）。
       push = 把东西从家里搬到网上
       pull = 把网上的东西搬回家里
```

**为什么需要它**：电脑坏了也不丢代码；多台电脑能同步。

---

## 5. SSH Key

**人话**：你家门钥匙，让 GitHub 知道「你是你」。

```
比喻：小区门禁卡——刷卡就进，不用每次输密码。
       公钥 = 锁（放在 GitHub 上）
       私钥 = 钥匙（放你电脑 ~/.ssh/ 下）
```

**为什么需要它**：比密码安全（密钥很长很难被破解）；配一次永久免密。

---

## 6. PAT（Personal Access Token）

**人话**：临时通行证，比密码安全，可以随时撤销。

```
比喻：酒店房卡——丢了可以让前台停用，再补一张。
       权限可以选「只读 / 读写 / 删仓库」。
```

**为什么需要它**：GitHub 不让用密码 push 了（太危险），PAT 是替代品。

---

## 7. `.gitignore`

**人话**：黑名单，告诉 Git「这些文件不要管」。

```
比喻：搬家时把「不要的杂物」列个清单，搬运工就不搬这些。
       node_modules/、.env、dist/ 都不要管。
```

**为什么需要它**：
- 节省空间（不传无用文件）
- 保护隐私（不传密码、API key）
- 避免冲突（不传系统自动生成的文件）

---

## 8. 拉取 / Clone

**人话**：把网上的项目完整下载到本地。

```
比喻：在网上看到一个食谱（仓库），下载到自己的电脑（本地）照着做。
       不会自动同步，你下载的永远是那一刻的版本。
```

**为什么需要它**：想跑 / 改 / 学习别人的开源项目。

---

## 9. Fork

**人话**：在 GitHub 上「抄一份」别人的项目到自己账号下。

```
比喻：看到一个喜欢的菜谱，复制到自己账号下可以随便改。
       改完了可以「请原作者合并」（这叫 Pull Request）。
```

**为什么需要它**：想贡献别人的开源项目、又不直接改原版。

---

## 10. Pull Request（PR）

**人话**：告诉原作者「我改了点东西，你要不要合并进去」。

```
比喻：你 fork 了一份菜谱，改完后跟原作者说：
       「我加了个川菜版，你要不要试试？」
       他同意了（merge），全网的人都能看到。
```

**为什么需要它**：开源协作的「礼貌机制」——不直接改原版，先问。

---

## 11. README

**人话**：项目的「门面」，第一眼看到的就是它。

```
比喻：餐厅的菜单 / 酒店的前台。
       告诉访客：这是啥、怎么用、谁能贡献。
```

**为什么需要它**：没 README 的项目 = 没菜单的餐厅，客人不敢进。

---

## 12. License（许可证）

**人话**：告诉别人「你可以怎么用我的代码」。

```
比喻：合同——是免费商用 / 只能学习 / 必须署名 / 改了也要开源。
       MIT = 最宽松，随便用
       GPL = 改了也要开源
       Apache 2.0 = MIT + 专利授权
```

**为什么需要它**：没许可证 = 别人不敢用（怕侵权）。

---

## 13. Issue（议题）

**人话**：项目里的「讨论帖 / 报bug 帖」。

```
比喻：餐厅的意见簿——客人提意见、提问题、提功能建议。
       维护者看了会回复，会修。
```

**为什么需要它**：发现 bug 第一反应不是发邮件，是开 Issue。

---

## 14. Star（收藏）

**人话**：给项目点个赞 + 收藏。

```
比喻：朋友圈点赞 + 收藏夹。
       Star 数高 = 项目受欢迎。
```

**为什么需要它**：方便找回来；给作者鼓励。

---

## 15. Mirror（镜像）

**人话**：把项目「复制」到另一个地方，提供同样内容。

```
比喻：一本书在新华书店有，图书馆也有。
       同一个内容，不同地方都能拿。
       国内 GitHub 镜像：ghfast.top、kgithub.com 等。
```

**为什么需要它**：GitHub 慢 / 不通时，镜像能救命。
