### 0.1 图片缺失时怎么办（分发渠道不允许上传图片）

部分分发渠道**不允许随包上传图片**，所以买家机器上的 `cover-assets/` 可能是空的。
这时按下面的顺序处理，**不要因为找不到图就跳过 Step H**：

1. **先看本机有没有现成的**：设环境变量 `MOGRAPH_ASSET_DIR`（兼容旧名 `MOGRAPH_PRO_ASSET_DIR`）指向本机已有的 `cover-assets` 目录
   （比如你本地仓库里的 `skills/mograph/cover-assets/`）。
2. **本地没有就下载**：换皮脚本内置了下载兜底 —— 本地全找不到时自动拉到
   `~/.cache/wanfeng-mograph/cover/`（`MOGRAPH_ASSET_CACHE` 可改目录），之后再跑脚本即可。两档源、路径一致：

   | 顺位 | 源 | 地址 |
   |---|---|---|
   | 1 | **AtomGit 国内源**（GitHub 打不开时用这个） | `https://atomgit.com/CoderWanFeng1/wanfeng-skills/tree/main/skills/mograph/cover-assets` |
   | 2 | GitHub 原始文件 | `https://raw.githubusercontent.com/CoderWanFeng/wanfeng-skills/main/skills/mograph/cover-assets/<文件名>` |

   > ⚠ **AtomGit 不能用 `.../raw/main/<路径>` 直链**（2026-11-17 实测：返回 64×48 占位 SVG / HTML，不是原图）。
   > 脚本走 `api/v5/repos/.../contents/<目录>?ref=main` 接口，从 `download_url`（`raw.atomgit.com/.../blobs/<sha>/...`）下载。
   > 手动下载请直接开目录页点文件。

3. **手动下载也行**：打开上面任一目录页，把 `封面-底图-混元WB.jpg` 与 `hy4-frame7.jpg` 下载下来，
   放进 skill 的 `cover-assets/`，或放到任一目录后用 `MOGRAPH_ASSET_DIR` 指过去。

> 下载只解决「图片从哪来」，**不改变授权范围**：封面底图与头发参考帧仍是受保护资产，
> 只能用于「在固定底图上换字换 logo」的封面换皮用途（见 `LICENSE.md` §2）。

**环境**：托管解释器 `~/.workbuddy/binaries/python/envs/default/bin/python3`
（PIL 12.x + numpy + cv2 5.0 都在这里；`/usr/bin/python3` 没有 cv2，会直接报错）。

## 1. 五步流程

```
1. 复制模板   templates/cover_from_base.example.py → <选题>/AI剪辑输出/src/cover.py
2. 取 logo    本地有合适的就用；没有就联网下载（判据与命令见 §1.2）→ 得到一个透明底 PNG
3. 改 CONFIG  只改【每期必改】项：OUT、两行文案与配色、logo 三项
4. 跑脚本     托管解释器直跑，秒级出图 → <选题>/发布包/封面-XXX.jpg
5. 三闸自检   见 §3（净空闸 / 明度闸 / 字号闸，全部实测，不许目测）
6. 读图交付   Read 工具真读一遍成品，再放进发布包
```

### 1.1 CONFIG 每期改什么

| 项 | 说明 |
|---|---|
| `OUT` | 竖版输出 `发布包/封面-XXX.jpg`；横版用独立配置，输出 `发布包/横版视频/封面-XXX-横版.jpg`。路径均以选题根定位，不以当前目录猜测。 |
| `LINE1_SEGS` / `LINE2_SEGS` | 两行文案。**中文段 kind="cn"、拉丁/数字段 kind="latin"，必须拆段**（原因见坑 2） |
| `LINE1_FILL` / `LINE2_FILL` | 字色。第一行沿用蓝 `(16,43,99)`、第二行沿用红 `(160,19,21)`，都是从底图原字采样的，**换选题一般不用改** |
| `ERASE_LOGO` | `False` = 保留底图原 WorkBuddy 标识（推 WorkBuddy 的选题用）；`True` = 抹掉换成自己的 |
| `ICON_DRAWER` / `WORD_TEXT` | 新 logo 的图标画法函数名 + 字标文本（示例：`z_icon` / `"ZCODE"`）。**走手绘路径时用** |
| `LOGO_PATH` | **外部 logo 文件路径**（联网下载或用户给的透明底 PNG）。留空 = 走手绘路径（58 号已验证，max diff = 0）；非空 = 顶替手绘，按宽高比自动落位：方形图标（宽/高 < 1.6）→ 贴到图标位、字标仍用 `WORD_TEXT` 画；横排整条（宽/高 ≥ 1.6）→ 整条进 `LOGO_BAND`，**不再画 `WORD_TEXT`** |
| `LOGO_BAND` | 横排整条的落位框 `(864,1150,1694,1450)`【勿改，与底图配准值同源】 |

标了【勿改】的（BASE、HEAD_SRC、DX/DY、两行 cx/cy/size、ICON_X/Y/S、band 坐标）都是
底图配准值和「行距 82px / 净空 33px」的验证结果，动了必翻车。

## 1.2 logo 从哪来（本地不够就自己上网取）

> 用户原话（长期约定，不是单期需求）：
> 「如果本地素材没有合适的相关产品 Logo，可以自行从网上下载，**在准确的前提下要好看**。」

### 取件顺序（先本地，后联网，最后兜底）

| 顺位 | 来源 | 什么时候用 |
|---|---|---|
| 1 | **本地素材** —— 选题工程里已有的图、skill 内 `references/assets/`、用户直接丢过来的图 | 有合适的就用它。本地已有的最省事，也最不容易出错 |
| 2 | **联网下载** | 本地没有合适的、或本地那张版本不对 / 太糊 / 带白边 → 自己去网上取 |
| 3 | **兜底：不露 logo** | 产品本来不需要露出标识 → `ERASE_LOGO=False`（保留底图原标识）；或在文案里用纯文字提产品名 |

### 准确性优先于好看（顺序不能倒）

选哪个 logo 是**判断题**，先过准确性三关，**任何一关不过就不许用**；好看是第二顺位。

| 关 | 判据 | 不过关怎么办 |
|---|---|---|
| ① **是不是这个产品** | 图形/文字与本期讲的产品**完全对得上**，不能是"同类"、"竞品"、"前代" | 换源。宁可换 3 次源，不许拿"差不多"的 |
| ② **是不是官方** | 来自官网 / 官方 GitHub / 官方社媒 / 官方素材站（**优先 SVG 矢量**） | 第三方画板、图标站的"仿制品"、AI 生成的 logo —— 一律不用 |
| ③ **是不是同一版本** | 与当期产品一致（GLM-4.5 的标不能用 GLM-3 的老标；配色/字形也要是当期的） | 换当期官方源 |

### 好看（准确性过了之后才轮到它）

- **优先 SVG 矢量** —— 任意放大不糊（`get_logo.py` 会自动转 PNG）
- 源图最短边 **≥ 256px**，否则放大到封面尺寸边缘发糊（脚本会打 warning）
- 要**透明底** —— 白底 logo 必须去白底，否则贴在墙上会露出一块白方块
- **不要四周留白** —— 留白会让 logo 比预期小一圈（脚本自动裁）
- 优先用**官方横排整条**（图标+字标一体），别自己拼"图标 + 拼字标" —— 拼的字标字体对不上官方，一眼假
- 颜色以官方为准，不要为了"配封面"擅自改色

### 怎么下载（可执行）

```bash
# 联网取 logo：下载 → SVG转PNG → 去白底 → 裁留白 → 登记来源
~/.workbuddy/binaries/python/envs/default/bin/python3 \
  skills/mograph-pro/scripts/get_logo.py \
  --url "https://<官方直链>.svg" \
  --out "<选题>/AI剪辑输出/assets/logo/<brand>.png" \
  --brand "GLM" \
  --manifest "<选题>/mograph-task/assets/asset-manifest.json" \
  --note "Step H 封面 logo"
```

取到之后，把输出路径填进模板 CONFIG 的 `LOGO_PATH`，其余照旧。

脚本**只管取件与规整，不管取哪个** —— 选哪个 logo 是判断题，按上面三关自己判。
脚本打印的摘要里看 `mode`：`icon` = 方形图标、`lockup` = 横排整条，模板按这个自动落位，不用手工选分支。

### 来源必须登记（W15）

`--manifest` 会把 url、抓取日期、用途写进 `asset-manifest.json`。
**不许跳过** —— 封面 logo 是外部素材，来源不明等于素材台账破了。

### 取不到 / 不确定怎么办

- 官方源都拿不到 → **不要用近似 logo**。改走 `ERASE_LOGO=False`，或用纯文字提产品名
- 拿到了但不确定准不准 → **问用户**：「这是 XX 官方的 logo 吗？」
- 优先级一句话：**宁可用文字，也不用不确定的 logo**

## 2. 版式实测值（用户四轮反馈收敛的最终形态）

```
第一行  免费用GLM     cy=172  字号 207（拉丁 202）
第二行  每天领3亿     cy=490  字号 262（数字 248）   ← 行距 82px（从 65px 拉开过）
第二行字底      y=593
头发顶          y=626                          ← 净空 33px
投影收住线      y=615                          ← 投影不碰头发
logo 图标       (864,1150) 300px；字标 y=1301 字号 152 字距 -6（宽度 508px，不出画）
```

**取舍关系（用户已拍板）**：「行距拉大 + 字号不缩 + 绝不压头发」三者不可兼得。
最终解 = 字号微缩 3%（272→262、207 号不变），换来行距 65→82px、净空 24→33px。
下次想调字号，先算字底到 y626 的距离，投影模糊半径 16 + 偏移 13 都要收在净空内。

### 2.1 视频号信息流适配（2026-11-20，72 号发布后真实反馈 · 新选题起默认执行）

72 号封面沿用底图原位（`cy=172/490`、`stroke=10/11`）发布后，用户在视频号里对比自家封面反馈：
**字太靠上、不够粗** —— 频道内表现好的封面（如底图原版样式「免费用AI / 自动剪视频」）字更粗、更靠下。

| 自由度 | 能不能动 | 怎么动 |
|---|---|---|
| 第一行位置 `LINE1.cy` | ✅ 可下移 | 172 → 约 260 一档；顶部留白加大，别顶视频号缩略图的裁切线 |
| 描边粗细 `stroke` | ✅ 加粗一档 | 10/11 → 14/15；「字更粗」主要靠这里 |
| 第二行位置 `LINE2.cy` | ⚠️ 几乎不能动 | 受头发净空硬限制（字底 y593 vs 发顶 y626，仅 33px），下移必压头发；想更靠下靠加粗补 |
| 字号 | ⚠️ 谨慎 | 加大字号同样吃净空；先算字底到 y626 的距离再动 |
| 两行 cx / 行距 82px | ❌ 勿动 | 底图配准值 |

**验收多一道「并排对比闸」**：成品封面与频道内表现好的封面（用户提供的截图基准）并排读图，
确认「字不飘、粗细相当」。净空闸 / 明度闸 / 字号闸照跑 —— **stroke 加粗后字底会向外扩约 stroke 差的一半**，
净空 ≥30px 必须出图后重跑实测，压线就回退一档，别拿估算值交差。

## 3. 三闸自检（全部用像素实测，目测不算）

```python
# 闸 1 · 净空闸：字底（含白边）到头发顶 ≥ 30px，投影收在头发顶之上
# 闸 2 · 明度闸：字色成品值 vs CONFIG 值，每个通道差 ≤ 6（防投影盖字的回归）
# 闸 3 · 字号闸：拉丁段字号 = int(中文号*0.98 / *0.95)，差 1 号边缘全糊
```

| 闸 | 怎么测 | 合格线 |
|---|---|---|
| 净空闸 | 沿第二行文字列做像素投影，找字底 y；暗色+偏暖判据找头发顶 y | 净空 ≥ 30px，投影收在头发顶上方 |
| 明度闸 | 抠成品字面中心像素和 CONFIG 颜色比对 | 逐通道差 ≤ 6（58 号实测蓝字 (19,45,100) vs 配置 (16,43,99)，合格） |
| 字号闸 | 检查 CONFIG 里拉丁字号是否等于 `int(中文号*0.98)`（行1）/ `int(中文号*0.95)`（行2） | 必须相等，手写错 1 号整个字形边缘偏移 |

**投影尾端怎么测（别用阈值法，会误判）**：取一段**纯墙面**（避开头发，如 x950-1250），
打印 y596→700 的逐行平均亮度。墙有竖向渐变，判据是「亮度**单调回升**到平台值」，
出现**局部暗带**才是投影残留。58 号实测：198.6(y596) → 210.1(y628) → 平台 208.4，
单调回升、无暗带 → 投影在 y620 前后收住，不碰头发（头发顶 y626）。

> ⚠️ 用「某行是否有像素 <195/185」这类阈值找投影最下沿会得到假阳性：JPEG 噪声 +
> 墙面竖向渐变本来就有暗值，58 号实测被误报成「投影止于 y633，距头发顶仅 1px」，
> 而真相是差 20px 以上。**一律看亮度曲线，不看单行阈值。**
> 同理找头发顶也别用单行阈值 —— 红色字身的暗红像素会命中「暗色+偏暖」判据，
> 必须从字底**下方**起扫，并要求连续 3 行成立。

## 4. 踩坑清单（每条都真实踩过，含用户直接打回的）

| # | 坑 | 表现 | 解法（已固化在模板里） |
|---|---|---|---|
| 1 | **投影盖字**（用户反馈「字怎么这么暗」） | `alpha_composite(文字, 投影)` 顺序反了，半透明投影压在字上，蓝字实测 (22,36,70)，暗了整整一档 | 必须 `alpha_composite(投影层, 文字层)`，**投影在下** |
| 2 | **TencentSans 拉丁是斜的** | 「GLM」「ZCODE」直接用中文字体排，字是歪的 | 中英拆段：拉丁/数字用 Arial Bold 直立体，按基线对齐 |
| 3 | **inpaint 抹字连头发一起抹**（用户反馈「发型很奇怪」） | 底图原字压在头顶上方，抹字后 y580-700 留一块模糊暗斑，发型缺一块 | 用 `hy4-frame7.jpg` 补回：底图人像就是这帧 1:1 贴入的，配准位移 dx=85/dy=390，逐像素贴回 + per-channel 色调增益 |
| 4 | **椅子颜色渗进墙面** | 铺平暗雾时取左侧墙色平均，把画面左下的椅子采进来了 | 只取右侧 y1020-1300 的**中位数**墙色，逐行填 |
| 5 | **换 logo 字标出画** | ZCODE 152 号仍右溢 | 字距收紧 -6，宽度落回 508px；字标用 `bbox` 垂直居中（`cy-(bb[1]+bb[3])/2`） |
| 6 | **行距太挤**（用户反馈） | 第二行 272 号时字底 602、头发顶 626，净空 24px，投影蹭发 | 字号微缩 3% + 第二行 cy 下移到 490，行距 82px、净空 33px |
| 7 | **从新视频抽帧自拼人像**（用户否决整个方案） | 人脸占 48% 过满，镜像补边 + 渐强虚化都救不回构图 | **不走这条路**。一律在混元底图上换皮，人像永远不动 |
| 8 | **用错解释器** | `No module named 'cv2'` | 换皮脚本必须在托管解释器跑（它要 PIL+numpy+cv2 三个都有） |
| 9 | **qlmanage 渲染 SVG 会裁掉右侧** | 200×120 的 SVG 渲染成 2048×2048 方图，「GLM」的 M 被切一半 | 转换顺序固定：**cairosvg → `sips`（macOS 自带，`sips -s format png -Z 2048`，比例正确、自带透明通道）→ qlmanage（只作最后保底）**。已固化在 `get_logo.py` |
| 10 | **白底 logo 没去干净** | 白底 logo 贴在墙上，露出一块白方块 | `get_logo.py` 的白底转透明用**边缘连通**判定：只吃与四边连通的近白像素，logo 内部的白色不受影响 |
| 11 | **图标 + 字标自己拼，字体对不上** | 自绘图标配自己排的字标，跟官方 logo 一眼就不像 | 优先取官方**横排整条**（宽/高 ≥ 1.6，模板自动走整条分支并停用 `WORD_TEXT`），别拼 |
| 12 | **logo 源图太糊** | 源图只有 64px 宽，贴到 300px 位上边缘全糊 | 换更高清的源（源图最短边 ≥ 256px）；`get_logo.py` 会打 warning 提醒 |
| 13 | **文案沿用底图原位，视频号缩略图里字飘、偏细**（72 号发布后用户对比自家封面反馈） | 字太靠上、不够粗，不如频道内「免费用AI 自动剪视频」那种粗字靠下的样式吸睛 | 第一行下移（cy 172→约260）+ 描边加粗一档（10/11→14/15）；第二行受净空 33px 限制不动；出图后与频道内高表现封面**并排对比**（§2.1），净空闸重跑实测 |

## 5. 与 wanfeng-path.md 执行流的关系

封面是**成片八步全部走完之后**的追加步（Step H），不插在中间：

```
Step 0 删减 → A 定版式 → A2 配图素材采集 → B 场景表 → C 静帧 → D 重渲 → E 终检 → F 响度归一 → G 交接
                                                                          ↓
                                                          Step H 封面（本文件）
```

- 交付目录：竖版封面放 `<选题根>/发布包/`。确认制作宽屏后，为横版单独排封面，与横版视频一起放 `发布包/横版视频/`。同选题直接裁取已确认竖版成品封面里**同一张肖像、同一表情**，等比适配，不拿补发丝参考帧或视频截帧替代；仅做横版而没有竖版封面时，确认并使用同一固定肖像资产（见 [`aspect-ratio.md`](aspect-ratio.md) §4.7）。
- 交接文档（§9 规范）里补一行：封面用的哪套 CONFIG（字 / 色 / logo），方便下期换皮直接抄
- 发布包三件套齐了才算交付完：**发布版视频（响度归一）+ 封面 + 发布文案**
