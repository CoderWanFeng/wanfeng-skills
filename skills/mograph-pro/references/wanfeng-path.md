# 晚枫成片打法 · wanfeng-path.md

> **这是 mograph-pro 的主规范。** 真人口播 / 文稿生成数字人混剪 → 有设计感的成片 + 封面。
>
> 真人设计基线来自真实成片（2-AI工具/20-混元hy4-flash，81.23s / 1080×1920@30）。
> 新增数字人分支按 [digital-human.md](digital-human.md) 执行；本地时间契约验证不等于人脸、口型与云端生成效果已验收。
>
> **历史真人版最终形态**：前 18.37s 语速 1.2×、开场为全屏设计版式（人脸在左下角）、
> 发布文件是 `-响度归一` 版（-14.4 LUFS / TP -1.0），母版留档。逐场结构见 §5.8。

---

## 0. 这条线是什么

**一句话**：这是晚枫工作室自己账号的专属剪辑打法 —— 不联网找现成动效代码、不装 Node、不起浏览器，
用 **Python + Pillow + ffmpeg** 手写场景表、逐帧自绘，把一条平铺的口播变成有版式、有节奏、有封面的成片。

| 你要什么 | 走哪条 |
|---|---|
| 按晚枫号的调性做一条成片（fs 全屏版式 + 圆形人头 + 步骤条 + 封面换皮） | **本文件** |
| 给任意口播做「通用包装」（正则在上下左右弹字卡，走 Remotion / HyperFrames） | 免费版 `mograph` skill |
| 只想要「删减」这一件事（把一口气录完的原片剪成干净底片） | 本文件 Step 0，**可以单独跑**（见 `references/cut-feature.md`） |
| 只想要「换封面」这一件事 | 本文件 Step H，**可以单独跑**（见 `references/wanfeng-cover.md`） |

**本线不检索外部动效代码，但素材照常联网找、照常做标注**（Step A2）——
「不检索」指的是不检索现成的 Remotion / HyperFrames 卡片实现，不是「不许上网」。

**本线不走通用的「正则命中 + slot 分配 + 联网找现成实现」那一套**，替换成本文件第 2 节的执行流
（Step 0 + 八步 A–H，其中 A 与 B 之间是 Step A2 配图素材采集）。

## 1. 为什么是「Pillow 自绘」而不是 Remotion / HyperFrames

这不是偏好，是环境逼出来的，也是**审美可控性**逼出来的。

| 维度 | Remotion / HyperFrames | 本线（Pillow 自绘） |
|---|---|---|
| 运行环境 | Node 18+ + 浏览器 | 只要 Python + Pillow + ffmpeg |
| 沙箱友好度 | Chrome / QuickLook 常被沙箱锁死，GPU 起不来 | 纯 CPU，一定能跑 |
| 版式控制 | 受框架 DOM / CSS 盒模型约束 | 像素级自由，1080×1920 上每一个 y 坐标都可控 |
| 依赖 | npm 生态，版本漂移 | 只有 Pillow，**零第三方 JS** |
| 出片质感 | 矢量、可无限缩放 | 2 倍超采样后下采样，中文字缘干净、无字体回退 |
| 迭代速度 | 改一个坐标要重启 dev server | 改完直接重跑，静态帧秒级出图 |

**结论**：晚枫号要做的是「设计感」而不是「动效炫技」，而且要在任何机器上都能复现出同一条片子 —— 自绘是唯一解。

**代价要认**：没有 CSS 动画曲线，要自己实现缓动（见 §4.3）；没有浏览器字体，中文字体只有 Hiragino Sans GB。

## 2. 执行流（Step 0 + 八步 A–H）

```
入口 · 选择来源               → 真人视频 / 文稿生成数字人（不能把文稿当现有视频）
画幅 · 是否生成宽屏           → 未明确则选一次：仅竖版 / 横竖双版 / 仅宽屏（aspect-ratio.md §1）
Step 0 · 确定文稿             → 真人先问删减；数字人无稿先协助写稿并确认
预分镜 · 按语义定 A/B         → 内容与素材需求，估时不当最终时间
数字人 · 准备完整素材         → plan → broll 配音试听 → digital 样段再补齐 → merge 回填
Step A · 定版式与设计令牌     → 抄 §3 §4，建 mograph-task 工程；按画幅写 CANVAS，坐标参数化（aspect-ratio.md §4）
Step A2 · 配图素材采集          → 按主题找图/截图/做标注，登记来源 → §2.3
Step A2-2 · 品牌 logo 自动采集  → 口播提到品牌名 → 自动取官方 logo 并上屏 → §2.4
Step B · 切场景表             → 按 §5 写 build_scenes()，逐句对齐 SRT
Step C · 静帧复核（秒级）      → 出 PNG 读图，改到干净再往下
Step D · 重渲全片             → 逐帧渲染 + ffmpeg 管道
Step E · 抽帧终检             → 每个场景抽一帧，逐张读图
Step F · 响度归一             → 两遍法 loudnorm，出发布版
Step G · 交接文档 + 交付       → 按 §9 写文档，给两个文件
Step H · 封面（换皮）          → 在混元封面底图上换字换 logo，人像不动 → references/wanfeng-cover.md
Step I · 小绿书贴图（可选）    → 问用户要不要；要则按 references/xiaolvshu.md 生成公众号图片消息贴图
```

**C 步之前不许进 D 步**。全片渲染 6 分钟起，版式问题在静帧上改只要几秒。

> **贯穿主线 + 支线：说什么出什么（W24）** —— 拿到**任意一份文稿**，Step B 切场景表时逐句标可视觉化锚点，
> 按 [`semantic-to-effect.md`](semantic-to-effect.md) 的映射表配一个**参数从该句抽取、真的会动**的效果基元，
> 并落盘逐句对照表验收覆盖。这不是 72 号专享，是给每个使用者的通用能力。

> **宽屏选择（W25）** —— 素材来源确认后，排版或数字人生成前，尚未明确画幅时问一次：仅竖版（推荐）、横竖双版、仅宽屏。选择宽屏后执行 [`aspect-ratio.md`](aspect-ratio.md) §4.7。
> 本文件 §3/§4/§5 的坐标都是**竖版 1080×1920 设计基准**，数值勿改（W7），
> 但要按 [`aspect-ratio.md`](aspect-ratio.md) §4 的 `CANVAS` 换算落位；**横版必须走左右分栏重排版，禁止拉伸竖版帧**。

> **支线：动画优先 · 两阶段成片（72 号实证）** —— 当素材是**已剪好成片 + 现成 SRT**、或用户要求**先看动画再定**、或要求**全片画面不能停超过 3 秒**时，
> 上面这条「一次出片」的流程不适用，改走 [`animation-first.md`](animation-first.md)：
> 阶段 ① 纯动画 Demo（跳过 Step 0、逐帧真动、全片节拍化、数据验证）→ **停下等用户确认** → 阶段 ② 真人层 + 声音 + 封面 + 发布包。
> 阶段闸是硬约束（W21）：未确认前不叠真人、不做封面/响度、不出「成片」口径。

> **A2 步为什么在 B 之前**：场景表里要写"截图面板"场景（§5.6），得先有图可截、有标注可画。
> 先切场景表再回头找图，会出现"这场没图可用"的白工。
>
> **A2 步不是晚枫路径的例外**。晚枫路径"不检索"指的是不检索外部动效**代码**，
> 素材（截图、配图）照常联网找、照常做标注 —— 见 §2.3 与 `references/visual-assets.md`。

### 2.2 Step H · 封面（成片交付后追加，必做）

用户长期约定：**以后所有选题的封面，都在混元封面底图上换字换 logo，人像一像素不动**
（「我以后都会穿那个衣服录视频」）。不重新设计、不从新视频抽帧自拼人像（该方案已被否决）。

完整打法（模板脚本 + 固定资产 + 三闸自检 + 踩坑清单）见 **`references/wanfeng-cover.md`**。
非宽屏封面放 `<选题根>/发布包/封面-XXX.jpg`；选了宽屏，另配独立横版封面，与横版视频一起放 `发布包/横版视频/`，文案可共用（[`aspect-ratio.md`](aspect-ratio.md) §4.7）。

### 2.1 Step 0 · 语义删减授权（拿到的素材是一口气录完的原始口播时）

**先解释，再让用户选择；不得默认开剪。**
向用户说明：

> 我可以先删除重录废稿、半截句和孤立口水词，并把过长停顿收紧到约 0.7 秒；默认保持内容顺序，不做重排。删减后我会给你一份完整保留口播稿，然后直接继续制作视频。是否允许？如果不允许，我会保持原片、原稿、内容顺序、停顿和时长不变，只做后续已授权的视频包装。

#### 用户允许删减

```bash
# 1) 出计划：JSON + 人可复核的 Markdown 报告
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --report plan.md

# 2) 读报告第四节「口播块全文」，逐条确认刀口认不认可

# 3) 认可就出底片
python3 scripts/cut_plan.py --video raw.MOV --out plan.json --apply base.mov
```

工具会识别四类问题并给出刀口（理由写在报告里）：

| 类别 | 判据 | 处理 |
|---|---|---|
| 重录废稿 | 相似度 ≥ 0.72 **或**短句是长句前缀；间隔 ≥ 1.2s | 删前一遍，**留最后一次** |
| 半截句 | 结尾是虚词/代词/连词且后面停顿 ≥ 0.8s | 删 |
| 孤立口水词 | 整句只有一个语气词，两侧都有停顿 | 删 |
| 长停顿 | 间隔 > 2.0s | **不删**，收紧到 0.7s |

**刀口只落在实测静音区间或整块上，绝不切半个字**（whisper 的句子边界会切在词中间，不能当刀口）。

底片完成后，agent 必须按最终保留内容整理 `clean-script.md`：一份从头到尾可连续阅读的
**完整保留口播稿**，并对照 `plan.json` 与 `base.mov` 复核；不能只给刀口、时间区间或删除清单，
`cut_plan.py` 也不会自动生成这份文稿。

把完整口播稿发给用户后，**不再等待二次确认，直接进入 Step A 继续制作视频**。
后续场景表、字幕与时间轴都以 `base.mov` 和 `clean-script.md` 为准，而不是原片。

#### 用户不允许删减

跳过整个 Step 0，不运行 `cut_plan.py` 生成删减方案或底片，不执行 `--apply` / `--reorder`。
原视频、音频、原稿、内容顺序、停顿和时长全部不动，直接以原媒体与原稿进入 Step A。
后续 §7 的提速也不执行，除非用户另行明确授权。

#### 素材是已剪好的成片 + 现成 SRT（支线例外）

**整个 Step 0 整步跳过**：不跑 `cut_plan.py`、不重新识别字幕、不做提速，原片 + 原 SRT **恒等映射**。
成片已删减过，再删会整体偏移，字幕与画面全部错位（72 号实证：用户明确「我这个已经删减过了，
你删减了之后和字幕就不匹配了」）。用户已提供识别好的 SRT 就直接用，不重识别。
详见 [`animation-first.md`](animation-first.md) §2.1。

#### 重排边界

「允许删减」不包含重排授权。使用 `--reorder` 把「成品展示」提到最前或进行任何其他调序前，
必须另行取得用户明确同意；未同意时一律保序。重排后字幕时间轴全部失效，Step B 的场景表必须重做。

规则细节、阈值表、走过的弯路见 `references/cut-rules.md`；
71 号的完整实证数据（30 块全表 / 25 句保留对照 / 删除量构成 / 阈值检验）已随包沉淀在
`references/cut-rules.md` §1.4 / §1.5。

**注意**：用户允许删减时，Step 0 出的底片是**干净但偏长**的（71 号实测保留 62.1%），
因为它只删语义废料、不做提速。开头提速 1.2× 仍然是 §7 那一步的事。

### 2.3 Step A2 · 配图素材采集

按口播主题找图、截图、做标注。**完整规范见 `references/visual-assets.md`**（找什么、去哪找、
怎么截图、来源怎么登记），这里只写晚枫路径特有的部分。

**先问用户一次**（不要拆成三轮追问）：

> 配图这块我确认三件事：① 有现成截图可以直接用吗（比如之前那批 WorkBuddy 界面截图）？
> ② 有没有链接或官网地址，我可以自己去截？③ 都没有的话，我按「<主题>」去网上找，
> 找不到就用动效顶上，可以吗？

**素材放哪**：`mograph-task/assets/`，另存 `asset-manifest.json` 登记来源
（URL / 截取日期 / `shows` 图上实际有什么 / `proves` 支撑哪句口播）。

**晚枫路径特有的三条**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **红框标注写进场景表，不烧进图片** | 红框由 Pillow 画在截图面板上（§5.6），同一张图能配不同段落；烧进图片就只能配一次 |
| 2 | **截图太扁就改自绘卡片**（§5.5） | 1000×187 的扁图硬塞进面板字看不清，红框会占满面板 |
| 3 | **`RED` 只用于红框**（§4.1） | 标注框和"重点强调"用同一个红，观众分不清哪个是哪个 |

**三条硬判据**（详见规范 §4，落到 W13）：图上出现的东西，必须正是那一句口播在讲的东西；
图上不可见的内容不能当证据；文件名、OCR 命中、目录里的现成文件都不等于证据成立。

**兜底**：真人找不到图 → 改成 `overlay` 文字卡/数字卡；数字人 B 段找不到图 → 实现全屏自绘说明 layers，不画人头，不能把占位底片当成品。
**绝不拿"看起来相关"的图硬凑**（71 号成片的截图全是对得上的，不能靠这条路补）。

### 2.4 Step A2-2 · 品牌 Logo 自动采集（口播提到品牌名 → 自动挂官方 logo）

口播里点了哪个品牌（GLM / MiniMax / WorkBuddy / Hy4-Flash…），就自动去下载那个品牌的**官方 logo**，
用进成片画面里——用户不用找图、不用给链接。

- **识别**：`scripts/brand_scan.py` 离线扫文稿 / SRT，出候选品牌表（置信度 + 首现句 + 本地是否已有）。
- **取件**：`scripts/brand_logo.py` 按品牌名扒官网（`og:logo` → `apple-touch-icon` → `favicon`），
  SVG 转 PNG、去白底、裁留白、登记 `asset-manifest.json`；取不到就退纯文字，**不拿近似 logo 硬凑**。
- **上屏**：三档（品牌角标 / 品牌卡 / 片尾聚合），尺寸、落点与避让规则见 **`references/brand-logo.md`**。
- **准确性**：与封面 logo 同一把尺子（W18 三关），落到 **W26**；每片上屏 ≤3 次。

### 3.2 环境（都是踩出来的，别改）

- **Python**：`~/.workbuddy/binaries/python/envs/default/bin/python3`（Pillow 12.x 在这里）
- **字体**：**只有 Hiragino Sans GB**（`/System/Library/Fonts/Hiragino Sans GB.ttc`，index 0=W3，index 2=W6），**没有 PingFang**
  - **实测字形覆盖（W3/W6 一致）**：`✓` `✦` **缺失，渲染成豆腐块，必须手绘**（对勾用多边形画，参考 `draw_check()`）；
    `→` `←` `↑` `↓` `①` `②` `③` **正常可用**，别白手绘箭头和圆圈数字
  - 判定方法：不要看 `font.getmask(ch).getbbox()` —— **缺字时 .notdef 方框也有 bbox**，必须真渲一张 PNG 用眼睛看
- **不要试图起 Chrome / QuickLook**：沙箱锁死，GPU 起不来
- **渲染必须后台直跑 python 命令**，不要 `&` + nohup 分离（会被回收）
- **超采样**：所有绘图先在 2 倍画布上做，常量 `S = 2` 是乘数。竖版 1080×1920 时是 2160×3840；
  换画幅后画布 = `(W*S, H*S)`（`W/H` 见 `aspect-ratio.md` §4 的 `CANVAS`）。
  `text()` / `pill()` / `shadow_rrect()` 内部已乘 S，**坐标直接用「最终目标画布」坐标**；
  自己用 `ImageDraw` 画时必须手动 `x * S`。本节所有 1080×1920 坐标是**设计基准**，换画幅按 `CANVAS` 换算落位、勿改数值（W7 / W25）

### 3.3 两套 Python 环境（最容易搞混）

| 解释器 | Pillow | 干什么 |
|---|---|---|
| `/usr/bin/python3` | 11.3.0 | 早期脚本（`build_mg_v3.py` / `mux_audio.py`） |
| `~/.workbuddy/binaries/python/envs/default/bin/python3` | 12.x | **本路径的渲染器**（`render_full.py`）、numpy 可用 |

报错 `No module named 'PIL'` = 用错解释器了，换另一个，不是装包。

## 4. 设计令牌（用户已确认，勿改）

> **坐标是「竖版 1080×1920 设计基准」上的绝对像素**（`SUB_TOP`、圆头圆心/半径、卡片锚点、安全区边距…）。
> 这些数值**一律不改**（W7）。换画幅时不是改数值，而是按 [`aspect-ratio.md`](aspect-ratio.md) §4 的
> `CANVAS`（`SX/SY/K` + 安全区比例）**换算落位**：竖版族纵向重分布、横版族走左右分栏重排版（禁止拉伸）。
> 配色 / 字体 / 节奏等**令牌值**在任何画幅下都相同，只有「坐标怎么落到画布」随画幅变。

### 4.1 配色

> **权威文件**：每条选题自己的 `AI剪辑输出/动效样式规范.md` 是当次确认过的风格定稿，
> 本节是它的可执行版本。两者冲突时以规范文件为准，并回头把本节改对。
> （当次的规范文件不随包分发；本节是随包提供的默认基线。）

| 令牌 | 值 | 用途 |
|---|---|---|
| `INK` | `(8,11,15)` | 最深底 |
| `TEXT` | `(243,246,248)` | 正文白 |
| `DIM` | `(168,178,188)` | 次要说明 |
| `ACCENT` | `(0,214,147)` | **品牌绿**，主强调（标题强调、刻度条、chip、步骤条高亮） |
| `AMBER` | `(255,194,75)` | **只**用于「限时免费」这类利益点 |
| `RED` | `(255,93,93)` | **只**用于截图上的标注框 |

> **配色定调历史（重要）**：整片曾完整试过一版「暖咖底 + 橙金强调」（INK `(26,18,12)` / TEXT `(250,244,236)` /
> ACCENT `(255,132,62)`），出样片后**用户明确否决，要求回退到冷深蓝 + 品牌绿**。
> 所以：**不要再主动提议暖色方案**，也不要因为「某条片子看起来更暖」就改令牌。W7 是结果，这段是原因。

**卡片**：`shadow_rrect`，圆角 46（产品速览卡 44），填充 `rgba(10,13,18,.96)`，白描边 + 大投影（blur 44 / off (0,26) / alpha 190）。卡片左侧一道绿色刻度条（6 段递减透明度，radius 4）。

**字幕条**：圆角 = h/2，深色 `rgba(9,12,16,.85)`，白描边 `alpha 30`，投影 blur 26 / off (0,14) / alpha 140。

### 4.2 字幕规范

### 4.3 动效节奏

| 元素 | 规格 |
|---|---|
| 卡片入场 | 统一 240ms 淡入 + 420ms 上滑（`ease-out-quint`） |

## 5. 版式库（照抄即用）

### 5.0 来源与 A/B 维度

两线都先由 Agent 按语义预分镜，不按关键词定案，不硬套出镜占比。真人先基于授权删减后的保留内容分镜；数字人先确认标记稿再配音，出镜视频只做 A 段。

| 来源 | A-roll | B-roll | 声音 |
|---|---|---|---|
| 真人 | 原底片 + 动效，或 `fs` 圆形人头 | 素材为主 + 圆形真人，人物始终可见 | 原口播音轨 |
| 数字人 | 数字人底片 + 动效，或 `fs` 圆形人头 | 全屏截图/录屏/图表/MG，无人头 | 全部 A/B 台词连续配音 |

`roll=a|b` 是内容侧重点，`presenter=full|circle|none` 是人物可见性，与 `mode=overlay|fs` 独立。以下历史示例仍为真人基线；数字人 B 的 `fs` 保留标题、主体、步骤条和品牌语言，但不得画人头。

### 5.1 两种模式

| mode | 含义 | 用在哪 |
|---|---|---|
| `overlay` | 真人画面打底 + 叠加一张卡 | 中段观点 / 数字 / 清单 |
| `fs` | **全屏设计版式**（背景 + 标签 + 标题 + 主体 + 步骤条 + 圆形人头） | 开场、操作步骤、截图演示 |

**`fs` 版式就是晚枫号最漂亮的那个排版**，用户原话：「目前这种有人脸、有步骤、有背景色和字的排版，我觉得是最漂亮的。」

### 5.2 `fs` 全屏设计版式分层（自上而下）

```
  60,190 ┌ 绿色/琥珀小标签        「第 1 步」「剪视频 · 第 1 步」「今天发布」
  56,320 ├ 标题行 1（白 62-66）
  54,404 ├ 标题行 2（白 66）
  54,470 ├ 标题行 3（绿强调 72-76）
  40,590 ├ 主体：自绘卡片 / 截图面板（圆角 34 + 红框标注）
      ~1040 ├ 主体底
  1280 ├ 底部步骤条 step_row(["…","…","…"], 高亮下标, 1280)
  1572 ├ 字幕（默认位置；镜头在左下角人头的开场场景用 sub_dy=-430 上移到 1142）
  1390 ├ 圆形人头顶边（右上：中心 y=268；左下：中心 y=1610，顶边正好 1390 落在步骤条下）
```

> **字幕的 1572 是默认值，不是固定值**：只有「人脸在左下」的开场场景才把字幕上移到 1142，
> 其余场景一律 1572。别把 1142 抄到全片，否则字幕会飘在画面中间。

### 5.3 圆形人头

| 项 | 值 |
|---|---|
| 源帧裁切 | 历史真人素材为 `(505, 655) r = 500`；新真人/数字人素材必须实测，禁止照抄 |
| 默认位置（右上） | `(812, 268) r = 236` |
| 开场位置（左下） | `(250, 1610) r = 220` |
| 描边 | 白色 alpha 90，宽 3.2 |
| 投影 | ellipse 下移 18，alpha 150，blur 26 |

**位置与半径是场景级参数**，不要写死在渲染循环里 —— 渲染循环读 `sc["head_pos"]` / `sc["head_r"]`，由 `add()` 传进来。

#### 源裁切包络：头顶和下巴都要留余量

- 源裁切圆不是「贴脸框」：头顶上方、下巴下方与左右脸外侧都要留运动净空；**下巴不是圆底，头顶也不是圆顶**。
- 新素材先画 100px 刻度网格，在开场、中段、结尾及点头 / 转头等动作最大帧，读取头顶 y、下巴 y 与左右脸 x 的多帧包络，再定 `(cx, cy), R`。垂直方向必须满足 `cy - R < min(头顶 y) - 上方余量`、`cy + R > max(下巴 y) + 下方余量`，且余量不得为 0；左右同理。禁止用单帧「刚好包住下巴」的参数。
- 定参后把同样时间点渲染成圆头静帧并逐张读图；任何一帧下巴 / 头顶贴边或被裁，都先改源裁切，再进全片渲染。

#### 手机安全区（视频号发布后实测反馈，2026-11-20 · 勿忽略）

> **画幅适配（W25）**：下面这组 `≥180px / ≥320px` 是**竖版 1080×1920** 的实测像素，仅作默认档基准。
> 换画幅一律用**百分比**：`aspect-ratio.md` §2.3 通发安全区取各平台并集（顶 12% / 底 20% / 右 15% / 左 8%），
> 1080×1920 下即顶 ≥230 / 底 ≥384 / 右 ≥162 / 左 ≥86px，比本节的视频号单平台线更严，取更严者。
> 横版（16:9）播放器 UI 轻，安全区约顶 8% / 底 10% / 左右 6%，并走左右分栏骨架（`aspect-ratio.md` §4.4）。

竖版 1080×1920 在**手机播放器**里：底部约 17%（y>1600 一带）会被视频号自己的 UI 盖住
（进度条、文案、点赞列），顶部贴边看着像切头。72 号发布后用户逐帧反馈：

| 位置 | 历史值（踩坑实证） | 问题 | 安全区参考 |
|---|---|---|---|
| 右上 | `(858,232) r200`（72 号） | 顶边仅 32px，贴顶「看起来很奇怪」 | 圆心 y ∈ [380, 480]，**顶边距画面顶 ≥ 180px** |
| 开场左下 | `(250,1610) r220`（71 号沿袭） | 底边 1830，被手机底部 UI 遮住，「有的手机都看不见」 | 圆心 y ∈ [1300, 1450]，**底边距画面底 ≥ 320px** |

- 圆头整体**往画面垂直中带收**；横向贴左右边可接受，用户抱怨的只有上下两端。
- 上表参考值**不是拍板值**：每期按实测人脸坐标渲染静帧、**画安全区框读图复核**后再定。
- 开场左下上移后若与上移字幕（`sub_dy=-430` → 条顶 1142）冲突：优先挪字幕 / 缩半径，
  **不许把圆头压回底边**换净空。

### 5.4 步骤条 `step_row(labels, highlight_idx, y)`

底部一行 3 段引导，当前步高亮（ACCENT 绿），其余压暗。**所有 `fs` 场景都要有**，这是版式的固定零件。

### 5.5 自绘卡片（截图看不清时改自绘）

截图裁出来太扁（比如 1000×187）字看不清时，**不要硬塞截图**，改成自绘卡片模拟 UI：
指令卡 = 输入框（技能名 → 「给我剪辑这个视频：」→ 两行路径 → 底部 ＋/模型胶囊/绿色发送按钮）。

### 5.6 截图面板与红框标注

| 项 | 规格 |
|---|---|
| 面板 | 圆角 30 + 白描边 + 投影 |
| 红框 | 6px、圆角 9、红色柔光；**只框一行，不压相邻行** |
| 裁切 | 先裁掉无用区域再缩放（`rounded_image(crop=...)`），别把 187px 高的扁图拉到 1000px 宽 |

### 5.7 小胶囊（pill）的配色铁律

`pill(img, xy, label, size, bold, fg, bg, border, ...)` 的 **fg 必须跟着 bg 走**，四种配对只有四种合法组合：

| 胶囊类型 | bg | fg | 用在哪 |
|---|---|---|---|
| 实心利益点 | `AMBER` 实心 | 深棕 `(38,27,2)` | 「限时免费」 |
| 描边弱标签 | 深色半透明 | `AMBER` 或 `TEXT` | 「本条视频」「还没装？」 |

| 描边强调 | `ACCENT + (26,)` | 亮青 `(155,240,212)` | 「我免费发布的技能」 |

> **踩过的坑**：悬念卡那个「↓ 看到最后」用了「实心琥珀」的前景色 `(40,29,3)` 配「深色半透明」的底，

## 6. 场景表写法

新扩展场景用 `wanfeng-scene-plan@2`。旧 `@1` 可用包内 `digital_contract.normalize_plan()` 读取，保持原时间、版式、head；默认 roll=a 只是待语义确认占位，正式场景须补充分类。
数字人完整时间轴从 `a_roll.json` 导入，读取配套 SRT、保留每段 index/kind/start/end/duration 和实际音视频路径。B 不要求数字人视频。不得按真人 5–12 秒规则跨 A/B 重组。
数字人渲染分支参考 `templates/digital_render.example.py`，启动全片前必须以实际注册的 layers 调用 `validate_render_plan(..., final=True)`，阻断缺素材和未实现 B 场景。

### 6.1 `add()` 的完整签名（真人时间映射）

```python
def add(t0, t1, mode, layers, head=False, bg=True, name="",
        head_pos=None, head_r=None, sub_dy=0):
    scenes.append(dict(
        t0=map_t(t0), t1=map_t(t1), mode=mode, layers=layers,
        head=head, bg=bg if mode == "fs" else None, name=name,
        head_pos=head_pos or HEAD_C, head_r=head_r or HEAD_R,
        sub_dy=sub_dy))
```

| 参数 | 作用 |
|---|---|
| `t0 / t1` | **原始口播时间**（不是成片时间，内部会过 `map_t()`） |
| `mode` | `"overlay"` / `"fs"` |
| `layers` | 图层元组列表 |
| `head` | 是否加圆形人头 |
| `head_pos` / `head_r` | 人头位置与半径，场景级覆盖 |
| `sub_dy` | 该场景字幕整体垂直偏移 |

### 6.2 场景表铁律

1. **一个场景讲一件事**。一段口播 = 一个场景，别把三件事塞一张卡。
2. **overlay 与 fs 交替**：连续 2 个 overlay 之后建议插一个 fs，防止整片都是「真人 + 居中卡」显得单调。
3. **`fs` 场景必须配步骤条**，否则和 overlay 没区别。
4. **人脸位置跟着内容走**：人脸在右上时，卡片避开右上；人脸挪左下时，字幕要上移（`sub_dy`）让位。
5. **真人相邻卡片可留 0.1–0.2s 空档**；数字人基础镜头及 A/B 场景覆盖必须连续，无空档，不得短暂露出占位底片。
6. **每句可视觉化表达都要配一个真动的效果**（W24）：手写 `build_scenes()` 时同步按 `semantic-to-effect.md` §3 §4 查基元、抽参数，别只贴静态卡、别把上一期的数值写死。

## 7. 语速调整（只改开头几秒时必读）

**数字人默认保持 1.0×**，其完整时间轴已由配音实测；不得套用本节历史真人的 1.2×。只有另获授权才同时变换音频、视频、字幕、场景，并重验口型。真人拒绝删减时也不提速，除非另获明确授权。

**提速不是只改音频** —— 画面时间轴必须同步压缩，否则从加速边界起整片音画错位。

### 7.1 底片预处理

```bash
ffmpeg -y -v error -i "原底片.mov" -filter_complex "
[0:v]trim=0:18.37,setpts=(PTS-STARTPTS)/1.2,fps=30[v1];
[0:a]atrim=0:18.37,asetpts=PTS-STARTPTS,atempo=1.2[a1];
[0:v]trim=18.37,setpts=PTS-STARTPTS,fps=30[v2];
[0:a]atrim=18.37,asetpts=PTS-STARTPTS[a2];
[v1][a1][v2][a2]concat=n=2:v=1:a=1[v][a]" \
-map "[v]" -map "[a]" -c:v libx264 -preset medium -crf 18 \
-pix_fmt yuv420p -c:a aac -b:a 192k "原底片-fast.mov"
```

`atempo` 是 WSOLA 时间拉伸，**保音高**（实测基频 115.1Hz → 115.1Hz）。

### 7.2 时间轴映射

```python
FAST_UNTIL = 18.37          # 落在某个场景边界上，跨界字幕正好被压紧
FAST_RATE  = 1.2
FAST_SHIFT = FAST_UNTIL * (1 - 1 / FAST_RATE)   # 3.0617s

def map_t(t):
    if t <= FAST_UNTIL:
        return t / FAST_RATE        # 压缩
    return t - FAST_SHIFT           # 整体前移

def map_span(s, e):
    if e <= FAST_UNTIL:  return s / FAST_RATE, e / FAST_RATE
    if s >= FAST_UNTIL:  return s - FAST_SHIFT, e - FAST_SHIFT
    return s / FAST_RATE, e - FAST_SHIFT   # 跨界：两端各取映射值，区间自然压紧
```

- 场景用 `map_t()`，字幕用 `map_span()`
- **改语速的完整流程**：改 `FAST_RATE` / `FAST_UNTIL` → 重生成 fast 底片 → 改 `map_t()` 里的分界与位移 → 重渲
- **只改 `render_full.py` 不同步重生成底片，一定音画错位**

### 7.3 提速后要验证的两件事

| 验证 | 方法 | 合格线 |
|---|---|---|
| 音画同步 | `ffmpeg -af silencedetect=noise=-32dB:d=0.22` 提取语音停顿点，与 `map_t()` 预测值比对 | 误差 < 80ms |
| 音高没变 | numpy 自相关估基频（40ms 窗 / 10ms 跳，lag 60–400Hz） | 与原片一致 |

## 8. 渲染与交付

### 8.0 交付前第一件事：验证文件是不是完整（血泪）

后台渲染任务会被**会话压缩 / 任务回收**打断，而 ffmpeg 是边写边封装的：
进程被杀时 mdat 写了一堆、**moov atom 没写** → 文件 40-50MB 看着像正常，实际：

```
$ ffprobe 成片.mp4
[mov,mp4,...] moov atom not found
...Invalid data found when processing input
```

**这种情况不报错、不退出、文件大小还在涨**，最容易误判成「渲染完成」。

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 成片.mp4
# 必须 ≈ 预期时长（如 81.3），报 moov 缺失 = 废片，删掉重渲
```

教训：本片第一版渲到 22:48 被会话压缩杀掉，产出 41MB 废片，白等 20 分钟。
**渲染完先 ffprobe，再谈内容。**

### 8.1 静帧复核（先做这步）

```bash
cd ".../mograph-task"
~/.workbuddy/binaries/python/envs/default/bin/python3 -u src/render_full.py stills 2,8.5,15.5,32.5
```

输出 `t002.0.png` 等到 `/tmp/qc/`。**必须用 Read 工具真的把图读出来看**，不能只看脚本打印。

**这就是本线的"样片"机制**：静帧秒级出图，改版式只要几秒，而全片要渲 6 分钟。
用户想要一段**能播的**短样片时，同样按"只渲这一小段、不渲全片"的原则做
（默认 5–10 秒，用户可指定时长），确认后再进 D 步。

### 8.2 重渲全片

```bash
~/.workbuddy/binaries/python/envs/default/bin/python3 -u src/render_full.py full
```

- 输出直接写到交付目录，覆盖旧片
- 全片约 6 分钟（2500 帧量级）
- 真人历史日志末尾 `frame short at N 0` 曾是底片差几帧的 EOF；数字人完整时间轴必须验实际帧数与总时长，缺帧不能一律当正常

### 8.3 终检抽帧

每个场景抽一帧 → 拼成 contact sheet → **逐张读图**。只看一帧不算终检。

### 8.4 响度归一（两遍法）

母版原声通常在 -22 左右 LUFS，直接发会被平台压。归一用 `loudnorm` 两遍法：

```bash
# 第一遍：量
ffmpeg -i 母版.mp4 -af loudnorm=I=-14:TP=-1.0:LRA=11:print_format=json -f null -

# 第二遍：回填 input_i / input_tp / input_lra / input_thresh + target_offset，加 linear=true
ffmpeg -i 母版.mp4 -af "loudnorm=I=-14:TP=-1.0:LRA=11:linear=true:measured_I=..:measured_TP=..:..." \
  -c:v copy -c:a aac -b:a 192k 发布版.mp4
```

- 第二遍务必加 `-c:v copy`，画面逐帧不变，不要重渲染
- 成片实测目标：**-14.4 LUFS / TP -1.0 dBTP**
- 交付两个文件：母版（留母）+ `-响度归一` 版（对外发）
