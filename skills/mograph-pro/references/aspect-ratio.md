# 视频比例设置（竖版 / 可选宽屏 / 各平台）

> 完整成片流程必须有一次**是否生成宽屏**的选择；通用竖版 9:16 / 1080×1920 是推荐项，宽屏 16:9 / 1920×1080 只在明确选择后制作。已经明确画幅的请求不重复问。

---

## 1. 什么时候问、怎么问

| 情况 | 动作 |
|---|---|
| 新做完整成片或正式样片，未说明要不要宽屏 | 确认素材来源后、开始排版或数字人生成前，主动问一次，等回答再锁定画幅 |
| 明确说「只做竖版」「不出横版」或仅指定非横版成片比例（如「做成小红书 3:4」） | 记录为仅所选非横版；不重复问、不顺带导出宽屏 |
| 明确说「只做横版」「换成 16:9」或「发 B 站横屏」 | 记录为仅横版；默认 16:9 / 1920×1080，不重复问 |
| 明确说「横竖都要」「另做/加一版横版」 | 保留或制作竖版，同时独立制作横版；已有竖版不覆盖、不重渲 |
| 只说平台且横竖都有可能（如「发 B 站」） | 同一轮把平台和宽屏选项一起确认，不从平台名擅自推断 |
| 只改字幕、封面、动效或现有视频的一处 | 继承已有画幅，不因局部修改重问或新导其他版 |

**直接用这句问，一次选定**：

> 这条要不要出 **16:9 宽屏版**？① 只做竖版 9:16（推荐）；② 竖版 + 宽屏各一份（如 B 站横屏）；③ 只做宽屏 16:9。已有指定平台或比例也可以直接告诉我。

把结果写进本次任务或分镜说明，例如 `outputs=vertical`、`outputs=vertical+landscape`、`outputs=landscape`，并附各自的画幅档位。**未答复不当作选择宽屏**；完整成片流程先等选择，再做影响画幅的工作。如果用户说「按默认」，记录为仅竖版。专项参数见下表，不把 B 站与 YouTube 的每个预设再抛一遍。

## 2. 选项总表

### 2.1 通用档（面向"通发"，首选）

| 选项 | 代号 | 比例 | 分辨率 | 面向 | 说明 |
|---|---|---|---|---|---|
| **通用竖版**（默认） | `vertical` | 9:16 | **1080×1920** | 国内短视频全平台 | **一次出片通发**：抖音 / 快手 / 微信视频号 / 小红书 / B站竖屏 / YouTube Shorts 都能直接用（§3） |

### 2.2 平台档（面向"明确指定"）

| 平台 | 代号 | 比例 | 分辨率 | 备注 |

> **平台档其实是"通用档 + 该平台 UI 安全区 + 封面策略"**，绝大多数共用同一份 9:16 或 16:9 画布。
> 不要为每个平台各导一版文件（除非用户明说要多版本）；一个通发版 + 平台上自身的裁切即可。
> 规格来自各平台创作者公开指南的整合值（2026-11 核实），平台会调整，**发布前以官方当期说明为准**；本表是渲染默认基线，不是法律/合规文件。

### 2.3 各平台 UI 安全区（竖版，占画面比例）

平台会在画面上叠 UI，字幕 / 人脸 / 关键数据必须躲开。下表是遮挡区，不是可用区：

| 区域 | 抖音 / 快手 | 视频号 | 小红书 | 通发取值（并集，最保守） |
|---|---|---|---|---|
| 顶（账号/搜索） | ~10–12% | ~12% | ~10% | **12%** |
| 底（文案/进度/按钮） | ~18–20% | ~18% | ~15% | **20%** |
| 右（点赞/评论/分享） | ~15% | ~15% | ~10% | **15%** |
| 左 | 少 | 少 | 少 | **8%** |

换成 1080×1920 像素：顶 ≥230px、底 ≥384px、右 ≥162px、左 ≥86px。
**通发版一律按最右列**（取并集），这样一个文件发到任何平台都不被挡。
这与 W22 的圆头「顶≥180 / 底≥320」不冲突：W22 是**视频号单平台**的圆头最低线，通发安全区是**全平台、全部关键内容**的线，取更严者（顶≥230 / 底≥384）。具体换算见 §4.5。

## 3. 一次出片通发国内（默认口径）

**结论：9:16 / 1080×1920 是国内主流短视频平台的最大公约数。**

- 抖音、快手、视频号、B站竖屏、YouTube Shorts 主推画幅都是 9:16；小红书信息流虽偏 3:4，但同样接受 9:16 满屏。
- 所以晚枫日常剪片，**做一条通用竖版 9:16，就能一次发国内各平台**，不用一平台一版。
- 代价只是留白更保守：按 §2.3 的**并集安全区**排版，牺牲一点边缘空间，换来全平台都不被 UI 盖住。
- 横版内容（B站横屏 / YouTube 长视频）是**另一条片子**，不在"一个视频通发"范围内 —— 横竖是两种构图，不能靠一个文件兼容（§4.4）。若用户真要一稿多投，做法是「竖版通发国内 + 另出横版给长视频平台」，且横版必须重排版，不是裁竖版。

## 4. 画布配置 CANVAS（渲染契约，最重要的一节）

### 4.1 为什么必须参数化

`wanfeng-path.md` §3.2 / §4 / §5 的所有坐标都是**竖版 1080×1920 上的绝对像素**：
`SUB_TOP=1572`、圆头 `(812,268) r236`、超采样 2160×3840、安全区顶 180 / 底 320。
这些值是用户四轮反馈收敛出来的**设计基准**，**不改数值**（W7）。但如果渲染器把 `W,H` 写死，选横版就会：
① 画布不对；② 直接等比拉伸 → 圆头变椭圆、文字压扁、卡片出界；③ 竖版专属安全区数字失效。

所以引入 **CANVAS 配置**：一份基准 + 一个目标画布，所有坐标经换算后再画。

### 4.2 设计基准与两套布局骨架

```python
# render_full.py / design.py 顶部，按本次选定的档位填
BASE_W, BASE_H = 1080, 1920          # 设计基准（勿改，所有既有坐标都在这上面）
CANVAS = {
    "preset":   "vertical",          # 档位代号，见 §2
    "W": 1080, "H": 1920,           # 目标画布
    "S": 2,                          # 超采样倍数，画布 = (W*S, H*S)
    # 通发安全区（占画面比例，见 §2.3 并集）
    "safe_top": 0.12, "safe_bottom": 0.20, "safe_right": 0.15, "safe_left": 0.08,
}
SX, SY = CANVAS["W"] / BASE_W, CANVAS["H"] / BASE_H
K = min(SX, SY)                      # 字号 / 线宽 / 圆角 / 半径统一缩放系数（保比例，不拉伸）
```

**两套骨架，不是两种缩放**：

| | 竖版族（9:16 / 3:4 / 1:1） | 横版族（16:9 / 4:3） |
|---|---|---|
| 布局 | 沿用 `fs` 全屏分层：标签 + 三行标题 + 主体卡 + 底部步骤条，**上下堆叠** | **左右分栏重排**：左列标题 + 圆头，右列主体卡；步骤条横置底部，字幕条居中靠下 |
| 坐标 | 基准坐标按 `SY` 纵向重分布（§4.3） | **禁止套用竖版坐标**，按横版专用锚点重排（§4.4） |
| 关键差异 | 3:4 / 1:1 垂直空间变短，标题区与卡片区压缩、字号随 `K` 缩 | 横向空间富余，卡片可并排、数据卡更宽；**不要再顶天立地堆三行大标题** |

### 4.3 竖版族：基准坐标缩放与纵向重分布

- **横向**：`x' = x * SX`，宽度 / 半径 `r' = r * K`（圆头保持正圆，用 `K` 不用 `SX`）。
- **纵向**：不能一律 `y * SY`（3:4 / 1:1 会把字幕和卡片挤没）。按三段锚点重分布：
  - 标题区贴 `safe_top`；字幕条贴 `safe_bottom` 上方；主体卡在两者之间按可用高度居中。
  - `SUB_TOP` 不再写死 1572，改为 `SUB_TOP = H * (1 - safe_bottom) - sub_h - gap`。
- **字号 / 线宽 / 圆角 / 描边**统一乘 `K`；`text()` 基线锚点口径（W2）不变。
- **超采样**：画布 = `(W*S, H*S)`；`text()/pill()/shadow_rrect()` 内部已乘 `S`，坐标仍用**目标画布**坐标；自绘元素手动 `x*S`。

### 4.4 横版族：重排版，禁止拉伸竖版

**硬约束（会写进 W25）**：横版**不许**把竖版 1080×1920 的帧等比缩放 / 加黑边 / 直接裁切来凑。9:16 → 16:9 是构图变化，不是尺寸变化。

横版专用骨架（相对 `W,H` 的比例锚点，非绝对像素）：

| 元素 | 横版锚点（占 W/H 比例） | 说明 |
|---|---|---|
| 圆形人头 | 圆心 `(0.24W, 0.44H)`，半径 `0.30H` | 左列偏上，正圆（半径按 H 算） |
| 标题区 | 左列 `x ∈ [0.08W, 0.46W]`，顶部 `0.16H` 起 | 两到三行，字号按 `0.062H` 基准 |
| 主体卡 | 右列 `x ∈ [0.50W, 0.92W]`，垂直居中 | 横向空间够，卡片可更宽 / 双卡并排 |
| 数据卡 / 柱状图 | 右列，宽度可到 `0.40W` | 横版更适合多柱对比（`grow_bar` 基元） |
| 字幕条 | `x = 0.5W` 居中，`y = 0.82H` | 底部字幕条不贴边，横版 UI 遮挡主要在底部 ~10% |
| 步骤条 | 底部 `0.92H` 横置 | `fs` 场景仍必须有（W4） |
| 安全区 | 顶 0.08 / 底 0.10 / 左右 0.06 | 横版播放器 UI 比竖版轻，取播放器通用值 |

- 横版 `K = min(SX, SY)` 会很小（`SY=0.5625`），**不要用它去缩竖版字号**：横版字号按 `H` 重定（`0.062H` 等），与竖版字号体系独立。
- 圆头素材仍从当前原片帧**实时裁**（W22）；横版圆头半径按 `0.30H`，位置和竖版一样要**静帧画安全区框复核**。
- 效果基元（`semantic-to-effect.md` §4）横竖通用，只是布局锚点换一套；参数依旧从文稿那句抽、不写死。

### 4.5 安全区 / 圆头 / 字号换算速查

| 项 | 竖版 1080×1920（基准，勿改） | 换到任意画布 |
|---|---|---|
| 通发安全区 | 顶 230 / 底 384 / 右 162 / 左 86 px | `H*0.12 / H*0.20 / W*0.15 / W*0.08` |
| W22 圆头最低线 | 顶≥180 / 底≥320 px（视频号实测） | 按 `H/1920` 换算，且**不得松于**通发安全区 |
| 圆头 | `(812,268) r236` / 开场 `(250,1610) r220` | 圆心按锚点重定位、半径 `r*K`；**每期仍须画网格实测**（W22），换算值只是起点 |
| 字幕条 | `SUB_TOP=1572` / 字号 56 | `H*(1-safe_bottom)-sub_h-gap` / 字号 `56*K`（竖版）、`0.062H` 系（横版） |
| 超采样 | 2160×3840（`S=2`） | `(W*S, H*S)` |

> **实测优先于换算**：任何比例下，圆头坐标 / 安全区都要在静帧上画框读图复核（§6），换算公式只给起点，不替代实测。

### 4.6 与现有规范、引擎、封面的接口

- **不擅改 W7 设计令牌**：保留已确认的底色、品牌色、字体和节奏；宽屏的语义辅助色是新增的局部强调层，不替换基础令牌，做法见 §4.7。
- **主规范**：`wanfeng-path.md` §3.2 超采样、§4.2 字幕、§5.3 圆头与手机安全区，全部按本节换算；原文保留竖版基准数值作为默认档。
- **数字人引擎**：`--aspect` / `RATIO_SIZES`（9:16 / 16:9 / 1:1 / 3:4 / 4:3 / 21:9）与 `scene_plan(aspect=...)` 的档位**必须与本 CANVAS.preset 一致**，不能 A 段竖、B 段横。H3 自托管 REF2VA 当前固定 832×480 / 16:9（见 `digital-setup.md`），竖屏需另做构图，不声称原生任意画幅。
- **封面（W12）**：竖版固定底图换皮；确认做宽屏后默认配独立横版封面（用户明确只要视频时除外），按 §4.7 沿用同一肖像，不拉伸、不重截。

### 4.7 宽屏专项（74 号经验）

1. **保留操作截图的上下文。** 用户提供完整操作图时，右栏按原比例先展示完整原图，再在原图坐标上加红框/箭头，指明按钮、菜单、下拉框、文档入口和表单位置。文字过小，用并排局部放大窗或短时推近，保留或先交代全景与目标的关系；不能整段只给局部。核对标注对应口播，不遮目标字，不对截图整体调色；有真实密钥、账号等敏感信息先遮盖，再展示其余界面。
2. **固定署名，不替换章节。** 晚枫工作室横版左上原来放「开场」「这期讲什么」的动态小标签，统一固定为 **「程序员晚枫」**，不随镜头换字或换色。相邻 `01/06` 一类章号（分母按实际章数），以及底部步骤条、字幕、正文照原逻辑。非晚枫账号勿默认用此署名，按用户提供的品牌名或不加。
3. **配色为内容服务。** 保留冷深蓝底、品牌绿署名和主要导航；允许按语义给标题关键词、卡片、节点、进度等动效加辅助色。例：淡金标免费权益、玫瑰提示额度不足、浅蓝给步骤、淡紫给模型或互动。按镜头实际含义选色，不把例子或 74 号数值硬套到新选题；每拍以一种强调色为主，既有红框、截图色、人物肤色和字幕可读性不受影响。不要满屏调色、彩虹轮换或仅靠颜色传达信息。对已交付的成片调整配色时，先另出预览，确认后再替换发布版。
4. **独立封面，沿用同一肖像。** 16:9 横版封面独立排版，默认 1920×1080。同一选题有已确认的竖版正式封面时，直接从竖版成品取**同一张人像、同一表情**，只等比裁切和换位置；不换成同人不同帧、补发丝参考帧或视频截图。如果只做横版且没有已确认竖封面，用用户确认的固定肖像资产，不擅自截视频。
5. **横版独立归档。** 发布视频和横版封面放 `<选题根>/发布包/横版视频/`；竖版三件套留在 `发布包/` 根，文案可共用。原片、预览/母版、静帧、脚本、旧版、交接和验收放同级 `剪辑过程/` 或独立工程。同步设置视频和封面脚本的输出路径；不覆盖已有竖版或未经确认的发布版。共享已确认的文稿、时间轴、旁白和截图源，按画幅重排并分别验收；数字人后端如不支持对应画幅，先说明并确认，不混用 `--aspect`。

## 5. 验收闸（Step C / E 各加一道）

- [ ] `ffprobe` 验成片**分辨率 == CANVAS 的目标 W×H**，不是 1080×1920 就算完（W9 之外再加一条）。
- [ ] Step C 静帧上**画安全区框**读图：所有标题 / 字幕 / 圆头 / 关键数据都落在通发安全区内（§2.3 并集）。
- [ ] **横版专项**：确认走的是左右分栏骨架，没有出现「竖版帧被拉伸 / 圆头变椭圆 / 三行大标题顶天立地 / 大片黑边」。
- [ ] 圆头在选定比例下**画网格实测**过，不是套竖版坐标（W22）。
- [ ] 数字人 `--aspect` 与 `CANVAS.preset` 一致；横版有独立封面，使用同一选题竖版成品的确切肖像或用户确认的固定肖像。
- [ ] 横版抽查完整操作图、标注准确、署名固定且章号不受影响、动效色彩有层次且截图/肤色不偏；发布包与过程文件分开。
- [ ] 若用户要「多版本」，每版都单独跑一遍以上闸口，并写进交接文档「本轮改了什么」。

## 6. 踩过的坑

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | **把竖版 1080×1920 等比缩放成 16:9** | 圆头变椭圆、文字压扁、卡片出界，整片报废 | 横版走左右分栏重排（§4.4），禁止拉伸 |
| 2 | **竖版安全区绝对像素（顶180/底320）直接用到横版** | 横版 1080 高，顶180=17%、底320=30%，过度留白 / 或反过来被字幕条盖住 | 安全区一律用**百分比**（§4.5） |
| 3 | **为每个平台各导一版** | 白渲 N 遍，平台其实共用同一份 9:16 | 默认一个通发版（§3），用户明说才多版本 |
| 4 | **通发安全区取交集** | 按最松的平台留白，发到视频号被底部 UI 盖住 | 取**并集/最保守**（§2.3） |
| 5 | **3:4 / 1:1 直接 `y*SY` 压坐标** | 字幕和卡片挤在一起 | 三段锚点纵向重分布（§4.3） |
| 6 | 数字人 `--aspect` 与主线 CANVAS 不一致 | A 段竖、B 段横，混剪契约破 | 同一个 preset 贯穿（§4.6） |
