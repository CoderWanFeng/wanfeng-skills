## 0. 何时问（唯一的触发点）

**Step H 封面完成、发布包整理时问一次**，口径：

> 发布包整理时顺手问：要不要做一套「小绿书 / 小红书」贴图（公众号图片消息用的竖版图，发图文时当封面和内页图）？

- 用户要 → 按本规范生成，进 `发布包/小绿书/`
- 用户不要 → **不做**，不要擅自跳过问询直接做（也不要在之后自作主张补做）
- 做完的成品**只放 `发布包/小绿书/`**，过程脚本放 `mograph-task/src/`（每期一份，命名 `cover_xiaolvshu*.py`）

## 1. 规格（公众号图片消息，2026-11 查证）

| 项 | 值 |
|---|---|

| 尺寸 | **1080×1440 px** |

## 3. 内页选题（按本期实证的叙事顺序）

1. **效果图集中展示**（放最前，钩子）：五套对比联络表（`质检-五套对比联络表.png` 竖长图直接内嵌）+ 姿势帧拍立得（C 档/抽帧），副题「同一张脸，多款裙颜色、姿势随便换。」（**副题文字以用户口述为准**）
2. **GitHub 地址**：真实仓库页截图 + 深色 URL 条 + 工具胶囊行
3. **SkillHub 页面**：真实技能页截图（评分 / 安全标识 / 下载按钮可见）+ URL 条 + 工具胶囊行
4. **WorkBuddy 内安装路径**：真实界面截图（iShot）+ 红框（技能 tab / 搜索框 / SkillHub 分类 / 结果卡）+ 四格局部放大 + 底部一行路径说明

> 地址必须核实后才能上图：GitHub 用 `api.github.com/repos/<user>/<repo>/contents/skills` 列目录确认 skill 目录名；SkillHub 页面直接访问 `skillhub.cn/skills/<user>/<slug>` 验证非 404。**不猜 URL、不伪造界面**（经验总结第 5 条同源）。

## 4. 制作流程

```bash
# ① 浏览器实拍外部页面（skillhub.cn / github.com），viewport 1280×860
#    截图 bytes 直接写文件存进 mograph-task/assets/web/（持久化，别留 /tmp）
# ② 复制 templates/xiaolvshu.example.py → mograph-task/src/cover_xiaolvshu*.py，改「每期必改」CONFIG
# ③ 用托管解释器跑（Pillow 12 + numpy），输出到 发布包/小绿书/
# ④ 读图检查（下一节清单），改到干净再交付
```

**截图卡内嵌规则**：`browser_card()` 内嵌截图**保顶裁切**（`cy0 = 0`）——网页/界面重点在顶部
（导航、Tab 行、标题区），居中裁切会切掉 Tab 行导致红框错位（本期实证踩坑）。

## 5. 读图检查清单（每张必过）

- [ ] 标题文字与页序号**同源**（标题文字必须从同一张映射表取，禁止硬编码三元链——页序重排后不同步 = 标题错位，本期实证）
- [ ] 标题、URL 条、胶囊不出画（宽 = 字符数 × 系数核算，超了缩字号）
- [ ] 序号等特殊字符的**字体覆盖**：`①②③` 在 Arial Bold 里是豆腐块，数字「1/2/3」正常——渲染后读图确认
- [ ] 底部文字 y ≤ 1410，且不被出血照片堆盖住
- [ ] 胶囊 fg/bg 跨明度配对（W10）
- [ ] 拍立得内图片裁切不越界（源图宽 < 1024 时按 `min(1024, sw)` 裁，否则右侧出黑边——本期实证）
- [ ] 外部页面截图必须真实（浏览器实拍），URL 事先核实
- [ ] 每张图 logo 角标只放一个，位置固定（主封面左下 / 内页右上 或 左下，整组统一）
- [ ] 人物图为 AI 生成时，提醒用户发布时平台 AI 标注照旧开启

## 6. 与其他规范的关系

- **W10**（胶囊配对）/ **W18**（文字优先于近似 logo）/ **W24**（参数从素材抽）全部适用
- 拍立得 / 投影 / 圆角卡画法复用 `mograph-task/src/cover_v4.py` 的 `polaroid()` / `paste_with_shadow()`——不要重写
- 视频里的 fs 版式令牌（wanfeng-path.md §4.1）与小绿书**同源**：改动任何一处颜色先想两头
- 模板脚本 `templates/xiaolvshu.example.py` 是**可复制的起点**，每期复制到 `mograph-task/src/` 改 CONFIG，不直接改模板
