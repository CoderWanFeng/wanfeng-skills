# 语义 → 画面效果引擎（semantic-to-effect.md）

> **这是 mograph-pro 最核心、最通用的一条能力，主线 + 动画优先支线共用，面向「任何使用者、任何一份文稿」。**
>
> **一句话契约**：**他说什么，就出现什么；出现什么，就真的会动。**
>
> 这里的「他说」有两个来源，走的是同一套引擎：
> 1. **口播文稿 / SRT 里写的话**（文稿驱动）——文案说「涨了 8 倍」，画面就得有柱子长起来；
> 2. **使用者在对话里用大白话提的效果或修改**（指令驱动）——他说「这个数字给我滚起来」「这里别停太久」「真的放大，别贴个圈」，就照着改出来。
>
> 使用者**不需要懂 Pillow、不需要写代码、不需要知道参数名**。把稿子给出来、或说一句想要什么，执行 Agent 按本文件逐句过一遍即可。
>
> **72 号只是首个实证**：`6000→50000`、`×8.3`、柱状图、放大镜，全是**那一份文稿里抽出来的参数**，不是模板常量。换一份稿子，参数自动换成新稿里的值。

## 0. 为什么单独成文（和现有文档的分工）

| 文档 | 沉淀的是 | 适用范围 |
|---|---|---|
| `wanfeng-path.md` | 主规范：设计令牌 / 版式库 / 时间轴 / 场景表 / 渲染交付 / W 规则（以晚枫号固定打法为基线） | 晚枫号固定打法 |
| `animation-first.md` | 72 号两阶段成片的全流程、节拍化与踩坑 | 成片 + SRT 的特殊支线 |
| **本文件** | **「换谁执行、换哪份稿子都能说什么出什么」的可迁移方法 + 配方库** | **所有稿子、所有使用者** |

主线 Step B 说「手写 `build_scenes()`，不靠正则」——**手写的是语义判断，不是从头发明效果**。
语义判断由 Agent 做（这一点不变），但**效果必须从本文件的基元库查、参数必须从句子抽、逐句必须过一遍**，
不能凭感觉跳过、不能把上一期的数值抄进来。这样才保证「换谁来做都成立」。

---

## 1. 契约（三条硬约束，落到 W24）

- **C1 锚点全覆盖**：文稿 / 指令里每一个「可以被看见的表达」，都必须落到一个画面效果。
  要产出一张**逐句「文稿原话 → 意图 → 基元 → 参数 → 是否真动」对照表**，缺一行就是漏了。
- **C2 参数来自语义，不写死**：数字、倍数、名词、方向、条目数、色卡，一律**从该句口播里读**；
  换稿自动变。文稿没点名的**不许编造**（不自己造数据、不加没说的对比）。
- **C3 出效果即真动**：效果必须有**逐帧运动过程**（W19），不是贴一张静态卡、不是整块淡入冒充；
  且服从全片 ≤3s 节拍（W20）。

> 违反 C1/C2/C3 的典型后果：宣传片里喊「你说什么就出什么」，实际换份稿子就退化成「随便贴几张卡」，当场穿帮。

---

## 2. 五步引擎（拿到任意文稿照做）

```
S1 标锚点   逐句 / 逐条 SRT 扫一遍，圈出「可视觉化表达」（数字、增减、对比、流程、
            清单、聚焦、强调、命名、状态、时间、收尾…）；纯观点句也标，走 §3 最后一类
S2 归意图   每个锚点归到 §3 的一个意图类（决定用哪种效果，不靠关键词正则硬套）
S3 查基元   按意图查 §4 效果基元库 → 取逐帧算法；从该句抽出参数填进去（C2）
S4 对齐轴   按 SRT 起止 / 按语速把效果钉到时间轴上；一句一效果或一句一拍，≤3s 切（W20）
S5 验收     §6 三道闸：锚点覆盖表 / 有过程 / 节奏数据；再全片搜一次有没有残留硬编码值
```

**对话指令通道**（使用者临时提需求时不重走全片）：把他那句大白话解析成
「**哪个锚点 / 哪个基元 / 哪个参数**」→ 只改那一处 → 局部出静帧复核，不重做全片结构。见 §5。

## 3. 语义意图 → 效果基元（通用映射表，不绑定任何一期）

> 「识别信号」是给 Agent 判断用的语义描述，**不是正则匹配串**。
> 最后一列只是 72 号的示范值，**示范，不是默认值**。

| 意图（他在说什么） | 识别信号 | 效果基元 | 从句子抽的参数 | 72 号实例（仅示范） |
|---|---|---|---|---|
| 数字 / 量级变化 | 「从 X 到 Y」「涨到」「有多少」 | `odometer` 翻牌器 | start, end, 单位, 前缀 | 6,000 → 50,000 |
| 倍数 / 增长 | 「翻了 N 倍」「涨了 N 倍」 | `grow_bar` + `counter_badge` | 倍数, 目标值, 是否冲顶 | ×8.3 → ×10 虚线柱 |
| 对比 / 前后 | 「之前…现在…」「A 比 B」 | `dual_compare` | 左右两组值与标签 | 6000 vs 5 万 |
| 流程 / 顺序 / 步骤 | 「第一步…然后…」「控制出现时间」 | `node_chain` | 节点数, 标签, 连接顺序 | 层级逐个连线生长 |
| 清单 / 并列 | 「有三件事」「①…②…③」 | `card_stagger` | 条目数, 每条文案 | 三件事清单 |
| 局部放大 / 聚焦 | 「看这里」「放大看」 | `magnifier`（真 scale） | 焦点坐标, 倍率 | 1 → 2.2 加焦点 |
| 描框 / 指向 | 「框住这一行」「箭头指这」 | `trace_box_arrow` | 框坐标 / 行数, 箭头终点 | 红框逐段描 |
| 强调 / 高亮 / 命名 | 「重点是」「这就叫…」 | `typewriter` + `keyword_pop` | 关键词, 逐字文案 | 逐字打出 + 变色 |
| 风格 / 外观可选 | 「好几种风格」「随便换」 | `swatch_carousel` | 色卡 / 样式列表 | 色卡位移轮播 |
| 否定 / 反转 / 悬念 | 「不是…而是…」「其实」 | `flip_reveal` | 正 / 反两句 | 反转卡 |
| 时间推进 / 等待 | 「三天后」「逐步」 | `timeline_sweep` | 时间点序列 | 时间轨推进 |
| 状态切换 | 「从…变成…」 | `morph` | 两种状态 | 双态过渡 |
| 收尾 / CTA | 「最后」「去试试」 | `hero_settle` | 主文案, logo | 呼吸光环落版 |
| 纯陈述 / 观点（无可视觉锚点） | 「没有任何门槛」「学不会」 | `beat_card` 短句卡点 | 拆出的短句 | 拆成 ≤2.3s 一拍 |

> 一句里点名了多个东西 → 允许叠多个基元，但**主效果只有一个**，其余降为配角，别抢视线。

## 4. 效果基元库（参数化：触发 / 逐帧过程 / 参数 / 坑）

> 所有基元都是**纯函数 `render_frame(t)` 上的一段运动**，只依赖时间 t，任意帧可单独渲染、可抽检、可复现（同 W19）。
> 缓动自己写：`ease_out_cubic / ease_out_quint / ease_out_back / ease_in_out`。

| 基元 | 逐帧过程（必须看得见「过程」） | 参数 | 坑 |
|---|---|---|---|
| `odometer` | 数字一帧帧滚到目标（旧字滚出渐暗、新字滚入渐亮） | start, end, fmt | 窗口 > 字高会新旧同亮重影 → **窗口 = 字高 + 滚筒渐隐渐显** |
| `grow_bar` | 柱子从 0 长到目标高，`ease_out`；可再接一段目标虚线柱继续冲顶 | 值数组, 上限, 倍数 | 别用「直接画出终态再淡入」冒充生长 |
| `counter_badge` | 倍数徽章随生长同步跳数、最后定格 | 倍数文本, 跟随目标 | 与柱高不同步会显得假 |
| `dual_compare` | 左右两栏 / 双柱逐项点亮，差值用引导线标出 | A/B 值, 标签 | 不可见的数字不能当证据（W13） |
| `node_chain` | 节点按时间逐个连线生长、逐级点亮 | 节点数, 坐标, 顺序 | 一次性全亮 = 没过程 |
| `card_stagger` | 卡片逐条错峰弹入（回弹缓动） | 条目数, 文案 | 内容必须跟面板一起进场，禁止空盒子先出现（§4.3） |
| `magnifier` | **真的 `scale` 1→N**，加焦点/暗角，不是贴个圆圈 | 焦点, 倍率, 区域 | 四元组 `(x0,y0,x1,y1)` 转宽高，别当 w/h 直接画 |
| `trace_box_arrow` | 红框逐段描出、箭头逐指、标签弹入 | 框坐标, 箭头终点 | 红只用于标注框（令牌 `RED`，§4.1） |
| `typewriter` | 逐字打出，已打字逐字变色到强调色 | 文案, 关键词, 速度 | 整行一次性出现不算 |
| `swatch_carousel` | 色卡真实位移轮播 | 色卡列表 | 换张静态图不算「可选」 |
| `flip_reveal` | 正面翻转露出反面文案 | 正反两句 | 别只做个透明渐变 |
| `timeline_sweep` | 时间轨 / 刻度按时间点推进高亮 | 时间点序列 | 与字幕时间轴对齐，别自己造时间 |
| `hero_settle` | 光环呼吸、轨道点旋转、边框脉冲（刻意慢，做节奏对比） | 主文案, logo | 半径先 `max(0, …)`，负值会让 `ellipse` 崩 |
| `beat_card` | 长静态句拆 ≤2.3s 一拍，每拍短句 + 一种动效轮换 | 短句列表, 拍型 | 一句话贴 6–11s 不动 = W20 红线 |
| `ambient`（跨拍底） | 宽光带横扫 + 刻度环 + 漂浮粒子，全时段跨拍不重复 | 速度, 相位 | **画在内容之前**，否则不透明宽带盖住正文；且防「拍内重播撞同相位」 |

> **图层顺序固定**：`ambient`（氛围）→ 场景内容（基元）→ `beat_layer`（UI）→ 圆头 → `overlay`（字幕/角标）。
> 圆头不被任何元素压住（W22）。

## 5. 对话指令通道（他说要什么效果，就改出什么效果）

使用者用大白话提需求，**不必懂代码**。执行 Agent 把它解析成「锚点 / 基元 / 参数」三元组，改一处不动全身：

| 使用者可能这么说（原话口吻） | 解析成 | 动作 |
|---|---|---|
| 「这个数字给我滚起来 / 别直接蹦出来」 | 锚点=该数字, 基元=`odometer` | 换基元，参数仍从句子抽 |
| 「柱子要涨起来 / 别贴张图」 | 锚点=增长句, 基元=`grow_bar` | 补逐帧生长 |
| 「放大镜要真的放大，别贴个圈」 | 基元=`magnifier`, 参数 scale | 真 scale + 焦点 |
| 「这里框一下 / 箭头指这」 | 基元=`trace_box_arrow` | 逐段描框 |
| 「这个画面停太久了 / 开始前三秒丰富点」 | 全局节拍（W20） | 拆 ≤2.3s 短句卡点；开场拆 4 拍 |
| 「不能有超过 3 秒不动的」 | 全片验收 | §6 三道数据闸 + 跨拍运动底 |
| 「别挡脸 / 上面那条不要」 | 图层避让（W22） | 删顶栏、chip/标题/卡片按圆头位置避让 |
| 「太花 / 太暗 / 换个色」 | 设计令牌（W7 / W11） | **配色令牌不许擅改**；只调该层透明度或如实说明已否决的暖色方案 |
| 「开场就要看到人」 | 真人层（W21/W22） | 阶段 ② 才叠；开场走左下大圆头 |

> **拿不准就回 §2 走一遍 S1–S5，别直接猜参数。** 指令与文稿冲突时，以使用者本轮明确说的为准，并在交接文档记一笔（W8）。

## 6. 验收（三道闸 + 一次参数复查，全部落盘）

1. **锚点覆盖表**：逐句列「文稿原话 → 意图 → 基元 → 参数 → 是否真动」。
   **每一句可视觉化表达都要有一行**，没有对应效果就补，不许用一张通用卡糊过去（C1）。随 Demo 一起交。
2. **有过程**（W19）：每个效果抽 4 个进度点，能看出变化；禁止整块淡入。出「过程总览图」。
3. **节奏**（W20）：帧差 / 单拍时长 / 连续静止段三项数据全过，不靠目测。
4. **参数复查**：全片搜一遍有没有残留**上一期的硬编码值**（如 `6000` / `50000` / `×8.3` / 上一期产品名）。
   这些值只允许出现在「本期文稿抽取」的结果里，不许写死在渲染函数里（C2）。
