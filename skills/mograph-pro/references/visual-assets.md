# 配图素材采集规范 · visual-assets.md

> **适用范围**：mograph-pro 的 **Step A2**（定版式之后、切场景表之前）。
> 免费版 `mograph` 的通用路径另有一份同源规范，采集逻辑一致，只有「挂载方式」和「标注风格」不同（见 §8）。
>
> **一句话**：按口播讲的主题去找图、截图、做标注；找不到就退回动画，不要拿一张"看起来相关"的图去配一段具体讲解。

---

## 1. 采集顺序（三段式，不许跳）

| 优先级 | 来源 | 怎么来 | 必须记录 |
|---|---|---|---|
| 1 | 用户直接给的截图 | 用户上传或指路本地文件 | 文件名 + 用途 |
| 2 | 用户给的链接 | 自己打开页面截图 | URL + 截取日期 + 用途 |
| 3 | 自己联网找 | 按主题搜索并截图 | URL + 截取日期 + 用途 + 许可判断 |
| 4 | 动画兜底 | 不出图，该场改用动效卡 | 在 spec 里标 `"fallback": "animation"` |

**先定主题，再找图。** 不要逐句去找——那会退化成"给每句话配一张无关的图"。

1. 从口播稿或用户描述里提炼**一个主题**（例："怎么在 WorkBuddy 里用 Hy4-Flash 剪视频"）；
2. 按主题找**一批**可能有用的素材（界面截图、操作步骤图、数据图、官网配图）；
3. 再回到口播句子上**分配**：哪一句该配哪张图。

分配的结果要写进场景表对应场次的图层（本线的挂载方式，见 §8）。

---

## 2. 怎么问用户（一次问清，不来回追问）

在合适的时机（本线 Step A2）**一次性**问这三件事，问完等回复，不要拆成三轮：

> 配图这块我需要确认三件事：
> 1. 你有现成的截图可以直接用吗？（发文件给我就行）
> 2. 有没有链接或官网地址，我可以自己去截？（比如产品页面、文档页、后台界面）
> 3. 都没有的话，我按「<主题>」去网上找，找到能用的就上，找不到就用动效顶上，这样行吗？

**为什么要问**：网上找的图和用户手里的图，可靠度差一个量级。用户有图就优先用用户的，没有再去找——这既省时间，也避免"搜了个差不多的但不是他说的那个版本"。

**用户给了链接但不一定要截图**：如果链接本身适合做成数据卡或文字卡（而不是一张界面图），可以直接把数据/结论做成卡，比截图更清晰。

## 3. 自己找图：搜什么、去哪找、怎么截

### 3.1 检索词公式

```
<主题关键词> + <具体对象/界面/产品名> + 截图 | 界面 | 操作步骤 | 后台
```

比泛搜「主题 + 图片」命中率高得多。英文资料密度更高时加英文词。

### 3.2 来源优先级

| 级别 | 来源 | 抓什么 | 注意 |
|---|---|---|---|
| A | 官方文档 / 官网 | 界面截图、参数说明、产品页 | 界面版本要和口播讲的一致 |
| B | 产品官方图库 / 官方博客 | 场景图、数据图 | 确认授权范围 |
| C | 社区实操图（教程文章、issue 附图） | 操作步骤的中间态 | 版权不明，只能个人发布用；商单要换掉 |
| D | 图库站 / 搜索引擎图片结果 | 不建议 | 画风不搭、授权不明、图与讲的内容无关 |

### 3.3 怎么截

| 场景 | 方式 |
|---|---|
| 网页 | 浏览器截图（视口截图优先，整页截图要先确认目标文字在不在画面里） |
| 本地视频 | `ffmpeg -ss <t> -i <v> -frames:v 1 shot.png` |
| 用户本地文件 | 直接复制到 assets 目录 |

**截图纪律**（这几条都是真踩过的坑）：

- 折叠面板（FAQ 手风琴、可展开表格）**默认是收起的**，答案正文根本不在画面里；
- 长页面超出截图高度时，目标内容在画面外——要么加高重截，要么滚动到目标位置再截；
- 懒加载内容要等它真的渲染出来再截。

### 3.4 预算

- 搜索不超过 **6 次**，入图不超过 **8 张**；
- 连续 3 次搜不到就停手，转 §7 兜底，不要死磕。

## 4. 图片与文字的关系：三条硬判据

**这是整份规范里最容易出事、也最该守住的地方。** 图片是"证据"，配错就是事故。

| # | 判据 | 说明 |
|---|---|---|
| 1 | **图上出现的东西，必须正是那一句口播在讲的东西** | 口播说"点这里的搜索框"，图上就得真的框住搜索框；讲的是 Hy4-Flash 那一行，就不能配一张别的模型行 |
| 2 | **图上不可见的内容，不能当证据** | 抓到的正文文字 ≠ 截图里看得见的文字。标题可见不等于正文可见 |
| 3 | **文件名、OCR 命中、目录里的现成文件，都不等于证据成立** | 文件名可能和画面完全对不上；OCR 没找到不能反推"没有"；目录里躺着的那张不代表它配的是这一句 |

**判据 1 的反例（都真踩过）**：

| 口播在说 | 配错的图 | 为什么错 |
|---|---|---|
| 「积分是 0」 | 一张只显示 ¥0.07~¥0.16 的定价表截图 | 数字对不上，观众一眼看出是别的档位 |
| 「打开模型列表选 Hy4-Flash」 | 一张技能详情页截图 | 讲的是模型列表，图是详情页，指错了地方 |
| 「免费，不用花钱」 | 一张写"限时免费"的活动页 | 活动页不等于产品免费 |

**判据 2 的反例**：FAQ 折叠面板里的答案正文——截图只有一排问题标题，答案一个字都没截到，却拿去证明"文档里写了 X"。

**判据 3 的反例**：素材目录里有 24 张图，渲染器只登记了 1 张且注释写着不用；于是口播说"0 元"时，画面挂的是一张旧图。

## 5. 标注规范

**该标注的地方必须标注。** 操作类与知识分享类内容，配图不做标注等于没配——观众看到一张界面，不知道该看哪儿。

| 内容类型 | 标注方式 |
|---|---|
| 操作步骤 | 步骤编号（①②③ 或 01/02/03）+ 箭头指向被点的那个元素 |
| 界面讲解 | 高亮框：框住目标行，**不压相邻行**；框外区域可压暗半透明 |
| 数据 / 对比 | 图注写清口径（时间范围、单位、来源） |
| 多处要点 | 每处一个编号标注，按口播顺序出现 |

**标注怎么落**：

- 本线：标注是渲染时画在截图面板上的一层（红框、编号 chip、箭头），**不烧进图片本身**——
  同一张图能配不同段落；红框规格见 `wanfeng-path.md` §5.6，编号用 `① ② ③`（字体实测可用，别手绘圆圈数字）。

**颜色口径**：晚枫路径里 `RED (255,93,93)` 只用于截图标注框，其他地方不要用红框，避免"框住的东西"和"重点强调"混淆。

## 6. 来源记录：asset-manifest.json

每张入图的素材都要登记，落成 `assets/asset-manifest.json`：

```json
{
  "assets": [
    {
      "file": "assets/shot-01-workbuddy-list.png",
      "used_at": [8, 11],
      "segments": ["第 8 段：打开 WorkBuddy", "第 11 段：搜「晚枫」"],
      "source": "user-provided",
      "url": "",
      "captured_at": "2026-11-17",
      "shows": "WorkBuddy 模型列表，Hy4-Flash 行被红框标出",
      "proves": "口播「在模型列表里选 Hy4 flash」",
      "license": "user-owned"
    },
    {
      "file": "assets/shot-02-docs-pricing.png",
      "used_at": [14],
      "segments": ["第 14 段：积分消耗 0.00x"],
      "source": "web",
      "url": "https://example.com/docs/pricing",
      "captured_at": "2026-11-17",
      "shows": "定价页，天用户体验价一栏为 0",
      "proves": "口播「积分消耗 0.00x」",
      "license": "official-docs-screenshot"
    }
  ],
  "fallbacks": [
    { "segment": "第 20 段", "reason": "该主题没有可用的公开截图", "used": "animation:number-roll" }
  ]
}
```

| 字段 | 作用 |
|---|---|
| `file` | 素材在 assets 目录里的相对路径 |
| `used_at` / `segments` | 用在哪个时间点、哪句话上 |
| `source` | `user-provided` / `web` / `local-video` |
| `url` / `captured_at` | 从哪抓的、什么时候截的（网页必填） |
| `shows` | 图上**实际**有什么 |
| `proves` | 它支撑的是**哪一句**口播 |
| `license` | 来源许可判断；不明的写 `unknown` 并在交付时说明 |
| `fallbacks` | 哪些段最终没出图、改用了什么 |

`shows` 与 `proves` 两栏是判据 1 的落地形式——**写不出 `proves` 的图，说明它不该出现在这条片子里**。

> **品牌 logo 也进这张表**（字段与上表一致，多一个 `logo_source_kind`）——
> 口播提到品牌名时的自动取件与上屏见 [`brand-logo.md`](brand-logo.md)。

## 7. 兜底：找不到图怎么办

按顺序降级，不要跳级：

1. **该场改用动效卡**：数字卡、对比卡、清单卡、时间轴卡。数据类内容本来就更适合做卡而不是贴图；
2. **用自绘的示意图**：画出结构关系（流程、层级、界面骨架），**但要画成示意图而不是伪装成截图**——不许画一个假的界面骗观众；
3. **该场不配图**：留原画 + 文字卡，把素材预算让给别的场。

**红线**：绝不用一张"看起来相关"的图去配一段具体讲解。宁可这一场只有文字卡，也不能让画面和口播对不上。

## 8. 本线 vs 免费版通用线

| | 本线（mograph-pro） | 免费版 `mograph` 通用线 |
|---|---|---|
| 步骤位置 | Step A2（定版式之后、切场景表之前） | Step 1.5（骨架之后） |
| 素材目录 | `<选题>/05-真人口播/mograph-task/assets/` | `task/<时间戳>_motion/assets/` |
| 挂载方式 | 场景表里的截图面板图层（`wanfeng-path.md` §5.6） | `overlay-spec.json` 的 `visual` 字段 |
| 标注风格 | 红框（6px / 圆角 9 / 只框一行）+ `① ② ③` | 渲染时叠加的高亮框 / 编号 chip / 箭头 |
| 截图太扁看不清 | 改自绘卡片模拟 UI（`wanfeng-path.md` §5.5） | 换一张，或做成卡片 |
| 能不能联网找图 | 能 | 能 |
| 品牌 logo | 有（Step A2-2，`brand-logo.md`） | 无 |
| 采集逻辑（三段式来源优先级 / 三条硬判据 / manifest 字段） | 完全相同 | 完全相同 |

## 9. 交付前检查清单

- [ ] 每张入图的素材在 `asset-manifest.json` 里有登记，`shows` 与 `proves` 都填了
- [ ] 逐张 Read 图片看过，确认要讲的那句话对应的内容**真在画面里**
- [ ] 没有"讲 A 配 B"的错配（口播提到的界面/数字/名称，与图上完全一致）
- [ ] 操作类与知识分享类的图做了标注（编号、箭头或高亮框）
- [ ] 标注没有压住相邻内容，也没有压住人脸安全区
- [ ] 网页素材记了 URL 与截取日期；许可不明的已在交付说明里写明
- [ ] 兜底的段落标了 `fallback` 与原因，没有"硬凑"出来的图
- [ ] 文件名与画面内容一致（重命名过就核对过）
