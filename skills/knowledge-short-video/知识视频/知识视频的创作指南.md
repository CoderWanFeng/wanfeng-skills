## 一、一句话用法

拿到口播稿后，按本指南 **8 步** 走完 → 出 1 份 3 文件发布包（视频 + 封面 + 文案），可直接发小红书 / 抖音 / 视频号。

```
口播稿（口播稿/*.md）
  ↓ 文本确认 + 拆段
segments.txt（每段 ≤ 30 字 / ≤ 8s）
  ↓ 选 2-3 模板 → 生成 cover 测试 → 锁风格
cover-test-{a,b,c}.png + 选定风格
  ↓ 生成封面（swiss-grid，与视频本体同风格）
cover.png（3:4 优先，竖版 1080×1440）
  ↓ 写 composition.html（GSAP fromTo）
composition.html（带 __VAR_XXX__ 占位）
  ↓ TTS 合成
scene_NN.wav × N + timeline.json
  ↓ 注入时间 + render
video_full.mp4
  ↓【精简发布包】封面 + 文案
发布包/  （3 文件：cover.png + video_final.mp4 + publish.md）
  ↓ 小红书 / 抖音 / 视频号发布
```

## 二、五条铁律（竖版专用）

1. **锁定 `/faceless-explainer` workflow**。竖版短视频（单人口播、60-90s、无人出镜）100% 命中这一个 skill，**不要再走决策树**。
2. **一帧 ≤ 8 秒**。竖版节奏比横版快，超 8 秒观众就走神。必要时拆段。
3. **TTS 锁定 MiniMax `WanfengCodex`，速度 1.0x**。不对比 Mac say / ElevenLabs / Kokoro。
4. **画面禁用创作稿术语**。kicker 用 `// 周二下午` `// 我也是`，**不要**用 `// 共情` `// 钩子` `// 受挫`。
5. **做发布包前先问"用户要几个文件"**。竖版短视频的最小发布包就是 **3 文件**（视频 + 1 张封面 + 1 份文案），不要默认全套。

## 三、8 步流程（每期必走）

### Step 1 · 准备口播稿 + segments.txt

**做什么**：根据**输入类型**分两路处理，最终统一为 TTS-ready 文本。

> **[修订] 输入分流**（2026-06-29）：
> - **A 路 · 知识点形式**：用户提供零散知识点 / 概念 / 要点 → 先**聚合为口播稿**（Hook + 正文 + 结尾三段式），再进入下方"复核 + 拆段"。
> - **B 路 · 已成稿文档**：用户提供现成的口播稿 / 文章 / 博客 / 教程 → 直接进入下方"复核 + 拆段"。
> - 无论 A/B，最终都要落到 `segments.txt`，交付形态一致。

**怎么做**：

1. **复核口播稿**：
   - **A 路来源**：用户提供的知识点（已聚合成口播稿）
   - **B 路来源**：用户提供的成稿文档，典型为 `workflow/口播稿/YYYYMMDD-<slug>.md`
   - 时长 60-90s，字数 250-380 字
   - 包含 Hook（3s）+ 正文（是什么/为什么/怎么用）+ 结尾（5-10s）
   - **[修订] 结尾元素可选化**：原强制要求的"关注引导"与"slogan"现为**可选项**，由创作者根据发布场景决定是否添加；不强制保留。

2. **拆 segments.txt**：
   - 格式：**每行 = `帧号\t口播`**，纯文本
   - 一段 ≤ 30 字 / ≤ 8 秒；超过就拆
   - 标点要全（`、`。！？），半角 `,;.` TTS 读不顺
   - emotion 标签可选：`surprised / sad / happy / angry / neutral`

3. **用户确认文本后再进 Step 2**。文本没确认就调 TTS = 浪费调用 + 重对音画（V7 教训）。

**已知坑**：
- ❌ 不要在这一步就调 TTS。两件事分开做。
- ❌ 不要在 segments.txt 里用半角标点。
- ❌ A 路（知识点形式）不要跳过"聚合为口播稿"环节直接拆段——结构化先于分镜。

**交付**：`Process/4-配音稿/segments.txt`（用户确认版本）。

### Step 2 · 锁定 swiss-grid 视觉规范 ⭐

> **核心决策**：每期视频统一用 **swiss-grid** 模板（白底 + Helvetica + 红黑 + 网格），不再做候选测试。
> **理由**：账号已经定型 swiss-grid 系列风格，观众认知一致；每期换模板反而打乱品牌识别。

#### 2.1 swiss-grid 视觉 DNA（锁定）

| 项 | 值 |
| --- | --- |
| 配色 token | `--bg: #fff` / `--ink: #0a0a0a` / `--red: #E30613` |
| 字体 | `Helvetica Neue` Bold 700-900 + `JetBrains Mono` |
| 字号上限 | 巨型数字 200-560px / 主标 132-168px / 标签 28-40px |
| 节奏约束 | 短段 1.5s / 长段 ≤ 5s / gap 0.15s / 硬切不用弹性 |
| 动效规则 | 进场淡入 0.22-0.34s / 退场淡出 0.12s / stagger 0.04-0.06s |
| 装饰元素 | 红色顶部横条 + 黑色底部横条 + grid line + `№ 编号` |

**模板来源**：`src/swiss-grid/composition.template.html`（已沉淀，不需要再选）

#### 2.2 不用候选测试的理由

- **品牌识别**：系列账号风格统一，观众一眼识别"这是晚枫的号"
- **效率**：每期省 30-60 分钟候选测试时间
- **沉淀复用**：swiss-grid DNA 已经在 netflix-headroom 任务验证（封面 v1+v2 + 36 段动画都通过）
- **变体管理**：视觉重点差异通过封面 v1/v2/v3 变体解决（见 2.4），不用换模板

**例外情况**（以下场景才考虑换模板，需用户拍板）：
- 节日特别篇（春节/中秋 → warm-grain 暖色）
- Vlog / 生活分享（→ warm-grain 或 nyt-graph）
- 全新系列启动（需要重新建立品牌识别）

#### 2.4 封面的迭代与变体管理 ⭐ NEW

> **背景**：用户经常说"再调调"、"换个重点"。同 DNA 出多个版本是常态。

**SOP**：

1. **同一 DNA 可以出 v1 / v2 / v3 ...**，新建子目录 `3-生成封面/v2/`，**绝不覆盖** v1
2. **每个变体单独 HTML + PNG**，便于回滚
3. **变体之间的差异**（视觉重点 / 文案变体 / 配色微调）写到 `decision.md` 的 v2 章节
4. **用户选哪个发布都行** —— 保留所有变体让用户拍板

**实战案例**（netflix-headroom-save-token）：

| 版本 | 视觉重点 | 用户反馈 |
| --- | --- | --- |
| v1（swiss-grid） | "好几万 AI 账单 / −95%" | "再调调，重点不够突出" |
| v2（swiss-grid 数字冲击） | "AI 成本 ÷ 20 / −95% 徽章 / 对比条" | "用这版，发布" |

**踩坑教训**：
- 不要试图用一个封面同时讲完所有重点 → 用 v1 讲故事钩子，v2 讲数字冲击
- v1 和 v2 的 HTML 不要共用一份 → 改一处会影响发布
- 用户的"重点不够突出"反馈 → 通常是**核心数字没在第一眼**位置

#### 2.5 浮动元素（徽章 / 装饰）布局 SOP ⭐ NEW

> **背景**：浮动徽章（−95%、NEW、HOT 等）一放就挡正文，本期踩坑 3 轮才到位。

**SOP**：

1. **先预留空白区**：用 grid placeholder 或注释标记浮动元素将要占的位置
2. **浮动元素和正文区保持 ≥ 40px 缓冲带**（CSS 里写 `top: X+40px`）
3. **位置选择优先级**：
   - 右上 → 右下 → 左下（**避开顶部红条和 kicker**）
   - 绝对不要压在主标 / 等式 / 对比条上
4. **Chrome headless 渲染后必须肉眼检查重叠**（CSS 计算和实际像素可能差几像素）
5. **如果空间不够**：扩大浮动元素所在的空白区（上下移动对比条 / 等式），**不要缩小徽章**

**实战案例**（netflix v2 徽章）：

| 轮次 | 徽章位置 | 问题 | 修法 |
| --- | --- | --- | --- |
| 1 | top:560, 等式上方 | 压住"2500 tokens" | 挪到 top:200 右上 |
| 2 | top:200, 右上 | 压住顶部红条和 kicker "TOKEN · 节约方案" | 挪到 top:1060 右下空区 |
| 3 | top:1060, 180×180 + bars 下移到 top:1280 | ✅ 干净不挡 | 通过 |

#### 2.6 封面设计规范（swiss-grid 体系）⭐ 锁定版

> **本节规范**：**封面**（静态发布物）使用与视频本体**完全相同的 swiss-grid 风格**（白底 + Helvetica + 红黑 + 网格）。不再做暗底金字/人物出镜的差异化设计。
>
> **为什么统一**：账号所有视觉物料（视频本体 + 封面 + 公众号配图）保持 swiss-grid 一致风格，品牌识别统一，观众一眼识别「这是程序员晚枫的号」。

| 产物 | 风格 | 大小 | 人/物 |
| --- | --- | --- | --- |
| **视频本体** | swiss-grid 白底 + 红黑 + Helvetica | 1080×1920 (9:16) | 无人出镜（排版为主） |
| **封面** | swiss-grid 白底 + 红黑 + Helvetica | 1080×1440 (3:4) | 无人出镜（排版为主） |

> **设计原则**：封面就是视频的「第一帧」—— 风格、字体、配色、版式与视频本体严格一致。点进视频看到的第一个画面与封面相同，没有违和感。

> ⚠️ **底色硬约束**（2026-06-23 hyperframes-pr-to-video-skill 实战复盘）：
> - 视频本体**只能**用白底 `--bg: #fff`，**禁止**用黑底/深色背景
> - composition CSS 第一行就要写 `:root{--bg:#fff; --ink:#0a0a0a; --red:#E30613; ...}`
> - 即使封面用了黑底风格（hyperframes-pr-to-video-skill 封面是黑底），**composition 也必须白底**
> - 黑底视频 → 渲染黑屏或观众认不出是同一系列
> **绝对禁止**：
> - ❌ 封面用暗底 + 金字 + 人物出镜（已废弃，不再使用）
> - ❌ 封面用 9:16 比例（已废弃，9:16 上传平台会被裁切，必须用 3:4）
> - ❌ 封面引入其他配色（如蓝/绿/紫/橙）
> - ❌ 封面与视频本体风格不一致（风格可同，比例必须不同）

##### 2.6.1 封面核心原则

封面不是「配图」，是「视频第一帧」—— 用户在信息流中停留不到 0.3 秒，必须用视觉瞬间传递两件事：

1. **这期讲什么**（大字号主标题，一眼可读）
2. **核心数字/反常识钩子**（视觉锤，第一眼抓住注意力）

封面 = 视频第一帧，所以封面的版式、字体、节奏与视频内容严格对应。

##### 2.6.2 品牌色彩体系（与视频本体一致）

| 层级 | 颜色 | 色值 | 用途 |
| --- | --- | --- | --- |
| 底色 | 纯白 | `#fff` | 全幅背景（与视频本体一致） |
| 主文字 | 墨黑 | `#0a0a0a` | 主标题、副标题、说明文字 |
| 强调色 | Netflix 红 | `#E30613` | 强调数字、装饰横条、进度条、kicker |
| 辅助色 | 浅灰 | `#e0e0e0` | 网格底纹、分割线 |

**配色禁忌**：
- ❌ 不要引入金色（`#F5C518`）—— 已废弃
- ❌ 不要引入暗底（`#070B14`）—— 已废弃
- ❌ 不要引入其他颜色（蓝/绿/紫/橙）—— 破坏系列感
- ✅ 只能使用白 + 黑 + 红 3 色

##### 2.6.3 格式与尺寸

**统一使用 3:4 竖版**（小红书/抖音/视频号通用，9:16 上传会被裁切）：

| 版式 | 尺寸 | 平台 |
| --- | --- | --- |
| **3:4 竖版（唯一）** | 1080 × 1440 | 小红书、抖音、视频号、B站竖屏、公众号头图 |

> **为什么用 3:4 不用 9:16**：
> - 9:16 视频帧在某些平台展示位会被裁切（顶部/底部被切）
> - 3:4 是各平台通用的封面比例，**不会被裁切**
> - 视频本体仍然是 9:16，封面 3:4 是单独的发布物
>
> **禁止 9:16 / 16:9 / 1:1 多尺寸**：只出一张 3:4，平台自动适配。
> **禁止裁切**：不要给 1 张封面出 4 个尺寸再裁切，直接用原图。

##### 2.6.5 主标题设计规则

**与视频本体的版式一致**：
- 用 swiss-grid 排版（左侧视觉锤 + 右侧信息区 / 上下二分 / 大数字矩阵）
- 不用暗底金字风格的金色发光阴影
- 不用人物出镜
- 不用标题拆分错位排布（那套是暗底封面的技法）

**核心结构**（参考 netflix 封面 v1/v2）：
1. 顶部红色横条（`AI · 主题` + 期号）
2. 主视觉区（巨型数字 / 核心问句 / 视觉锤）
3. 信息卡片（3 个概念 / 关键点）
4. 底部装饰（脚注 + 工具条）

**示例**（netflix v2 节约Token版）：
- 顶部红条：`AI ENCODING · TOKEN SAVER`
- 主视觉：`AI 成本 ÷ 20`（÷ 20 红色巨型）
- 等式：~~50000~~ ÷ 2500 tokens
- 徽章：−95% TOKEN（圆形）
- 对比条：100% → 5%
- 底部：Headroom 工具条

##### 2.6.5.1 封面简化原则 ⭐ NEW

> **核心原则**：封面不是「配图」，是「钩子」。普通人在信息流停留不到 0.3 秒，必须**一眼看懂**这期讲什么。

**3 个硬要求**：

1. **字要少** — 不要堆砌信息（5 卡片、长副标、复杂 sub 文字）
   - ✅ 4-5 块内容是上限
   - ❌ 6+ 块内容 = 失焦
2. **重点要突出** — 1 个核心问题 + 1 个核心转换 + 1 句话解释
   - ✅ 视觉锤放第一眼位置（巨型字 180px+）
   - ❌ 核心数字藏在角落
3. **普通人能看懂** — 每个词都让"没学过 AI 的人"秒懂
   - ✅ "噪声 → 合影"（人话）
   - ❌ "Diffusion model 30 step denoising"（术语堆砌）

**反面案例**（信息密集，重点不突出）：

| ❌ 错误 | ✅ 正确 |
|---|---|
| 6 块内容（顶部红条 + Hero + 等式 + 徽章 + 5 卡片 + 工具条 + 底部） | 4 块内容（顶部红条 + Hero 问句 + 核心转换 + 工具条 + 底部） |

##### 2.6.8 浮动元素（徽章）布局 SOP

### Step 4 · 写 composition.html（GSAP fromTo）

**做什么**：基于选定模板的 `src/<template>/composition.template.html`，实现分镜稿的视觉效果。

**模板架构**：
```
src/<template>/composition.template.html    ← 唯一视觉源（含 __VAR_XXX__ 占位符）
tasks/<task>/work/composition.html          ← resync.py 注入实际时间后产物
```

**核心模式**（V9 教训，已锁定）：

| 错误写法 | 正确写法 | 原因 |
|---|---|---|
| `tl.from("#s1 .big", {opacity: 0, y: 40})` | `tl.fromTo("#s1 .big", {opacity: 0, y: 40}, {opacity: 1, y: 0, duration: 0.5, ease: "power2.out"})` | inline 初始属性导致视觉跳变 |

**4 条硬约束**（不遵守会 lint 报错）：
1. 每个 timed 元素必须有 `data-start` + `data-duration` + `data-track-index` + `class="clip"`
2. timeline 必须 paused 且注册到 `window.__timelines[composition-id]`
3. 视频 `muted` + 单独 `<audio>` 元素
4. 只用确定性逻辑（**禁** `Date.now()` / `Math.random()` / 网络 fetch）

**已知坑**：
- 所有 `data-start` / `data-end` 用 Python 计算到 **3 位小数 + 0.01s gap**。
- 视觉段和音频段必须用**同一份**时间精度（不能 visual 2 位 + audio 3 位）。
- `bg` 黑色露出边缘 → 显式 `html,body{background:#fff}` + 每个 section 单独 bg。
- 大脚本 `write` 工具 JSON parse 失败 → 改用极简生成器（57 行模板 + 数据 dict）。

**交付**：`src/<task>/composition.template.html`（含完整 section + GSAP 时间线）。

### Step 5 · 合成 TTS 配音

**做什么**：把 `segments.txt` 合成 N 段独立 wav + `timeline.json`。**每段必须带情绪**（不许纯 neutral 一路念到底）。

**怎么做**（命令可直接复制）：

```bash
# 1. 单段 wav（独立，支持单段重试）
OUT_DIR=tasks/<task>/work/audio/variants/<v>/segments \
  python3 tools/tts/minimax-tts.py

# 2. 拼接 + timeline.json
SEGMENTS_DIR=tasks/<task>/work/audio/variants/<v> \
  VARIANT_NAME=<v> TTS_MODEL=minimax-speech-01-turbo TTS_VOICE=WanfengCodex \
  ./tools/audio/concat-wav.sh
```

**TTS 锁定配置**（竖版短视频默认）：
- **引擎**：`speech-01-turbo`
- **声音 ID**：`WanfengCodex`
- **速度**：**1.0x**（1.3x 仅 dev 预览，不用于发布）
- **API 端点**：`https://api.MiniMax.chat/v1/t2a_v2`

**segments.txt 情绪格式**（**必带**）：

```
N\t[emotion]\ttext
```

- **N**：段号（1, 2, 3...）
- **[emotion]**：情绪标签，必须是以下 5 个之一：
  - `neutral` — 陈述、定义、说明（**全篇最多 40%**）
  - `happy` — 反常识揭示、行动号召、好消息、**[修订] 结尾引导关注（可选）**
  - `surprised` — 反转、惊讶、揭示（如"答案很反常识"）
  - `sad` — 警告、避坑（如"不写这句，AI 把你爸画成别人"）
  - `angry` — 强烈批判（极少用）
- **text**：口播文本

**情绪分配原则**：

| 段类型 | 默认情绪 | 示例 |
|---|---|---|
| Hook（前 3 秒） | `happy` / `surprised` | "父亲节刷屏的"穿越合影"" |
| 反转 / 揭示 | `surprised` | "答案很反常识——" |
| 行动号召 | `happy` | "普通人 5 分钟也能做" |
| 好结果 / 数字冲击 | `happy` | "30 步后，从噪声长出合影" |
| 警告 / 避坑 | `sad` | "不写这句，AI 容易把你爸画成别人" |
| 术语解释 / 陈述 | `neutral` | "这叫 Vision Encoder" |
| **[修订] 结尾 CTA（可选）** | `happy` | "关注晚枫"（若选择添加结尾引导） |

**禁止**：
- ❌ 全篇 neutral 一路念到底（生成的配音太平，没情绪）
- ❌ 每段都加情绪标签但没认真选（乱标 happy/sad）
- ❌ emotion 标签位置错（必须 `[emotion]` 在 text 前面，不是后面）

**已知坑**：
- **emotion 参数必须在 `voice_setting` 内嵌套**，不能放 payload 顶层（V9 调试记录）。
- 同一段不要重复 emotion 标签（否则 API 报错）。
- 不要换 TTS 引擎对比效果，浪费时间。
- **实测时长常超过预估**（V11 数据：预估 127.8s，实测 136.7s，+7%），靠 Step 6 的 sync-to-composition.py 反向同步修正。

**交付**：`scene_NN.wav` × N + `narration.wav` + `timeline.json`。

### Step 6 · 注入时间 + render

**做什么**：把 `timeline.json` 里的实测时间注入模板，渲染出无音/占位音的 mp4。

**4 步最小循环**：

```bash

```

**已知坑**：
- ⚠️ `npm run dev` 是**长驻服务**（不是一次性命令），必须 `run_in_background: true` 后台跑。
- F5+ 渲染全黑 / 截断 → 检查相邻 clip 是否真的 0.01s 分离。
- **实测时长超过预估**：靠 `sync-to-composition.py` **反向同步**（用实测 audio 时长重算 visual 的 data-start），不要回头改 segments.txt。

> ⚠️ **`data-duration` 必须精确匹配 narration.wav 总时长**（2026-06-23 opencode-free-model 实战复盘）：
> - **核心规则**：`data-duration="<n>"` 的 `n` 必须是 narration.wav 的实际总时长（秒）
> - **计算方法**：
>   ```bash
>   ffprobe -v error -show_entries format=duration \
>     -of default=noprint_wrappers=1:nokey=1 narration.wav
>   # → 115.21s
>   ```
> - **场景时长分配**：把总时长按 segments.txt 的累计时长分配到 6 个 scene 的 `data-duration` 上
>   - S1 Hook（段 1-4）: 累计配音时长
>   - S2 Knowledge（段 5-9）: 累计配音时长
>   - S3 Steps（段 10-12）: 累计配音时长
>   - S4 How to use（段 13-22）: 累计配音时长
>   - S5 Model ranking（段 23-30）: 累计配音时长
>   - S6 CTA（段 31+）: 累计配音时长
> - **症状**：`data-duration` 设大（> 实际场景总时长）→ 67s-115s 之间视频全空白
> - **症状**：`data-duration` 设小（< 配音时长）→ 配音被 `-shortest` 截断
> - **执行顺序（硬性）**：
>   1. 先完成 Step 5 TTS + concat narration.wav
>   2. **测 narration.wav 实际时长**（ffprobe）
>   3. 再分配 6 个场景的 data-start / data-duration
>   4. 最后再 render
> - **速算工具**（一次性 Python 脚本）：
>   ```python
>   from pathlib import Path
>   import subprocess
>   seg_dir = Path("Process/5-合成配音")
>   durations = []
>   for f in sorted(seg_dir.glob("scene_*.wav")):
>       d = float(subprocess.check_output(
>           ["ffprobe", "-v", "error", "-show_entries", "format=duration",
>            "-of", "default=noprint_wrappers=1:nokey=1", str(f)]
>       ))
>       durations.append(d)
>   total = sum(durations)
>   # 按 6 段分配（按 segments.txt 的段号切分）
>   splits = [(0,4), (4,9), (9,12), (12,22), (22,30), (30,31)]  # 段号 [start, end)
>   for i, (a, b) in enumerate(splits, 1):
>       s = sum(durations[:a])
>       d = sum(durations[a:b])
>       print(f"S{i}: data-start=\"{s:.3f}\" data-duration=\"{d:.3f}\"")
>   print(f"data-duration=\"{total:.3f}\"")
>   ```

**交付**：`composition.html`（已注入时间）+ `video_anim.mp4`（占位音）。

## 八、迭代经验

竖版短视频最容易翻车的 6 个点：

1. **第一步就把 TTS 调了** → 文本没确认就合成 = 100% 返工。先 segments.txt 后 TTS。
2. **画面禁用词**写进画面了（`// 共情` `// 受挫`）→ 观众看不懂。kicker 用 `// 周二下午` 这种内容回声。
3. ~~**每期都用同一模板**（早期 paper 白底）~~ → ~~观众审美疲劳。**每期 Step 2 重选 2-3 模板测**~~。**统一 swiss-grid，不再换模板**（品牌识别优先）。
4. ~~**选了模板但没测 cover**~~ → ~~视频里好看的不一定缩略图好看。**cover 测试 SOP 必走**~~。**取消候选测试**。
5. **浮动徽章压住正文** ⭐ → 见 2.5 浮动元素布局 SOP（先留空白、≥40px 缓冲、肉眼检查）。
6. **封面出多个尺寸再裁切** → 唯一 3:4 1080×1440，平台自动适配，不要裁切。

把这 6 点过一遍，能少 90% 返工。
