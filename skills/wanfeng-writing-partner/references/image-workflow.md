# 配图与图床流程详解

本文是 SKILL.md 第 4–6 步的展开。

---

## 一、配图选型决策树

按顺序问三个问题，命中即停：

1. **这段在讲某个工具/网站/后台怎么用，有界面吗？** → 用真实截图
2. **这段讲的是功能、流程、原理、数据、对比、踩坑吗？** → 用暖白插图
3. **有公司/产品/人物主体吗？** → 官网素材；没有 → 图库图

**硬规则**：

- 有界面就截图，**绝不用自制插图去"模拟"界面**——自制的界面是假信息，读者照着做会卡住
- 同一篇文章里截图与插图可以混用，但同一节内不要混
- 截图标注来源页面链接；自制插图标"· 晚枫自制插图"或"· 自制插图"

## 二、网页截图流程

### 取图来源优先级

1. **自己的使用画面**（首选）：截自己用的那一屏，最真实，没有第三方版权问题
2. **官网产品页/功能页/文档页**：公开的产品界面
3. **官方文档截图**：参数、配置项、报错信息

### 截图步骤

```bash
# 方式一：手动截图（推荐，最直观）
# 打开浏览器 → 定位到目标页面 → 截屏工具只截必要区域

# 方式二：用浏览器自动化工具（适合反复截同一页面）
# 使用 agent-browser 或 Playwright 打开页面并截图
```

### 裁剪与缩放

截图后通常需要裁剪和缩放，用 Python + Pillow 处理：

```python
from PIL import Image

img = Image.open('raw_screenshot.png')

# 裁剪到必要区域（坐标根据实际图片尺寸调整）
cropped = img.crop((x1, y1, x2, y2))

# 等比缩放到 1200px 宽
target_w = 1200
target_h = round(cropped.height * target_w / cropped.width)
resized = cropped.resize((target_w, target_h), Image.Resampling.LANCZOS)

resized.save('output_screenshot.jpg', quality=94, optimize=True)
```

### 脱敏处理（关键步骤）

截图里如果有以下信息，必须在发布前去除：

| 必须去除 | 可以保留 |
|---------|---------|
| 真实姓名、身份证号 | 产品公开展示名 |
| 个人头像 | 品牌 Logo |
| 账号 ID（如 `os_xxx`、`user_xxx`） | 公开价格信息 |
| 邮箱、手机号 | 产品版本号 |
| 真实订单号 | 功能描述文字 |
| 内部系统地址 | 平台公开品牌名 |
| 浏览器书签栏里的个人信息 | — |

**遮盖方法**（Pillow）：

```python
from PIL import Image, ImageDraw

img = Image.open('screenshot.png').convert('RGB')
draw = ImageDraw.Draw(img)

# 用白色矩形覆盖敏感区域（坐标根据实际图片调整）
draw.rectangle([x1, y1, x2, y2], fill='#FFFFFF')

img.save('screenshot_clean.jpg', quality=94)
```

**脱敏后必须逐张打开目检**：确认敏感信息完全消失，同时产品关键信息（价格、功能名、版本号）仍然可见。

### 证据图的三条硬判据

当截图用于"证明"文章里某个具体说法时：

1. **只有肉眼在图上看到才算证据成立**：标题可见 ≠ 正文可见，折叠面板里的内容截图里看不见
2. **每张证据图要能回答三件事**：出自哪个 URL、截取日期是哪天、它证明的是哪句话
3. **文件名与画面内容可能完全对不上**：裁完没核对就命名，不能按文件名挑图

## 三、暖白插图生成

适合讲流程、原理、数据对比、踩坑清单等没有界面可截的段落。

### 色板（固定，不得自创近似色）

| 用途 | 十六进制 |
|------|---------|
| 暖白底 | `#FAF7F1` |
| 白卡 | `#FFFFFF` |
| 冷灰面板 | `#EEF0F3` |
| 暖黄面板 | `#FFEDDC` |
| 浅蓝面板 | `#DEEAFE` |
| 橙红强调 | `#F07628` |
| 正文墨 | `#1C2026` |
| 描边 | `#E2E5E9` |
| 次要灰 | `#7E8690` |
| 更浅灰（脚注） | `#A2A7AD` |

**配色规则**：

- 底永远是暖白，正文墨 `#1C2026`
- 橙红 `#F07628` 只用于强调数字、序号、勾选，一张图里不超过 3 处
- 暖黄面板 = 提示/口径说明；冷灰面板 = 中性说明；浅蓝面板 = 操作步骤
- 禁止：深色底、渐变主色、霓虹色、高饱和蓝绿紫、纯黑

### 尺寸

| 用途 | 尺寸 |
|------|------|
| 封面 | 1200×675（16:9） |
| 步骤图 | 1200×640 |
| 正文图 | 1200×600 |

### 运行方法

```bash
# 检查 Pillow 是否可用
python3 -c "import PIL" 2>/dev/null || pip3 install pillow

# 生成全部示例图
python3 scripts/warm_illustration.py --out /tmp/illus

# 只生成指定的几张
python3 scripts/warm_illustration.py --out /tmp/illus --only cover flow
```

> ⚠️ 部分机器的默认 `python3` 没有安装 Pillow。先探测再运行，不要反复试同一个解释器。

### 新增一张图的方法

1. 复制脚本里任意一个 `fig_*` 函数
2. 改数据与文案
3. 改 `save()` 里的文件名
4. 在 `FIGS` 字典里登记
5. 运行 → 逐张打开目检

### 生成后自检清单

- [ ] 脚注固定在底部，卡片/面板没有压到它
- [ ] 卡片内文字不溢出（`fit_text` 之后仍要目检）
- [ ] 橙红强调一处图内 ≤ 3 处
- [ ] 一张图只讲一件事
- [ ] 手机端可读（正文最小字号 ≥ 21px @1200 宽）

## 四、图片命名规范

所有图片文件名必须：

- 只用英文中横线 `-` 分隔，不用中文标点、空格、`%` `?` `#` `&`
- 包含日期前缀和语义描述：`<YYMMDD>-<主题>-<用途>.jpg`
- 示例：`261119-product-screenshot.jpg`、`261119-feature-flow.jpg`

## 五、图床上传与引用

### 上传流程

1. 图片处理完毕，保存在本地临时目录
2. 用你配置的图床工具上传（PicGo 面板、图床网页、CLI 命令均可）
3. 拿到返回的**公开直链 URL**
4. 用浏览器打开 URL 验证：HTTP 200、Content-Type 是 image、尺寸正常
5. 把 URL 写入文章

### 在文章中引用图片

```markdown
![这段在解释什么](https://你的图床/261119-flow-diagram.jpg)

*图：流程说明 · 自制插图*
```

截图类：

```markdown
![产品功能页面](https://你的图床/261119-product-page.jpg)

*图：XXX 功能界面 · 来源：[官方文档：https://example.com/docs](https://example.com/docs)*
```

> 图注属于「图片来源斜体标注」，按 `writing-guide.md` §9.3 **保持原格式**：不加引号、不进引用块。只有正文里独占一段、或夹在句子中间的链接才套 §9.2 两条规则。

### 禁止事项

- 不得把图片长期存在本地再引用本地路径
- 不得使用占位符 URL（如 `https://待补充`）当成成稿
- 不得用普通 GitHub 页面地址（要用 Raw 直链或 CDN 地址）
- 不得在文章里暴露任何人的图床账号、Token、配置路径
- 不得用通配符路径上传（某些工具会回退到剪贴板上传，把无关图片传上去）

## 六、封面图

Frontmatter 的 `cover` 字段必须是一个已验证可访问的图片 URL。

- 宽度 1200px，与文章核心主题相关
- 可以用暖白风格自绘，信息量比通用图库封面大
- 工具/工作流类文章推荐用暖白自绘封面，风格与正文插图统一
