# 写作规范详解

本文是 SKILL.md 第 2–3 步的展开，面向中文 AI 工具类长文（公众号、知乎专栏）。

> ⚠️ **优先级**：`references/viral-patterns.md` 是从 4 篇高互动实证文章反推的写法，**与本文冲突时以实证为准**。
> 实证修正了本文旧版的三处一刀切：「每篇必含 AI 原理段」「主体 ≤ 3 个 `##`」「Slogan 一字不差」——这三条只在科普观点类成立。

---

## 一、定位与语气

**目标读者**：对 AI 感兴趣的普通人，不是程序员；更具体地说，是**想省钱、怕踩坑、今天就想动手试一下**的人。

**五大原则**：

1. 内容价值优先——读完能直接用
2. 绝对零门槛——不用代码、编程术语、行业黑话
3. 信任优先——不制造焦虑、不割韭菜、帮读者避坑，**主动亮短板**
4. 聚焦不发散——严格围绕 AI / 科技主线
5. 阅读友好——适配手机长文阅读习惯

**语气公式**：像朋友聊天，不像论文、不像新闻稿、**更不像公关稿**。

---

## 二、标题写作

### 硬指标

- 建议 **18–32 字**，硬上限 36 字（含英文产品名时可到 36）
- 必须出现**具体对象**（产品名、价格、数字）
- 必须有**具体利益或低门槛承诺**，不靠空悬念
- 前 15 字把利益说完

### 六种模板（前两种来自实证，优先用）

| 类型 | 模板 | 实证/示例 |
|------|------|------|
| **① 利益前置**（首选） | `免费/白嫖/领 + 具体数字 + 平台名 + 低门槛承诺` | `免费领取 WorkBuddy 3万积分，教程来了！` |
| **② 极简承诺** | `在 X 里做 Y，简单到 N 步就出片` | `在 WorkBuddy 里做视频，简单到 3 步就出片` |
| 数字冲击 | X 变成 Y | `Copilot涨价26倍，AI免费时代结束了` |
| 反常识 | 明明A，为什么B | `明明是国产AI，为什么反而不懂中文` |
| 个人体验 | 我用了X天 / 亲测有效 | `每月"白嫖"200美元？Qoder Ultra 免费用，亲测有效` |
| 避坑提醒 | 别急着X，先看Y | `别急着买AI电脑，先看这3个问题` |

### 禁忌

- 空泛：`AI趋势分析`
- 虚假夸张：`最强` `全球第一` `震惊` `揭秘` `不看后悔` `深度解析`
- 数字模糊：`大幅` `超多` `海量` `相当可观` —— 一律换成具体值
- 太长（>36 字手机显示不完整）、太专业

挑 6–8 个候选，实测字数，选最佳。

## 三、正文结构：按文章类型分叉

**先判类型，再搭结构。不要所有文章都套同一个骨架。**

| 类型 | 主体 `##` 数 | 小标题风格 | AI 原理段 | 典型递进 |
|---|---|---|---|---|
| 科普 / 观点 | ≤ 3 | 判断句，不像目录 | **必含** | 现象 → 为什么 → 原理 → 回到现实 |
| 手把手教程 | 4–6 | `01 / 02 / 03` 编号 + 动作 | 不必 | 准备工作 → 为什么值得 → 步骤 → 跑通后能做什么 |
| 产品发布 / 评测 | 6–8 | 口语短句 | 不必 | 能做什么 → 怎么装 → 开工先选哪条路 → 准备什么 → 费用与边界 → 第三方评测 → 现在动手 |
| 免费福利 / 活动 | 3–5 | 「不当 X，也有 Y 的办法」 | 不必 | 我领到了 → 普通人怎么领 → 进阶申请 → 线下/下一步 |
| 合作 / 身份公告 | 3 | 时间线（去年 → 今年 → 接下来） | 不必 | 前因后果 → 具体支持 → 能给读者带来什么 |

### 通用骨架

```
[开头] 固定问候 + 第一句给结果 + 具体日期/身份 + 读者顾虑（80-150字）
   ↓
[主体] 按上表选结构与小节数，语义递进
   - 每段 ≤ 3 行，重点加粗
   - 决策/对比/费用信息一律表格化
   - 写「能做什么」的同一节里必须写「不能做什么 / 差在哪 / 多少钱」
   ↓
[结尾] 升华 + 具体互动 + 可复制指令 + 入口 + Slogan（按类型）+ 参考链接 + 相关阅读
```

### 开头

- **固定开场白**：`大家好，我是程序员晚枫。`（可用「这里是」）
- **第一句就给结果**：`WorkBuddy 的 3 万积分，我领到了。`
- 用**具体日期 / 身份 / 事件**建立可信度，不写「最近」
- 优先引用**读者原话**当钩子：「评论区问得最多的就一句话：……」

### 开头禁止

- `随着人工智能技术的发展……`
- `近年来，AI 逐渐进入大众视野……`
- `本文将从三个方面分析……`
- 铺垫半天不给利益

### 教程类：先给地图再走路

开头明说：「**全文分两部分：准备工作和实操教程。你只需要先把准备工作做完，再往下按教程一步步操作，就能跑通。**」

### AI 知识段（仅科普 / 观点类必含）

```
热点现象 → 但你知道为什么吗？→ 原理（大白话）→ 所以你会看到 → 回到现实
```

教程、发布、福利、公告类**不要硬塞**，会打断实操节奏。

### 小标题要求

- 必须像判断或动作，不像论文目录
- ✅ `真正贵的不是价格` / `01 准备工作：先注册这两个账号` / `不当合伙人，也有领积分的办法`
- ❌ `背景介绍` `总结` `我的看法` `晚枫点评`

## 四、亮短板与反公关（硬规则）

**每篇至少 1 处，且必须放在读者做决策之前，不许藏到文末。**

1. 写「能做什么」时，同节写清**不能做什么 / 差在哪 / 要花多少钱**
2. 用直给的句式：`代价我先摊开说` `效果也不如 … 那条` `… 做不到的事，我也不会绕着说` `有了支持，不等于只剩好评`
3. 区分「官方说的」与「我实测的」：明示哪些来自官方公告、哪些是自己的体验
4. 第三方评测指出不足时**照写并认下来**：`这几条我认。…… 下一版会修`
5. 官方邮件 / 证书 / 报告原话用 `>` 引用块，不转述成自己的话
6. 权益、费用、入选、规则类信息一律带口径：`以官方审核和实际安排为准` `技能显示的是预估，不是最终账单` `领取时仍按当前账号的活动规则来`

> 实证原话：「我们不需要您说 Qoder 有多好，只需要您把真实用过的东西写下来，包括哪里不好用。这比任何宣传都有价值。」

## 五、共情、自嘲与黑色幽默

**每篇至少 1 处**，公式：`替读者说出顾虑 + 站到他那边 + 一句自嘲点到为止`

- `大家都是靠薅免费额过日子的穷人，懂你。`
- `说白了，掏十几块去试一个 AI 工具，对大多数人真不算小数目。`
- `免费又好用的东西，目前 PDD 都做不到。`

常用过渡词：`说白了` `说简单一点` `一句话` `摊开说` `这点我不想让你踩坑`。

**只嘲讽现象和自己，绝不嘲讽具体的人**；不制造焦虑、不催单。

---

## 六、排版铁律

1. 每段 ≤ 3 行，单句成段可以
2. 章节间用 `* * *` 或 `---` 分隔
3. `##` 章节 + `###` 子标题，不跳级；教程类用 `01 / 02 / 03` 编号
4. 核心观点 / 数据 / 边界用 `**加粗**`（每段不超 2 处）
5. 3 个以上并列项用列表
6. **决策 / 对比 / 费用 / 评分一律表格化** —— 读者要选、要花钱、要照做的地方优先表格
7. 图片放在它解释的文字之后，下方斜体 `*图片来源：…*`，写明谁提供、出自哪个页面、截取日期
8. 官方原话、合规提醒、可复制指令用 `>` 引用块
9. 零术语；出现术语立刻用一句人话解释

---

## 七、Frontmatter 格式

```yaml
---
title: 文章标题（与正文主标题一致）
date: YYYY-MM-DD HH:MM:SS（与当前系统时间一致）
tags: [公众号文章, 具体标签1, 具体标签2]
categories: [公众号文章]
cover: 已验证可访问的图片URL
---
```

- `tags` 第一个固定 `公众号文章`
- `cover` 必须有值且 URL 可访问
- YAML 中能用引号就用，遇到 `:` `,` `#` 等特殊字符必须加引号

## 八、结尾固定结构（按类型）

按顺序：

1. 升华式总结（一句话戳透核心，不列 123）
2. **具体互动**：`看明白的点个赞。` / `你最想先做哪一类视频？评论区打出来。`（不要「大家怎么看」）
3. **一条可直接复制的指令**：`@晚枫数字人 帮我生成数字人` / `请根据 https://… 安装 @…`
4. 入口：注册链接 / 发布页 / 开源仓库 / 报名页
5. **固定 Slogan**（教程、福利、产品发布类）：
   ```
   **科技不高冷，AI很好用。**
   我是晚枫，关注我，带你一起玩AI！
   ```
   **合作 / 身份公告类可省略**，换成克制收束（「接下来，就从一个个具体案例开始。」）
6. `### 参考链接`（科普 / 评测 / 福利类 ≥ 3 条官方或权威来源；纯教程、公告类不强求）
7. `## 相关阅读`（2–4 篇相关公众号文章）
8. 正文底部引导图（单独一行）
9. 关联推荐自己的其它 Skill（可选）

## 九、链接格式

### 9.1 链接本体（不变）

**非微信链接**统一写：

```markdown
[标题：完整URL](完整URL)
```

中括号里必须带完整 URL，原因：公众号编辑器对超链接保留不稳定，读者复制正文就能拿到链接。

**三个例外**：

| 类型 | 写法 |
|------|------|
| 微信链接 | `[标题](https://mp.weixin.qq.com/s/xxx)` 不重复 URL |
| 图片 | `![alt](URL)` alt 里不写 URL |
| 代码块内链接 | 给读者复制执行的命令，不加标题 |

### 9.2 按出现位置定包装方式（硬规则）

> ⚠️ **核心原则**：链接在正文里怎么摆，只看一件事——**它是不是独占一段**。两种写法二选一，不能混用，也不能都不用。

**链接本体写法不变**（`[标题：完整URL](完整URL)`），只看这条链接在段落里怎么出现：

| 位置 | 判定 | 写法 |
|------|------|------|
| ① **单独成段** | 一段里只有这一条链接，前后没有别的文字 | 用 `>` 引用块包住 |
| ② **嵌在正文句子里** | 同一行里链接和说明文字混排 | 链接前后用**英文引号 `"`** 包住 |

**① 单独成段 → 引用块**

```markdown
> [WorkBuddy 官方活动页：https://example.com/act](https://example.com/act)
```

- `>` 后跟一个空格；引用块**前后各留一个空行**，不与正文段落粘连
- 可以在链接前加 `> 原文链接：` 之类引导语，但整段仍以 `>` 起头
- ❌ **禁止**把一条裸链接单独扔在正文段落里

**② 嵌入正文 → 前后加英文引号**

```markdown
活动规则写在 "[WorkBuddy 官方说明：https://example.com/rules](https://example.com/rules)" 这一页，照着做就行。
```

- 引号**包在整个链接外侧**（`"[标题：URL](URL)"`），不要插进 Markdown 语法内部把链接拆断
- 裸 URL 同样处理：`直接打开"https://example.com"就行`
- 前半句后半句照常写，不要让链接和中文直接粘在一起（如 `见[链接]这一页`）

**判断口诀**：独占一段就上 `>`，夹在话里就上 `""`。

### 9.3 不套用上面两条的情况（保持原格式）

| 保持原格式 | 例子 |
|---|---|
| `### 参考链接` / `## 相关阅读` 里的列表项 | `- [标题：URL](URL)` |
| 图片与图片来源斜体标注 | `![alt](URL)`、`*图片来源：[官网](URL)*`、`*图：…*` |
| front-matter 的 `cover` / YAML 字段 | `cover: https://…` |
| 代码块 / 可复制指令里的裸 URL | `请根据 https://… 安装 @…` |
| 表格单元格内的链接 | 表格里的链接保持原写法 |
| 官方原话所在的 `>` 引用块里原本就带的链接 | 保持引用块，不再额外加引号 |

列表项和图片来源标注最容易被机械套用 —— **尤其别给图注里的链接补引号**。

## 十、真实感要求

每篇至少 2 处来自亲身体验的表述，且尽量**带具体日期**：

- 「11 月 5 日收到官方确认邮件时……」
- 「评论区问得最多的就一句话：……」
- 「我自己对比下来，…… 那条更自然一点」
- 「最让我意外的是……」

**不要写成公关稿。** 不编造阅读量、价格、权益；拿不到的数据宁可不写。
