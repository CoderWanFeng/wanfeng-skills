## 二、十条硬模式

### P1 标题：利益前置，不玩悬念

公式：`免费 / 白嫖 / 领 + 具体数字 + 平台或产品名 + 低门槛承诺`

- 数字必须**具体到单位**：`200 美元`、`3 万积分`、`3 步`、`12 块`；不写「大幅」「超多」「海量」。
- 后半段给承诺或结果：`亲测有效`、`教程来了`、`简单到 3 步就出片`、`发布新版本`。
- 4/4 标题都含产品名，4/4 都含具体数字，4/4 都在前 15 字里把利益说完。
- **禁用**：`揭秘` `震惊` `不看后悔` `深度解析` `万字长文`。悬念可以有，但必须挂在具体利益后面（第 1 篇的「？…不然你以为呢」）。

### P2 开头：固定问候 + 第一句就给结果

- 固定开场白 **4/4**：`大家好，我是程序员晚枫。`（第 3 篇用「这里是」）。
- 第一屏直接抛结果，不铺垫：
  - 「**WorkBuddy 的 3 万积分，我领到了。**」
  - 「最近有个好消息，想跟大家分享：**我第 2 年成为 Qoder 大使了。**」
  - 「上次把 Skill 发出来之后，评论区问得最多的就一句话：想试一下，是不是必须先充值？」
- 立刻给**具体时间 / 身份 / 事件**建立可信度：`11 月 5 日收到官方确认邮件`、`8 月 29 日深圳站授勋`、`10 月 17 日重庆首场沙龙`、`周末参加腾讯云西部架构师峰会`。
- 禁止：`随着人工智能技术的发展……`、`近年来……`、`本文将从三个方面分析……`。

### P3 把读者的真实原话当钩子

- 直接引用评论区/群里的原话，而不是自己编一个「很多朋友问」：
  - 「评论区问得最多的就一句话：**想试一下，是不是必须先给 MiniMax 充值？**」
  - 「评论区里排前面的回复是『太贵了，等涨工资再说』。」
- 顺序：先替读者把顾虑说出来 → 给一句干脆的答案（「答案是『是』」）→ 再展开。

### P4 主动亮短板（最不可省，也最容易被 AI 写丢）

**每篇至少 1 处，且必须放在读者做决策之前，不能藏到文末。** 原文证据：

- 「**代价我先摊开说**：这条积分的免费路只能出画面，出不了你的声音，效果也不如 MiniMax 那条。」
- 「积分路线做不到的事，**我也不会绕着说**。」
- 「**有了支持，不等于只剩好评。** 好用的地方讲清楚，不好用的地方也说出来。」
- 引用官方邮件原话（用 `>` 引用块）：「我们不需要您说 Qoder 有多好，只需要您把真实用过的东西写下来，包括哪里不好用。这比任何宣传都有价值。」
- 第三方评测指出不足后直接认：「**这几条我认。** 费用数字在不同文件里确实有几处对不上，接下来的版本会把价格表收敛到一处。」
- 明确区分「官方说的」与「我实测的」：「哪些来自官方，哪些是我的体验，会明确区分。」

落地动作：写「能做什么」时，**同一节里必须写清「不能做什么 / 差在哪 / 要花多少钱」**。

### P5 共情与自嘲，永远站读者一边

- 「**大家都是靠薅免费额过日子的穷人，懂你。**」
- 「说白了，掏十几块去试一个 AI 工具，对大多数人真不算小数目。」
- 「**免费又好用的东西，目前 PDD 都做不到。**」
- 「不然你以为呢？」（口语插话，配一个表情）
- 常用过渡词：`说白了`、`说简单一点`、`一句话`、`摊开说`、`这点我不想让你踩坑`。
- 只嘲讽**现象和自己**，绝不嘲讽具体的人；不制造焦虑、不催单。

### P6 结构按文章类型分叉，先给地图再走路

**4 篇没有一篇讲 AI 原理** —— 不要为了凑「每篇必含原理段」硬塞一段科普，那会打断实操节奏。

| 类型 | 主体 `##` 数 | 小标题风格 | AI 原理段 | 典型递进 |
|---|---|---|---|---|
| 科普 / 观点 | ≤ 3 | 判断句，不像目录 | **必含** | 现象 → 为什么 → 原理 → 回到现实 |
| 手把手教程 | 4–6 | `01 / 02 / 03` 编号 + 动作 | 不必 | 准备工作 → 为什么值得 → 步骤 → 跑通后能做什么 |
| 产品发布 / 评测 | 6–8 | 口语短句 | 不必 | 能做什么 → 怎么装 → 开工先选哪条路 → 准备什么 → 费用与边界 → 第三方评测 → 现在动手 |
| 免费福利 / 活动 | 3–5 | 「不当 X，也有 Y 的办法」 | 不必 | 我领到了 → 普通人怎么领 → 进阶申请 → 线下/下一步 |
| 合作 / 身份公告 | 3 | 时间线 | 不必 | 去年 → 今年 → 接下来能给大家带来什么 |

- 教程类开头明说地图：「**全文分两部分：准备工作和实操教程。你只需要先把准备工作做完，再往下按教程一步步操作，就能跑通。**」
- 每节收尾给一句加粗小结：「**一句话：想先试试水，走积分；想用自己的声音说话，走 MiniMax。**」
- 用 `* * *` 分隔线分节，不跳级使用 `###`。

### P7 关键决策信息一律表格化

读者要**做选择 / 花钱 / 照着做**的地方，优先表格而不是长段落。4 篇实际用到：

- 两条路线的逐项对比（画面 / 声音 / 字幕 / 花费 / 前置条件）
- 成长计划的任务—奖励表
- 「说清四件事」的需求要素表
- 费用明细表（项目 / 参考费用 / 说明）
- 第三方评测五维度得分表

### P8 证据链：截图 + 图注 + 官方原话 + 第三方数据

- 每张截图下方一行斜体 `*图片来源：…*`，写明**谁提供的 / 出自哪个页面 / 截取日期**，例如「*图片来源：Qoder 官方 B 站视频分享卡片，由程序员晚枫提供*」。
- 官方邮件、证书、评测报告原话用 `>` 引用块，不当成自己的话转述。
- 第三方评测给分 + 分项表，**连「不足」一起写**（「它也点出了不足：少量说明前后不一致」）。
- 权益 / 费用 / 入选类信息必须带口径：`是否入选由官方评审决定`、`以官方审核和实际安排为准`、`具体费用以平台为准`、`技能显示的是预估，不是最终账单`、`领取时仍按当前账号的活动规则来`。

### P9 结尾：具体互动 + 可复制指令 + 入口

- 互动要具体到能一句话回答：「看明白的点个赞。」「💬 **来评论区聊聊**：你最想先做哪一类视频：品牌片、投放素材，还是短剧？评论区打出来。」
- 给**可直接复制**的一句指令：`@晚枫数字人 帮我生成数字人`、`请根据 https://skillhub.cn/install/skillhub.md，安装 @…`。
- 给入口：注册链接、SkillHub 发布页、GitHub 开源仓库、活动报名页。
- 关联推荐自己的其它 Skill / `## 相关阅读`（2–4 篇）。
- **固定 Slogan 按类型**：教程、福利、产品发布类用
  ```
  **科技不高冷，AI很好用。**
  我是晚枫，关注我，带你一起玩AI！
  ```
  合作 / 身份公告类**可以不硬塞**，换成克制的收束（第 1 篇：「接下来，就从一个个具体案例开始。」）。

### P10 排版

- 段落 1–3 行，单句成段很常见；手机端阅读优先。
- 加粗只给**结论 / 费用 / 边界**，每段不超过 2 处。
- 少量 emoji（👉 💬），不堆砌。
- 零术语；出现术语立刻用一句人话解释（「TRACE 是 SkillHub 用来判断一个 Skill 到底好不好用的五维体系……」）。

## 三、反模式（写完逐条排除）

- ❌ 通篇只夸、不写代价和边界 —— 公关稿，直接违背 P4
- ❌ 把「我拿到了福利 / 我成了大使」写成炫耀，没转成「读者能怎么用」
- ❌ 悬念式标题，前半段不给利益
- ❌ 数字写成「大幅」「超多」「相当可观」
- ❌ 为了凑「必含 AI 原理段」在教程里硬插科普
- ❌ 术语不解释、评论区原话改写成「很多用户关注」
- ❌ 参考链接、Slogan 不分类型一律强塞
- ❌ 编造阅读量、价格、权益；官方口径缺失
