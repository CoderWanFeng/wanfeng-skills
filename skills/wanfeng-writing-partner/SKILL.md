# 晚枫写作搭子（wanfeng-writing-partner）

> **它替你解决的事**：从「看到一个 AI 热点/产品，想写一篇公众号文章」到「本地有一份可以直接复制进编辑器的 Markdown 成稿」，中间所有步骤——查资料、起标题、搭结构、做配图、传图床、检查格式——它都带你走一遍。
>
> **你会拿到**：一篇 1500–4000 字的中文长文 Markdown 文件，包含 frontmatter、正文、配图外链、参考链接和结尾。
>
> **这套方法来自晚枫实际在用的流程 + 4 篇高互动实证文章的写法归纳**，不是理论框架。
> **动笔前先判文章类型**（科普 / 教程 / 产品发布 / 免费福利 / 合作公告），不同类型用不同结构 —— 见 [references/viral-patterns.md](references/viral-patterns.md)。

---

## 何时使用

✅ **使用本 Skill 的场景**：

- 看到一个 AI 热点/产品发布，想写一篇公众号文章
- 已有素材（官方文档、截图、体验记录），需要整理成结构化长文
- 文章写完了，需要起标题、检查格式、生成配图
- 需要把网页截图脱敏后上传图床、插入文章
- 想把一篇旧文章按新规范改写

❌ **不要使用**：

- 纯代码开发文档（用 repowiki-generator）
- 短视频脚本（用 knowledge-short-video）
- 小红书笔记（本 Skill 面向 1500+ 字长文）

## 第0步 · 首次提示前准备本地示例（必须先执行）

**触发时机**：Agent 实际调用本 Skill、加载正文后，在第一次业务提示、提问或让用户选择之前执行本步骤；仅安装、扫描技能列表或读取 frontmatter 不会自动运行脚本。即便用户只需要起标题、配图或脱敏，也先完成本步骤。用户明确禁止写文件或宿主要求授权时，遵守其限制，不绕过授权。

### 生成与保留规则

- `examples_zh` / `examples_en` 是平台入口示例，**各最多 3 条**；更多示例只在运行时生成到用户项目，禁止回写 frontmatter。
- 从用户指定的项目或当前已打开的工作区确定项目根目录，不把 Skill 安装目录当项目，不猜测用户主目录、不扫描私人资料。输出固定为 `<用户项目>/workflow/写作搭子/示例/`。
- 默认生成 **12 类场景，每类中文请求和英文请求各 1 条，共 24 条**：热点长文、官方文档教程、产品体验评测、标题优化、正文结构、旧文改写、暖白流程插图、网页截图规划、截图脱敏、图床上传、图片与引用链接、发布前检查。
- 每类单独一个 Markdown 文件，包含「需要准备、中文请求、英文请求、预期产物、注意边界」，另生成 `00-使用说明.md` 作为索引。内容由 [scripts/init_examples.py](scripts/init_examples.py) 的场景规则生成。
- 示例只教用户怎么提需求，产品、素材、URL 用明确占位符；不生成冒充实测的完整文章，不包含真实账号、配置或密钥。
- 初始化仅离线写文本：**不执行示例请求、不联网、不安装依赖、不绘图、不上传图床、不发布、不调用付费接口**。
- 每个项目首次调用时生成，后续调用检查并只补缺；已存在的非空 UTF-8 文件保留，包括用户修改的内容。空文件、目录占位、符号链接或权限问题均报错，不自动覆盖、删除或跟随。

### Agent 执行动作

1. 解析本 Skill 实际所在目录和用户项目目录，将下方占位路径替换成真实路径；**由 Agent 执行，不先要求用户手工建示例或选择场景**：

   ```bash
   python3 "<Skill所在目录>/scripts/init_examples.py" --project "<用户项目目录>"
   ```

   仅依赖 Python 3 标准库；如果现有 Python 3 的命令是 `python`，使用已经确认的该解释器，不自动安装。

2. 检查退出码为 0、JSON 中 `ok` 为 `true`，确认 `index` 和示例文件已实际存在。根据 `created` / `kept` 如实说明新建或复用，不把保留的用户改写文件说成刚生成的默认内容。
3. 完成后才给第一次业务提示：提供本地索引链接，最多展示 2–3 个相关入口；用户已经说清需求时直接进入对应步骤，不强迫重复选择。需要补充信息时一次只问一个缺失项。
4. 若没有 Python / 执行工具，但有文件写入工具且已知可写的用户项目，可读取脚本中的场景规则，按相同目录、数量、字段和保留规则生成，并逐个确认文件存在且非空；不能只在聊天中贴示例就声称已落盘。
5. 若没有明确项目、写入权限、写文件工具或用户禁止落盘，不强行生成。首次响应先如实说明“本地示例尚未准备”，可提供不落盘的简短示例并继续力所能及的帮助；仅在确有必要时询问目录或请求授权。文件冲突保留原状，说明冲突路径，待用户处理后重试。

## 七步工作流

### 第1步 · 确认选题与素材

第0步完成后，复用用户已给的信息，逐项补齐三件事（一次只问一个缺失项）：

1. **写什么**：具体产品名、事件或功能（必须有专有名词，不接受"AI 行业"这种泛指）
2. **给谁看**：目标读者是谁，能不能用这个产品
3. **素材在哪**：官方文档 URL、已有截图、体验记录

**事实核验**（不可跳过）：

- 打开官方文档/产品页，确认功能描述、价格、规则与你的理解一致
- 数字（价格、用户数、日期）必须有可溯源的出处
- 规则类信息（退款、收费、限制）以官方当前文档为准，不凭旧记忆

### 第2步 · 起标题

用 `lengyi-title` 方法（如果已安装），或按以下规则（**优先用实证模板**）：

- **利益前置公式**（4 篇高互动样本 4/4 命中）：`免费/白嫖/领 + 具体数字 + 平台或产品名 + 低门槛承诺`
  - 例：`免费领取 WorkBuddy 3万积分，教程来了！`、`在 WorkBuddy 里做视频，简单到 3 步就出片`
- 建议 **18–32 字**，硬上限 36 字（含英文产品名可到 36）
- 必须含具体产品名**和**具体数字（带单位；不写「大幅」「超多」「海量」）
- 前 15 字把利益说完，后半段给结果或承诺，不重复前半段
- 禁用 `揭秘` `震惊` `不看后悔` `深度解析` 类空洞词

挑 6–8 个候选，实测字数，选最佳。详见 [references/viral-patterns.md](references/viral-patterns.md) P1。

### 第3步 · 判类型 + 搭正文结构

**先判类型再搭骨架**。4 篇实证里**没有一篇讲 AI 原理**，别为了凑旧规范硬塞科普段：

| 类型 | 主体 `##` 数 | 小标题风格 | AI 原理段 |
|---|---|---|---|
| 科普 / 观点 | ≤ 3 | 判断句，不像目录 | **必含** |
| 手把手教程 | 4–6 | `01 / 02 / 03` 编号 + 动作 | 不必 |
| 产品发布 / 评测 | 6–8 | 口语短句 | 不必 |
| 免费福利 / 活动 | 3–5 | 「不当 X，也有 Y 的办法」 | 不必 |
| 合作 / 身份公告 | 3 | 时间线（去年 → 今年 → 接下来） | 不必 |

```
[开头] 固定问候「大家好，我是程序员晚枫」+ 第一句给结果 + 具体日期/身份 + 读者原话当钩子
   ↓
[主体] 按上表选结构，语义递进
   - 每段 ≤ 3 行，重点加粗
   - 决策 / 对比 / 费用 / 评分信息一律表格化
   - 写「能做什么」的同一节必须写「不能做什么 / 差在哪 / 多少钱」
   - 区分「官方说的」与「我实测的」；官方原话用 > 引用块
   ↓
[结尾] 升华 + 具体互动 + 一条可复制指令 + 入口 + Slogan（按类型）+ 参考链接 + 相关阅读 + 引导图
```

**四条实证硬规则**（详见 [references/viral-patterns.md](references/viral-patterns.md)）：

1. **亮短板**：每篇至少 1 处主动摊开代价 / 边界，放在读者做决策之前，不藏文末；第三方评测指出不足要照写并认下来。
2. **共情自嘲**：站读者一边（「大家都是靠薅免费额过日子的穷人，懂你」），只嘲讽现象和自己，不催单。
3. **证据链**：每张截图配 `*图片来源：…*` 斜体注；官方邮件 / 证书 / 报告原话用 `>` 引用块；评测连分项得分和不足一起写。
4. **口径严谨**：权益、费用、入选、规则类信息带「以官方审核和实际安排为准」「技能显示的是预估，不是最终账单」。

**Frontmatter 格式**（5 字段，顺序固定）：

```yaml
---
title: 文章标题
date: YYYY-MM-DD HH:MM:SS
tags: [公众号文章, 标签1, 标签2]
categories: [公众号文章]
cover: 已验证的封面图URL
---
```

详细写作规范见 [references/writing-guide.md](references/writing-guide.md)；实证写法见 [references/viral-patterns.md](references/viral-patterns.md)。

### 第4步 · 配图：截图或插图

每张图先问：**这一段在讲什么？**

| 内容类型 | 用什么图 | 方法 |
|---------|---------|------|
| 工具/网站/后台怎么用 | **真实截图** | 打开官网 → 截取相关区域 → 脱敏 |
| 流程/原理/数据/对比 | **暖白插图** | 运行 `scripts/warm_illustration.py` |
| 品牌/产品/发布会 | 官网素材 | 从 Press Kit 或产品页下载 |

**截图规范**：

1. 打开官方页面，只截必要区域（不留浏览器地址栏和无关侧栏）
2. 等比缩放到 1000–1200px 宽
3. 脱敏：遮盖真实姓名、头像、账号 ID、邮箱、手机号、订单号
4. 商品公开昵称（如开发者展示名）可以保留
5. 图片下方用斜体标注来源

**插图规范**：

- 暖白底 `#FAF7F1` + 橙红强调 `#F07628`，色板固定不可自创
- 2 倍超采样，LANCZOS 缩回，边缘不毛刺
- 所有文字走 `fit_text`（自适应宽度，防溢出）
- 一张图只讲一件事
- 生成后逐张打开目检

详细配图流程见 [references/image-workflow.md](references/image-workflow.md)。

### 第5步 · 上传图床

图片处理完，需要上传到**你自己的图床**，拿到公开 URL 后才能插入文章。

**图床选择**（按难度递增）：

| 方案 | 适合谁 | 特点 |
|------|--------|------|
| [SM.MS](https://sm.ms) | 新手 | 注册即用，免费额度够日常 |
| [图壳](https://imgkr.com) | 中文用户 | 国内访问快 |
| GitHub + PicGo | 有 GitHub 账号 | 免费无限容量，需配置仓库和 Token |
| 阿里云 OSS / 腾讯云 COS | 长期运营 | 稳定、有 CDN，但按量付费 |

**通用流程**：

1. 本地图片准备好（JPG/PNG，语义文件名如 `261119-product-screenshot.jpg`）
2. 上传到图床（用图床自带面板，或 PicGo 等客户端工具）
3. 拿到返回的**公开直链 URL**
4. 浏览器打开 URL 验证：状态 200、Content-Type 是 image、尺寸正常
5. 在文章里写 `![描述](你的图床URL)`

**PicGo 命令行用法**（如果你选择用 PicGo）：

```bash
# 安装（一次性）
npm install -g picgo

# 上传单张（必须传绝对路径，不能用通配符）
picgo upload /完整路径/图片文件名.jpg

# 指定配置文件
picgo -c /你的配置路径/config.json upload /完整路径/图片.jpg
```

> ⚠️ 具体图床配置（仓库地址、Token、域名）因人而异。本 Skill 不携带任何人的图床信息，请自行配置属于你的图床。

### 第6步 · 插入图片与链接

图片 URL 确认后，按格式写入文章：

```markdown
![这段在解释什么](https://你的图床/文件名.jpg)

*图：说明文字 · 来源：[官方页面名：https://example.com/page](https://example.com/page)*
```

**链接格式**：非微信链接本体统一 `[标题：完整URL](完整URL)`，**再按它在正文里的位置包装**，本体写法不变：

1. **单独成段**（一段里只有这一条链接）→ 用 `>` 引用块包住：

   ```markdown
   > [WorkBuddy 官方活动页：https://example.com/act](https://example.com/act)
   ```

2. **嵌在正文句子里** → 链接前后用**英文引号 `"`** 包住：

   ```markdown
   活动规则写在 "[WorkBuddy 官方说明：https://example.com/rules](https://example.com/rules)" 这一页。
   ```

**保持原格式、不套上面两条**：`### 参考链接` / `## 相关阅读` 列表项、图片与 `*图片来源：…*` 图注、front-matter、代码块内裸 URL、表格单元格里的链接、官方原话引用块里原本带的链接（详见 [references/writing-guide.md](references/writing-guide.md) §9.3）。微信文章间的链接仍是 `[标题](https://mp.weixin.qq.com/s/xxx)`，不加 URL 重复。

### 第7步 · 发布前检查

逐项确认（**标 ⭐ 的按文章类型判断，不是一刀切**）：

- [ ] 标题 18–32 字（硬上限 36），含**具体数字 + 产品名**，前 15 字把利益说完
- [ ] 正文 1500–4000 字
- [ ] ⭐ 主体 `##` 数符合所选类型上限（科普 ≤3 / 教程 ≤6 / 发布 ≤8 / 福利 ≤5 / 公告 ≤4）
- [ ] ⭐ 科普类才有「讲透 AI 原理」段；教程 / 发布 / 福利 / 公告类不硬塞
- [ ] **至少 1 处主动亮短板**，且位于读者做决策之前
- [ ] 至少 1 处共情 / 自嘲；区分「官方说的」与「我实测的」
- [ ] 决策 / 对比 / 费用信息已表格化；每张图有 `*图片来源：…*`
- [ ] 权益 / 费用 / 入选类信息带「以官方为准」口径
- [ ] 结尾有具体互动 + 一条可复制指令 + 入口
- [ ] 所有数字可溯源（官方文档 / 自己的截图），无编造
- [ ] 图片 URL 全部能打开（HTTP 200 + image content-type），没有占位链接
- [ ] 截图已脱敏（无真实姓名、头像、账号 ID）
- [ ] 链接格式正确（非微信链接用 `[标题：URL](URL)`）
- [ ] 链接按位置包装：单独成段用 `> 引用块`，嵌入正文用英文引号 `"` 包住
- [ ] ⭐ 参考链接：科普 / 评测 / 福利类 ≥ 3 条；纯教程 / 公告类不强求
- [ ] ⭐ 结尾 Slogan：教程 / 福利 / 发布类一字不差；合作公告类可省略
- [ ] 代码围栏配对（` ``` ` 数量为偶数）

用 `scripts/check_article.py --type <类型> <文章.md>` 自动检查大部分项；`--type auto` 自动推断类型。

## 边界与安全

| 行为 | 是否执行 |
|------|---------|
| 联网查官方文档核实事实 | ✅ |
| 生成暖白风格插图 | ✅ |
| 打开网页截图 | ✅ |
| 裁剪/脱敏截图 | ✅ |
| 上传到用户自己的图床 | ✅（用户授权后） |
| 部署网站 / 发布到公众号 | ❌ |

| 暴露任何人的图床地址、账号、密钥 | ❌ |

## 失败兜底

遇到以下情况，按「原文 + 人话 + 根因 + 3 步 + 兜底」回应：

- 官方页面打不开：换浏览器 UA 重试 → 用 WebFetch → 找缓存/存档 → 标注"截至发稿时无法验证"
- 图床上传失败：检查网络 → 确认文件路径是绝对路径 → 手动拖入图床面板 → 换图床
- 插图文字溢出：减小内容量或增大卡片尺寸 → 拆成两张图
