# 微信公众号 · 涨粉分析模块

> **状态**：✅ 已实现（v1.1.0 新增）
> **定位**：把 `../hit-methodology.md` 的通用方法论，翻译成公众号能直接算的口径与动作。主线只有一条 —— **阅读怎么变成关注，以及为什么没变成**。
> **数据来源**：第一方后台导出，**不联网、不需要 API Key**。

---

## 0. 适用范围与边界

| 项 | 说明 |
|---|---|
| 输入 | `账号数据/wechat-公众号/<账号>/<YYMMDD>/` 下的 `user_analysis.xls`（HTML 伪 xls）、`tendency_*.xls`；可选：图文分析单篇导出 |
| 现有解析能力 | **账号级**：关注趋势、阅读趋势、渠道分布、文章排行。**没有单篇涨粉明细** |
| 不做什么 | 不生成文章、不预测爆款、不把公众号阅读和视频平台播放相加 |
| 硬依赖 | 无 |

> ⚠️ **本模块移植的是分析逻辑，不是数据管道。**「公众号数据雷达」专家的 6 个技能走红狐 RedFox API（需 `REDFOX_API_KEY`，本机未配置），拿的是**第三方公开榜单**；本模块处理的是**第一方后台数据**，两套口径**严禁混算**。专家技能在这里只贡献方法，不贡献数据。

## 1. 口径字典（「口径必须显式」的公众号落地）

### 1.1 账号级（现有脚本可拿到）

| 字段 | 含义 | 坑 |
|---|---|---|
| 送达人数 | 推送覆盖人数，**被屏蔽的不计入** | 不等于粉丝总数 |
| 阅读人数 | **去重**，且**含非粉丝** | 这是「每千阅读涨粉」的正确分母；含非粉正是拉新口径 |
| 阅读次数 | 含同一人重复打开 | 不能和阅读人数混用，会虚高 |
| 累积关注人数 | 历史累计 | 累计值，不是当期增量 |
| 净增关注人数 | 新增关注 − 取消关注 | 日增量，可与图文数据对齐 |
| 取消关注人数 | 取关 | 算留存要用 |
| 图文转化率 | 阅读人数 ÷ 送达人数 | 衡量标题 / 封面 / 推送时段的**第一跳** |

### 1.2 单篇级（官方字段，目前缺）

来源：微信开放社区「获取发表内容详细数据」接口 / 后台图文分析单篇明细。

| 官方字段 | 含义 | 对涨粉的用途 |
|---|---|---|
| `read_subscribe_user` | **阅读后关注人数** | ⭐ 单篇涨粉的分子，公众号版的「涨粉数」 |
| `read_jump_position` | 5 段跳出分布 | 定位读者在哪一段跑掉 → 关注引导该放哪 |
| `read_finish_rate` | 读完率 | 承接内容的质量信号 |
| `read_avg_activetime` | 平均阅读时长 | 辅助判断信息密度 |
| `read_user_source` | 消息 / 会话 / 朋友圈 / 推荐 / 搜一搜 等来源 | 拆分存量粉与增量曝光，见 §5 |

### 1.3 三条致命坑

1. **口径是「发表日 → 统计日」累计，不是当日增量。** 拿它和视频平台的「当日播放」并排比，或拿不同统计日的文章互比，都会得出假结论。所有单篇对比必须**统一统计日**。
2. **图文详解只保留 7 天。** 单篇数据过期永久缺失 —— 这不是导出麻烦，是**采集时机**问题：发布后 7 天内必须落盘，否则这一篇永远进不了四象限。
3. **页面摘录 ≠ 原始导出。** 页面是约数、常为累计；报告里必须注明来源类型，两者不能混算。

## 2. 公众号涨粉漏斗（本模块核心）

```text
送达人数
  ↓ ① 图文转化率 = 阅读人数 ÷ 送达人数        ← 标题 / 封面 / 推送时段
阅读人数（去重、含非粉）
  ↓ ② 读完率 read_finish_rate                 ← 开头 / 结构 / 长度
读完的人
  ↓ ③ 阅读后关注率 = read_subscribe_user ÷ 阅读人数   ← 关注引导 + 内容价值
新增关注
  ↓ ④ 留存率 = (新增关注 − 取关) ÷ 新增关注    ← 承接内容是否兑现承诺
净增关注
```

### 卡点诊断表（每期必填）

| 症状 | 大概率卡在哪一跳 | 该改什么 | 不该改什么 |
|---|---|---|---|
| 阅读人数低、送达正常 | ① 打开 | 标题具体化、封面、推送时段 | 别急着改正文 |
| 阅读高但读完率低 | ② 读完 | 开头 3 行给结论、砍铺垫、加小标题 | 别加关注引导（人还没读完） |
| 读完率高但关注极少 | ③ 转化 | 结尾关注理由、系列预告、资料包钩子 | 别再堆信息量 |
| 新增关注多但净增少 | ④ 留存 | 检查承诺是否兑现、系列是否断更、取关归因到内容类型 | 别只盯拉新 |

> 每期报告必须定位到「卡在哪一跳」，而不是笼统写「涨粉慢」。这与通用方法论的「放量 / 承接」对应：卡 ①② 是分发与包装问题，卡 ③④ 才是内容价值问题。

## 3. 通用效率指标的公众号翻译

| 通用指标（`../hit-methodology.md`） | 公众号公式 | 注意 |
|---|---|---|
| 每千播放涨粉 | **每千阅读涨粉 = `read_subscribe_user` ÷ 阅读人数 × 1000** | 分母是**阅读人数**（去重含非粉），不是阅读次数、不是送达 |
| 每千播放收藏 | 每千阅读在看 / 分享 = 对应数 ÷ 阅读人数 × 1000 | 公众号「收藏」权重远低于视频平台，主看**在看 + 分享** |
| 每千播放互动 | (在看 + 点赞 + 评论 + 分享) ÷ 阅读人数 × 1000 | 只在同一口径内比较 |
| 取关率 | 取消关注 ÷ 新增关注 | 沿用通用定义 |

**账号级退化公式**（只有 `tendency_*.xls`、拿不到单篇字段时）：

```text
每千阅读涨粉 ≈ 净增关注人数 ÷ 阅读人数 × 1000
```

→ 只能做**账号级趋势**，不能下「哪篇涨粉」的结论；报告必须标注「账号级估算，非单篇归因」。

⚠️ **公众号没有「播放」**。禁止把「阅读人数」代入跨平台的每千播放榜，也禁止和视频号 / B站做数值排名（L1 纪律）。

## 4. 单篇级归因：四象限与基线

沿用 `../hit-methodology.md` §三，只改分母：

| 象限 | x = 阅读人数（中位数切） | y = 每千阅读涨粉（中位数切） | 分析判定 |
|---|---|---|---|
| 高 × 高 | 真爆款 | 标记为高价值结构，待验证是否可复用 | |
| 高 × 低 | 伪爆款 | 分发 / 推荐红利，不复制 | |
| 低 × 高 | 埋没好内容 | 判定为分发不足、题材有效；**不代做重发或改标题** | |
| 低 × 低 | 无效内容 | 不分析 | |

**硬规则**

- 用**中位数**切，不用「1 万阅读」这类绝对阈值
- **固定观察窗口**：统一取「发布后第 7 天」或「发布后第 30 天」的累计快照，不可混用
- 基线用**同平台、同内容类型、同窗口**的中位数 + P75，不用均值
- 样本 < 3 篇 → 只写「待验证」，不成规律（§7）

### 当前缺口与补齐

| 缺口 | 影响哪些结论 | 补齐方式 | 优先级 |
|---|---|---|---|
| 无单篇 `read_subscribe_user` | 四象限为空、无法定位卡在哪一跳、公众号进不了内容级归因 | 发布后 **7 天内**导出单篇图文分析，或通过开放平台接口采集，落盘到 `账号数据/wechat-公众号/<账号>/<YYMMDD>/` | **高** |
| 无 `read_user_source` | 分不清涨粉来自存量粉还是推荐增量 | 同上 | 中 |
| 统计日不统一 | 累计口径跨文章不可比 | 采集时记录 `统计日` 字段，文件命名带日期 | 高 |

> `../report-spec.md` §3.5 已写明「公众号无单作品数据」。本模块生效后该表**仍可能留空**，但必须在表下补一句「未取得单篇明细，卡点诊断见 `platforms/wechat.md` §2」——不能默默跳过。

## 5. 来源分层与分段流失（公众号专属）

### 5.1 `read_user_source` 分层

| 来源 | 性质 | 涨粉解读 |
|---|---|---|
| 消息 / 会话 | 存量粉丝 | 阅读后关注率往往较高，但**是老读者，不等于拉新** |
| 朋友圈 / 推荐 / 搜一搜 | 增量曝光 | 决定能不能破圈；占比高但涨粉低 = 放量内容 |

**辛普森悖论检查（必做）**：按来源分组算每千阅读涨粉。若「整体涨粉率上升」但**每个来源分组都下降**，说明是来源结构变了（推荐占比暴增），不是内容变好 —— 此时不能写「内容改进有效」。

**「放量 / 承接」在公众号的判据**

- 推荐 + 搜一搜占比高、每千阅读涨粉低 → 判定为放量内容
- 消息 / 会话为主、每千阅读涨粉高 → 判定为承接内容（高价值结构，账号护城河；是否系列化由内容侧决定）

### 5.2 `read_jump_position` 分段流失

5 段跳出分布 → 定位读者在哪一段走掉 → **判定流失发生在哪一段**（数据结论）。
不输出「关注引导应该放第几段」这类内容侧改动建议。

| 流失集中段 | 诊断 | 动作 |
|---|---|---|
| 第 1 段 | 开头没接住标题承诺 | 前 3 行给结论，别铺垫 |
| 中段 | 信息密度或结构问题 | 加小标题、清单化 |
| 末段 | 读完但没关注 | 结尾补「为什么要关注」+ 系列预告 |

> 关注引导放在**流失最少的那一段之后**，不要一律堆在文末。这是可 A/B 的变量（§7）。

## 6. 移植自「公众号数据雷达」的涨粉分析逻辑

> 以下 6 条只取**分析方法**，不取数据管道，不依赖红狐 API Key。

### 6.1 反例对照法（最优先，与「必写反例」完全对齐）

专家的「同作者爆文 vs 最低阅读文对比」改成**涨粉口径**：取本期 **每千阅读涨粉最高 1 篇** 与 **最低 1 篇**（阅读量需过下限，见 6.2），逐项对比：

| 对比项 | 要回答什么 |
|---|---|
| 选题 / 切入点 | 是「具体额度」还是泛介绍？有没有点名具体任务 |
| 标题结构 | 数字、权益承诺、使用门槛、身份词、对比反差 |
| 来源结构 | 是推荐带量还是老读者打开 |
| 读完率 / 分段流失 | 差异在哪一段产生 |
| 关注引导位置 | 有没有、放在第几段、有没有系列预告 |
| 是否属于系列 | 系列第几篇，前序是否导流 |

**输出必须是一条可证伪的归因判断**（如「最高涨粉篇在 `read_user_source` 的『搜一搜』占比上比最低篇高 X 个百分点」），不是「标题要写好」这类无法验证的建议。每条判断立刻配一条能推翻它的样本（`../hit-methodology.md` §四）。
本模块**只做差异归因，不产出标题、话术或改法**。

### 6.2 增长率口径与小基数防线

- 阅读增长率、涨粉增长率都可用，但**必须同时给绝对量**
- **小基数高增长无效**：单篇阅读人数低于「账号同期阅读中位数 × 0.2」或 < 500（取更严者）的，**不进增长率榜**，只标「样本过小」
- 增长率不能替代效率指标：阅读 +200% 而每千阅读涨粉下跌，是**变差**不是变好

### 6.3 三层加权对标（差距量化）

专家 `核心基础 40% + 运营变现 35% + 数据特征 25%` 改造为「自己 vs 对标号」的差距表：

| 层 | 权重 | 公众号可比的字段 |
|---|---|---|
| 核心基础 | 40% | 内容垂直度、发文频率、头条 / 次条结构 |
| 运营变现 | 35% | 系列化程度、关注引导话术、资料包钩子 |
| 数据特征 | 25% | 图文转化率、读完率、每千阅读涨粉、取关率 |

**对标号数据只能由用户提供，或后续作为可选外部输入接入**；没有数据时这一节写「未取得对标号，本期只做自身基线」，**不许编数**。

### 6.4 四维账号体检（描述性，不替代效率指标）

采用 `wechat-account-analyzer` 技能文件**实际口径**：内容健康度 / 用户活跃度 / 核心数据表现 / 运营规范性（百分制，S/A/B/C/D/E）。

⚠️ 两点纪律：

- 专家 prompt 里另有一套「内容力 / 传播力 / 增长力 / 商业力」说法，与本模块口径不一致 —— **以技能文件为准**，不要混用
- 体检分是**描述性打分**，不是涨粉因果结论；报告里必须和「每千阅读涨粉」分开写，不能拿评分高低解释涨粉

### 6.5 爆款四维拆解（只给已发布内容打标）

**四维拆解**（内容概述 / 热点利用 / 传播作用 / 达成效果）嫁接到 `../hit-methodology.md` §三第 ④ 步的「共现特征清单」，作为公众号版**评估编码维度**。仍要回全量内容数一遍，**只出现在头部才是真规律**。

- ✅ 只给**已发布**文章打这四维标签，再按标签分组比效率指标
- ❌ 不用它给未发布选题打分、排序或预测爆款
- ❌ 不采用外部方法论里的「三维先验评分（相关性 10 + 热度 3 + 时效 2）」—— 那是**发之前给候选选题排序**，属于创作侧，越界

### 6.6 高增长账号类型分析（可选外部输入）

若用户提供了对标号 / 榜单数据，只输出**赛道分布与共同特征的统计差异**。**必须与第一方数据分节写**，并标注来源与可信度降级（第三方口径 ≠ 后台口径）。不输出「该迁移什么到自己账号」这类选题建议。

## 7. 样本量、置信度与实验设计

沿用 `../hit-methodology.md` §五 / §七，公众号特例：

| 规则 | 公众号版 |
|---|---|
| 样本量 | < 3 篇只写「待验证」；单篇结论一律标低置信度 |
| 观察窗口 | 统一「发布后第 7 天」或「第 30 天」累计快照，**不混用** |
| 控制变量 | 一期只改一个：标题 / 封面 / 关注引导位置 / 系列钩子，四选一 |
| 判断指标 | **每千阅读涨粉**（主）+ 读完率（辅），不用阅读量 |
| 期间不偷看 | 公众号数据每日累计更新，中途看会诱导提前下结论 |
| 必写反例 | 每条规律配一条能推翻它的样本（§6.1） |
| 采集纪律 | 单篇数据 **7 天内**落盘，过期记为永久缺口 |

**置信度标准直接沿用 `../hit-methodology.md` §五表格，不另立标准。**

## 9. 后续落地（给接手的 AI）

当前 `scripts/parse_data.py` 只有账号级公众号解析，**不要造一个没有数据可算的空壳脚本**。按顺序推进：

1. **先补采集**：发布后 7 天内导出单篇图文分析，落盘命名 `图文分析_YYYYMMDD.xlsx`，**必须带 `统计日` 列**
2. `parse_data.py` 加 `parse_wechat_article()`，返回独立 key `wechat_article`（与 B站三口径同理，**不要 concat 进账号级表**）
3. 加 `analyze_wechat.py`（或 `analyze.py` 分支）：输入 `wechat_article`，输出漏斗 4 跳 + 每千阅读涨粉 + 四象限 + 反例对照表
4. `monthly_report.py` 的 `4.x` 填数函数接上，判断层仍由人写

**接口约定**：任何公众号单篇指标必须带 `统计日` 字段，否则禁止跨文章比较。
