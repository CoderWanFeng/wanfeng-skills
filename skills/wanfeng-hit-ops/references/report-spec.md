# 月度报告规范

> 章节结构、判断层写法、交付清单。
> 模板骨架在 [`../templates/月度报告模板.md`](../templates/月度报告模板.md)。

---

## 一、三层填充原则

| 层次 | 谁填 | 内容 | 判断标准 |
|---|---|---|---|
| **数据层** | 脚本 | 粉丝总览表、数据范围表、各平台整体表现、Top 内容榜、数据文件清单 | 能被算出来的，一律不让人手写 |
| **分析层** | **计算层**（`scripts/analysis/`） | 结论摘要、数据事实、分析判断、结构拆解、关键内容表现（带效率指标）、反例、跨平台结构规律、平台分工、缺口表、置信度分级、候选验证方向 | 能从数据算出的**事实与有限的推论**，一律不让人手写；但不决定取舍 |
| **判断层** | 人/AI | 跨平台取舍的最终判断、第六章采纳哪条方向、对外怎么讲、以及任何超出「已发布内容评估」的动作 | 需要判断的，一律不让脚本编；**不写标题、选题清单、脚本或排期** |

**为什么分开**：脚本编出来的结论会被当成事实。分层之后，「数字」和「解读」在文档里物理隔离，读者一眼能看出哪句是推断。

**计算层与分析层的边界**：计算层输出的是**带数据和依据的发现条目**——
现象 / 数据 / 判断 / 置信度依据 / 反例。它回答「数据说明了什么」，
不回答「所以该做什么」。后者是判断层的活。

## 二、章节结构（七章 + 附录）

```
一、结论摘要                  ← 人工
二、粉丝总览                  ← 自动（表）+ 人工（统一限制）
三、数据范围与可信度           ← 自动（表）+ 人工（本期缺口）
四、单平台分析 4.1~4.6        ← 自动（整体表现/关键内容表现）+ 人工（判断/拆解/反例）
五、跨平台综合分析 5.1~5.3    ← 人工
六、下期行动                  ← 人工
七、数据缺口与下一步采集       ← 人工
附录：本期数据文件清单          ← 自动
```

### 各章要求

| 章 | 必须有 | 常见错误 |
|---|---|---|
| 一、结论摘要 | 3~6 条，每条格式「平台 —— 现象 —— 数据 —— 判断」 | 写成流水账；只写现象不给数据；判断混在现象里 |
| 二、粉丝总览 | 表格 + 口径限制清单 | 把不同口径的数排在一起排名；漏掉「某平台没导出粉丝数」 |
| 三、数据范围与可信度 | 每个数据源的区间 + 来源 + 能支持什么结论 | 只写「数据来自后台」；不写缺失的账号 |
| 四、单平台分析 | 整体表现 → 数据事实 → 分析判断 → 结构拆解 → 关键内容表现 → 反例 | 没有反例；数据事实里夹判断 |
| 五、跨平台综合 | 内容结构规律 + 平台分工 + 最重要的数据问题 | 跨平台比播放量；规律没有反例；写成选题清单 |
| 六、下期行动 | 验证方向（带变量、样本、指标、窗口、止损）+ 必做（数据侧）+ 明确不做 | 「多发优质内容」这种没法验证的话；写出具体标题/选题 |
| 七、数据缺口 | 缺口 → 影响 → 补齐方式 → 优先级 | 只列缺口不说影响哪些结论 |
| 附录 | 文件清单 + 采集说明 | 路径写成相对路径让人找不到 |

## 三、每个平台小节的写法

### 3.1 整体表现（自动填）

账号级指标表。字段口径写在「说明」列里。

### 3.2 数据事实（人工）

**只写数字与倍数关系，不写判断。**

```
✅ 数据事实：后 15 天播放 160,695，前 15 天 228,854，减少 29.8%；
   但日播放中位数只降 8.7%（9,406 → 8,583），每千播放关注反而从 8.81 升到 9.12。

❌ 数据事实：流量在下滑，说明选题吸引力下降，需要尽快调整内容方向。
```

第二条把判断写进了「事实」，读者分不清哪句是数据、哪句是推断。

### 3.3 分析判断（人工）

**写含义、可能的原因、下一步，并标置信度。**

```
**分析判断（置信度：中高）：** 总量降幅（-29.8%）远大于日中位数降幅（-8.7%），
说明减少的是 10 月 21 日、24 日两个峰值，而多数日子的基础流量没有下滑。
分享率与关注效率没有同步恶化（每千播放关注 +3.6%），所以当前问题不是关注引导话术，
而是缺少同级别的高质量分发内容。下一步：把 10 月 21 日那条的选题结构找出来复用。
```

**置信度标准**：

| 置信度 | 条件 |
|---|---|
| 高 | 完整口径 + 可交叉验证 + 有反例检验过 + 样本 ≥ 10 |
| 中 | 单数据源 / 样本有限 / 有未排除的干扰因素 |
| 低 | 样本 < 3 / 只有页面摘录 / 窗口重叠 |

### 3.4 结构拆解（人工）

2~4 条，**每条带数据**。写结构，不写现象复述。

```
✅ - 头部 2 篇 GLM 笔记贡献 85.7% 观看、91.3% 涨粉，选题集中度过高
✅ - 每千播放收藏由 51.47 降至 36.68（-28.7%），增量流量偏浅层
❌ - 小红书表现不错，抖音一般
```

### 3.5 关键内容表现（自动填，有数据的平台）

单作品榜。脚本能填的平台：抖音、小红书、视频号。

**没有单作品数据的平台（B站、公众号、快手）**：该表留空，由人工补，或在表下写明「本期未取得单稿明细」。

> 📌 **公众号已有专属分析模块** [`platforms/wechat.md`](platforms/wechat.md)：即使该表留空，也必须在表下注明「未取得单篇明细，卡点诊断见 `platforms/wechat.md` §2」，并按该模块「报告落点」一节补上漏斗表、来源分层表、反例对照表与 4 条交付勾选。后续其它平台模块补齐后同样处理（见 [`platforms/README.md`](platforms/README.md)）。

### 3.6 反例（人工）

**每节必写，这是最值钱的部分。**

```
**反例（同样重要）：** 两篇 GLM 合计占 11 篇的 85.7% 观看，但「封面点击率不能单独解释流量」——
「GLM每天3亿Token」与「WorkBuddy的3万积分」封面点击率同为 11.6%，曝光却是 18,721 vs 358。
选题需求、初始受众反馈与平台分发同样重要，不能只优化封面。
```

## 四、跨平台综合（第五章）

### 5.1 内容结构规律

> 只描述**已发布内容**的共同结构，不给选题清单、不给新标题。

| 结构编码 / 共现特征 | 跨平台证据 | 当前判断 |
|---|---|---|
| `T6 + has_concrete_quota=是` | 小红书 GLM 两篇每千观看涨粉 9.60 / 6.00，其余免费类 0~4.93；视频号 GLM-5.3 每千播放涨粉 9.87 | 高置信度：判定为高价值结构（是否系列化由内容侧决定） |

**证据必须带数字**，且是**同口径**的数字。编码表见 [`hit-methodology.md`](hit-methodology.md) §八。

### 5.2 平台分工

同一主题在不同平台的表现差异 + 原因推断。

```
- 「具体额度型免费」—— 小红书负责拉新（曝光 18,721），视频号负责承接（每千播放涨粉 9.87），
  抖音负责放大（本地部署类每千播放涨粉仅 1.23，说明抖音用户不为「额度」而来）
```

### 5.3 本期最重要的 N 个数据问题

每条格式：**问题名 —— 现象+数据 → 需补采的数据 / 待验证的假设**。箭头右边**只写数据侧动作**，不写「该做什么内容」。

```
1. **涨粉效率被放量稀释：** 后半月播放 +122.4%，但每千播放收藏 -28.7%
   → 需补采「分内容类型」的收藏明细，验证是否被商单流量稀释（需先完成商单/自然分层）
2. **选题集中度过高：** 2 篇内容占 85.7% 观看
   → 样本仅 2 篇，标低置信度；需补样本后重算中位数与 P75，不写「该换什么方向」
```

## 五、下期行动（第六章）

> ⛔ **本章只写「验证方向」，不写内容。** 允许：待验证的编码方向 + 样本条数 + 判断指标 + 观察窗口 + 止损条件。
> 禁止：具体选题、标题文本、脚本、封面文案、发布排期。第六章是**实验设计**，不是内容计划。

### 验证方向（实验设计）

| 待验证的编码方向 | 名额（样本条数） | 验证设计（只描述变量） | 主要判断指标 | 观察窗口 |
|---|---:|---|---|---|
| `T6 + has_concrete_quota=是` | 3 | 同一模型，只改变「标题是否给出具体额度」，其余编码不变 | 每千播放涨粉 | 30 天 |

**判断指标必须是效率指标**，不能是播放量。详见 [`hit-methodology.md`](hit-methodology.md) §七（实验设计与止损）、§八（编码表）。

### 必做事项

用 `- [ ]` 勾选框，每条可验收。**只写数据侧动作**（补采哪份导出、补哪层分层、复算哪个指标），不写「写一条 XX 内容」。

### 明确不做

写下这期不做什么，附原因。

## 六、数据缺口（第七章）

| 缺口 | 影响 | 补齐方式 | 优先级 |
|---|---|---|---|
| 公众号「Python自动化办公社区」本期未取得 | 该账号近 3 个月无数据，无法判断是否掉量 | 切号后重新导出 | 高 |
| 视频号缺单条视频明细 | 峰值日无法归因到具体作品 | 导出「动态数据明细」 | 中 |

**每一行都要写「影响哪些结论」**——只列缺口不说影响，等于没列。

### 结论置信度

```
- **高置信度：** 「具体额度」比泛「免费」更有效（跨 2 个平台、4 篇样本、反例已检验）
- **中置信度：** 放量内容会稀释深度互动（B站单平台、30 天窗口）
- **待验证：** 封面点击率与曝光的关系（样本仅 2 条反例）
- **不可判断：** 快手本期涨粉为负，但样本只有 1 个账号、58 天、无法区分内容问题还是冷启动
```

## 七、交付清单

报告写完，逐条核对：

- [ ] 结论摘要每条都有数据支撑
- [ ] 数据范围表列全了所有用到的数据源
- [ ] 缺失的账号在「本期缺口」里单列了（不能默默不写）
- [ ] 每个平台小节都有「反例」
- [ ] 每条判断都标了置信度
- [ ] 数字之间没有跨平台排名
- [ ] 抽样指标用的是效率指标（每千播放涨粉/收藏），不是绝对播放量
- [ ] 验证方向有控制变量、样本量、判断指标、观察窗口、止损条件，且**只描述变量、不出现具体标题或选题文本**
- [ ] 完成「商单 / 自然」分层（未完成时相关结论已降级为低置信度并注明）
- [ ] 全篇没有出现任何新标题、选题清单、脚本、封面文案或排期建议
- [ ] 「明确不做」写了
- [ ] 数据缺口的每一行都写了影响哪些结论
- [ ] 附录的文件路径是相对数据根目录的、真实存在的

## 八、命名与归档

```
月度报告/YYYY-MM/
├── 月度报告_YYYY-MM.md              ← 脚本自动稿（数据层已填，判断层待写）
├── <报告名>_<数据截止日>.md          ← 人工撰写的复盘稿
└── <报告名>_<数据截止日>.html        ← 同稿的可视化版
```

- **自动稿与人工稿并列存放，靠命名区分，脚本不覆盖人工稿**
- `analyze.py --save` 落 `report_<时间戳>.md`，不产生无时间戳的固定名文件
- 一个月一个文件夹，方便横向对比
